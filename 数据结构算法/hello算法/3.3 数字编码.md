**1. 整数：补码**

计算机里的有符号整数通常用补码存储。

- 正数：补码就是它本身。
- 负数：先写对应正数的二进制，按位取反，再加 `1`。
- `n` 位有符号整数范围：

```
-2^(n-1)  到  2^(n-1) - 1
```

例如 8 位整数范围是 `-128 ~ 127`。

`-5` 的 8 位补码：

```
+5        0000 0101
按位取反  1111 1010
加 1      1111 1011
```

补码解决两个问题：

- 正数、负数都能直接走同一套加法电路；`a - b` 等于 `a + (-b)`。
- 没有 `+0` 和 `-0` 两种零。

所以 `1000 0000` 在 8 位补码中代表 `-128`，这也解释了负数比正数多一个。

**2. 溢出**

固定位宽装不下时，超出的高位会被丢弃。例如 8 位范围内：

```
127 + 1  →  -128
```

算法题里要警惕计数、乘法、累加是否超过类型范围。不同语言对有符号整数溢出的处理规则不同，不能把这种回绕当作通用逻辑依赖。

**3. 浮点数：范围为什么大**

32 位 `float` 分三段：

```
┌────────┬────────┬────────┐
│ 符号 S │ 指数 E │ 分数 N │
│  1 位  │  8 位  │ 23 位  │
└────────┴────────┴────────┘
```

计算方式可理解为：

```
值 = 正负号 × 2^(指数) × 有效数字
```

指数位让数值能按 `2` 的幂次放大或缩小，所以同为 4 字节，`float` 的范围远大于 `int`。

代价是精度：数字越大，相邻两个可表示浮点数之间的间隔越大。因此浮点数适合近似计算，不适合要求绝对精确的金额计算。

**4. 浮点数特殊值**

```
E = 0    ：零或很接近零的次正规数
E = 1~254：普通浮点数
E = 255  ：无穷大或 NaN（非数字）
```

`NaN` 常见于非法计算，例如 `0.0 / 0.0`。

**5. 写代码时的判断规则**

```
要精确表示整数        → int
担心固定范围溢出      → 先检查范围或换更大类型
要表示测量、比例、小数 → float / double
比较计算得出的浮点数  → 用允许误差，不直接 ==
金额、计数、下标      → 不要优先用 float
```

一句话：**补码让整数加减统一；浮点数用指数换来巨大范围，但牺牲了精度。**
