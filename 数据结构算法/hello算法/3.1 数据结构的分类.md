**3.1 数据结构分类**

先分清两件事：**元素之间怎么关联**，和**它们在内存里怎么存**。前者是逻辑结构，后者是物理结构。[原文](https://www.hello-algo.com/chapter_data_structure/classification_of_data_structure/)

```
┌──────────┬────────────────────┬──────────────────────┐
│ 分类维度 │ 问的问题           │ 典型分类             │
├──────────┼────────────────────┼──────────────────────┤
│ 逻辑结构 │ 元素之间如何关联   │ 线性、树形、网状     │
│ 物理结构 │ 数据在内存如何存放 │ 连续、分散           │
└──────────┴────────────────────┴──────────────────────┘
```

```
[数据结构] ──┬── 逻辑结构：看元素关系
             │   ├── 线性：一对一
             │   ├── 树形：一对多
             │   └── 网状：多对多
             └── 物理结构：看内存布局
                 ├── 连续：数组
                 └── 分散：链表
```

**1. 逻辑结构**

- 线性结构：元素按顺序排成一条线。数组、链表、栈、队列都属于这一类。核心关系是：一个元素通常只直接连接前后元素。
- 树形结构：一个父节点可连接多个子节点。树、堆属于这一类。
- 网状结构：节点之间可任意多对多连接。图属于这一类。

不要把“线性”理解成内存必须连续。它只说明元素关系像一条线。

**2. 物理结构**

- 连续存储：元素挨着放。数组属于这一类。知道下标，就能直接定位对应位置。
- 分散存储：元素可放在不同位置，用链接关系串起来。链表属于这一类。

物理结构会影响访问、插入、删除的效率。后面学数组和链表时，重点就是这部分。

**3. 一个数据结构可以有两层身份**

栈、队列描述的是“数据怎么进出”；数组、链表描述的是“底层怎么存”。

所以栈和队列既能用数组实现，也能用链表实现。树、堆、图、哈希表也常能基于数组、链表，或两者组合实现。[原文](https://www.hello-algo.com/chapter_data_structure/classification_of_data_structure/)

**4. 静态与动态**

- 普通数组初始化后长度固定，常叫静态数据结构。
- 链表运行中可增删节点，长度可变，常叫动态数据结构。
- 动态数组会申请一块更大的连续内存，再搬迁旧数据；Python 的 `list` 就接近这种思路。

**5. 选择时先问什么**

```
要按下标直接找第 i 个元素 → 优先想到数组
内存未必有连续大空间        → 优先想到链表
只关心后进先出              → 栈
只关心先进先出              → 队列
有父子层级关系              → 树
有复杂连接关系              → 图
```

**6. 哈希表的处理**

这一页把哈希表同时列进了线性和非线性，还列入树形结构，分类本身有冲突。别拿它做“线性还是非线性”的死记题。

现阶段只记：哈希表处理的是“键 → 值”的映射；底层常结合数组和链表。

一句话：**逻辑结构决定元素关系，物理结构决定内存布局；数组和链表是许多复杂数据结构的底座。**
