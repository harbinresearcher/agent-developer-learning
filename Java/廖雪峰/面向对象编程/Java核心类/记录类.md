# 记录类

> **重要程度：中**｜**手练：需要**
> **重点**：record 分量、自动生成的方法、值相等、浅不可变和版本要求。

## 解决什么问题

有些类型主要传递一组确定的数据，如坐标或请求结果。`record` 用紧凑语法声明这些分量，编译器会生成对应构造器、访问方法以及按分量实现的 `equals`、`hashCode`、`toString`，减少重复代码。record 在 Java 16 成为正式语言特性；项目的编译与运行版本必须支持它。

## 完整例子：需要 Java 16 或更高版本

保存为 `RecordDemo.java`。确认 `javac -version` 和 `java -version` 均满足要求，再编译运行：`javac -encoding UTF-8 RecordDemo.java`、`java RecordDemo`。日志写到标准错误。

```java
import java.util.logging.Logger;
public class RecordDemo {
    private static final Logger logger = Logger.getLogger(RecordDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：创建和比较记录
         * ========================================================================
         * 数据源：两个内容相同的坐标
         * 操作：
         * 1) 创建记录并读取分量
         * 2) 比较记录的值
         */
        logger.info("开始处理坐标");
        // 1.1 创建两个坐标记录
        Point first = new Point(2, 3);
        Point second = new Point(2, 3);
        // 1.2 读取分量并比较值
        System.out.println("x=" + first.x());
        System.out.println("equal=" + first.equals(second));
        System.out.println("record=" + first);
        logger.info("坐标处理完成");
    }
}
record Point(int x, int y) { }
```

标准输出：

```text
x=2
equal=true
record=Point[x=2, y=3]
```

## 执行过程

`record Point(int x, int y)` 声明两个分量。`new Point(2, 3)` 调用生成的规范构造器。`first.x()` 是生成的访问方法，名称是 `x()` 而不是 JavaBean 风格的 `getX()`。两个对象是不同实例，但两个 int 分量值相同，自动生成的 `equals` 返回 true。默认 `toString` 展示类型名和分量值。

## 限制与常见误区

record 分量对应的实例字段是 final，record 本身不能再被继承；它可以实现接口。可以写紧凑构造器做参数校验或规范化，但规则必须与业务约定一致。

**不可变是浅层的。** 如果分量是可变 List，final 只限制字段引用重新赋值，List 内容仍可能改变；需要不可变语义时，在构造和访问边界按需求复制或使用不可变数据结构，同时考虑元素自身是否可变。数组分量还会影响默认相等语义：数组的 `equals` 默认比较身份，不自动逐项比较。

record 适合数据载体，不保证所有 ORM、序列化或绑定框架都支持；应核对所用框架版本及约定。某些工具预期 `getX()` 风格的方法，不能假设它们会自动识别 `x()`。

## 手练与答案

1. 将第二个坐标改成 `(2, 4)`：`equals` 为 false。
2. 尝试给 record 分量重新赋值：对应字段是 final，不能在创建后直接修改。
3. 把可变列表作为分量后修改列表：记录内部可观察到的列表内容可能变化，除非在适当边界做防御性复制。
