# 枚举类

> **重要程度：高**｜**手练：需要**
> **重点**：枚举常量、字段和方法、比较、稳定业务编码、解析异常。

## 解决什么问题

订单状态是有限集合：新建、已支付、取消。若到处使用任意字符串，拼错时可能直到运行才暴露。`enum` 将允许的状态定义为明确类型和常量，代码能用类型表达业务含义。

## 完整例子

保存为 `EnumDemo.java`，用 `javac -encoding UTF-8 EnumDemo.java` 编译，再运行 `java EnumDemo`；日志写到标准错误。

```java
import java.util.logging.Logger;

public class EnumDemo {
    private static final Logger logger = Logger.getLogger(EnumDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：读取和比较订单状态
         * ========================================================================
         * 数据源：定义好的订单状态
         * 操作：
         * 1) 读取枚举常量的名称和业务编码
         * 2) 从名称还原状态并比较
         */
        logger.info("开始处理订单状态");
        // 1.1 获取枚举常量及其稳定业务编码
        OrderStatus status = OrderStatus.PAID;
        System.out.println("name=" + status.name());
        System.out.println("code=" + status.code());
        // 1.2 从常量名称解析并比较
        OrderStatus parsed = OrderStatus.valueOf("PAID");
        System.out.println("same=" + (status == parsed));
        logger.info("订单状态处理完成");
    }
}
enum OrderStatus {
    NEW("N"), PAID("P"), CANCELLED("C");
    private final String code;
    OrderStatus(String code) { this.code = code; }
    String code() { return code; }
}
```

标准输出：

```text
name=PAID
code=P
same=true
```

## 执行过程

`OrderStatus` 声明三个常量。每个常量都是这个枚举类型的对象；`PAID("P")` 把字符串传给枚举构造器，保存到该常量的 `code` 字段。`name()` 返回声明时的常量名称 `PAID`，自定义 `code()` 返回约定的业务编码 `P`。`valueOf("PAID")` 按名称找到该常量；两个引用指向相同枚举常量，所以 `==` 为 true。

`valueOf` 接受的是**名称**，不是业务编码：`valueOf("P")` 会抛 `IllegalArgumentException`；传 null 会抛 `NullPointerException`。对于外部输入，应明确空值和未知编码如何处理，按业务编码转换时需要自己实现查找，而不是直接调用 `valueOf`。

## 重要规则

- 枚举类可有字段、构造器和方法；构造器由枚举声明使用，调用方不能 `new OrderStatus(...)`。
- 同一枚举类型的常量可用 `==` 比较。枚举引用可能是 null；若允许缺失状态，仍需明确处理。
- `values()` 返回当前声明的常量数组；`ordinal()` 是从 0 开始的声明位置。调整声明顺序会改变 ordinal，因此不要把它当作长期稳定的数据库或接口编码。
- 给每个状态设计明确、唯一的业务编码，变更时考虑旧数据、未知值和迁移。枚举的名称或 `toString()` 也不应未经约定就当成永远不变的外部协议。
- 枚举可用于 `switch`、`EnumMap`、`EnumSet`；switch 是否穷尽、null 如何处理依赖 Java 版本和具体语法。

## 工作中怎么用

使用枚举约束有限状态，并把状态转换规则放到合适的业务层。枚举本身不会自动阻止从取消状态跳到已支付；合法流转仍需业务校验及必要的并发控制。

## 手练与答案

1. `OrderStatus.valueOf("NEW")` 得到 `NEW`；`valueOf("N")` 抛 `IllegalArgumentException`。
2. 在枚举中插入一个新常量，原有常量的 `ordinal()` 可能改变；本例明确赋予的编码 `N`、`P`、`C` 不因此自动改变。
3. 用同一业务编码定义两个常量会怎样？编译器不负责保证编码唯一，查找逻辑可能产生歧义，应在设计或测试中保证唯一。
