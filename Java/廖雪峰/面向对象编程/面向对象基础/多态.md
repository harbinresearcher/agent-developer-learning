# 多态

> **重要程度：高**｜**手练：需要**
> **重点**：父类型引用、重写、动态分派。

## 先理解：统一调用，不同实现

同一段业务要发送邮件或短信。调用方只关心“发送通知”这一共同能力；实际使用哪个实现，取决于传入的对象。这就是常见的运行时多态：父类或接口类型的引用，调用被重写的实例方法时，实际执行的方法由对象的运行时类型决定。

## 完整例子

保存为 `PolymorphismDemo.java`，编译并运行；日志写到标准错误。

```java
import java.util.logging.Logger;

public class PolymorphismDemo {
    private static final Logger logger = Logger.getLogger(PolymorphismDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：用统一类型处理不同对象
         * ========================================================================
         * 数据源：两种通知对象
         * 操作：
         * 1) 保存到父类型数组
         * 2) 调用同名方法并观察具体行为
         */
        logger.info("开始发送通知");
        // 1.1 父类型引用可以指向子类对象
        Notice[] notices = {new EmailNotice(), new SmsNotice()};
        // 1.2 同一调用交给实际对象对应的实现
        for (Notice notice : notices) {
            System.out.println(notice.send());
        }
        logger.info("通知处理完成");
    }
}

class Notice {
    String send() { return "普通通知"; }
}
class EmailNotice extends Notice {
    @Override
    String send() { return "邮件通知"; }
}
class SmsNotice extends Notice {
    @Override
    String send() { return "短信通知"; }
}
```

标准输出：

```text
邮件通知
短信通知
```

## 执行过程

`Notice[]` 的元素类型是父类 `Notice`；`new EmailNotice()` 和 `new SmsNotice()` 创建两个不同子类对象，它们都可赋给父类型引用。第一轮调用 `notice.send()` 时，引用指向邮件对象，所以运行 `EmailNotice.send()`；第二轮运行 `SmsNotice.send()`。

编译时，变量声明类型 `Notice` 决定此处允许调用哪些成员；运行时，实际对象决定调用哪个被重写的实例方法。父类型变量不能直接调用仅在子类声明的方法，即使它当前指向子类对象。

## 重写、重载和例外

重写是子类提供继承来的实例方法的新实现；写 `@Override` 让编译器检查是否真的重写。方法名相同但参数列表不同是重载，重载的选择主要在编译时完成。字段访问和 `static` 方法隐藏不按上述实例方法的动态分派规则选择；不要用字段同名隐藏表达多态。

`final` 实例方法不能被子类重写；构造器不被重写。向下转型只有实际对象确实是目标类型时才安全，否则会抛 `ClassCastException`；通常优先通过父类型或接口暴露所需行为。

## 工作中怎么用

业务依赖小而明确的接口，使用方传入具体实现，例如邮件发送器与短信发送器。这样可以替换实现或测试替身；但要确认各实现遵守相同约定，不能仅因为语法允许就把没有共同含义的类型强行放进继承关系。

## 手练与答案

把第二个对象改成 `new Notice()`：输出依次是“邮件通知”“普通通知”。若 `EmailNotice` 的 `send` 改名且保留 `@Override`，编译器会报错，因为没有重写父类对应方法。
