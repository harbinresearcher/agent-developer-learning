# 包

> **重要程度：高**｜**手练：需要**
> **重点**：包名与完整类名、目录结构、import 和跨包访问。

## 先理解：类怎么避免重名

两个团队都可能写一个 `User` 类。包给类型命名空间：`com.example.account.User` 与 `com.example.order.User` 是两个不同类型。完整类名包含包名和类名；`import` 只是让源码可以使用较短的类型名，不会把代码复制进当前文件。

## 完整例子：两个包互相调用

建立下面的目录，分别保存两个文件。目录中的 `src` 是源码根目录；`app`、`demo/util` 对应各自的包名。

```text
src/
├── app/Main.java
└── demo/util/Greeting.java
```

`src/app/Main.java`：

```java
package app;

import demo.util.Greeting;
import java.util.logging.Logger;

public class Main {
    private static final Logger logger = Logger.getLogger(Main.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：调用其他包中的类型
         * ========================================================================
         * 数据源：调用者提供的姓名
         * 操作：
         * 1) 引入并调用公开工具类
         * 2) 输出生成的问候语
         */
        logger.info("开始生成问候语");
        // 1.1 调用已导入的类
        String message = Greeting.greet("小明");
        // 1.2 输出结果
        System.out.println(message);
        logger.info("问候语生成完成");
    }
}
```

`src/demo/util/Greeting.java`：

```java
package demo.util;

import java.util.logging.Logger;

public class Greeting {
    private static final Logger logger = Logger.getLogger(Greeting.class.getName());
    public static String greet(String name) {
        /*
         * ========================================================================
         * 步骤1：生成问候语
         * ========================================================================
         * 数据源：传入的姓名
         * 操作：
         * 1) 组合字符串
         * 2) 返回问候结果
         */
        logger.info("开始组合问候语");
        // 1.1 组合并返回文本
        String result = "你好，" + name;
        logger.info("问候语组合完成");
        return result;
    }
}
```

在包含 `src` 的目录运行以下命令。`-d out` 指定 class 文件输出目录；随后类路径根目录是 `out`，启动时使用完整类名。

```text
javac -encoding UTF-8 -d out src/app/Main.java src/demo/util/Greeting.java
java -cp out app.Main
```

标准输出为 `你好，小明`。日志写到标准错误，显示格式可能不同。

## 执行过程

`Main.java` 首行声明 `package app`，所以它的完整类名是 `app.Main`。`import demo.util.Greeting` 允许在源码里简写 `Greeting`；真正的类仍是 `demo.util.Greeting`。运行时 `java -cp out app.Main` 会从 `out` 这个类路径根目录查找 `app/Main.class`，再加载所需类型。

`Greeting` 类及 `greet` 方法都是 `public`，因此其他包中的 `Main` 可以访问。若把 `Greeting` 改成包访问权限，即删掉类声明前的 `public`，`app` 包中的代码不能使用该类，即使写了 `import` 也不行。

## 常见误区

- 包声明写在源码开头，位于 `import` 之前；一个源码文件最多声明一个包。实践中通常让目录和包名对应。
- 同包类型通常可直接使用短名；`java.lang` 中的类型会自动可见。`import demo.util.*` 只按规则引入该包中的类型，不包含 `demo.util.sub` 等子包。
- 两个不同包中的同名类发生歧义时，可对其中一个使用完整类名。`import` 不会改变成员的访问权限。
- `demo` 与 `demo.util` 是不同的包，包访问权限不会自动延伸到子包。
- 包名不是文件夹的简单别名；运行时能否加载还取决于 classpath 和模块配置，见 [[classpath和jar]]。

## 工作中怎么用

采用团队约定的稳定包名前缀，按业务或职责组织代码。避免把所有类型放在默认包里；也避免把内部实现随意设成 `public`。构建工具会管理源码目录、依赖和编译输出，但理解包与类路径仍有助于排查找不到类的问题。

## 手练与答案

1. 删除 `import demo.util.Greeting`，并改用 `demo.util.Greeting.greet("小明")`：可以编译，结果不变。
2. 把 `Greeting` 声明为包访问权限：跨包调用无法编译；`import` 不能放宽权限。
3. 将运行命令改成 `java -cp out Main`：找不到入口类，因为真实完整类名是 `app.Main`。
