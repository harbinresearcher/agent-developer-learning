# 接口

> **重要程度：高**｜**手练：需要**
> **重点**：接口契约、实现类、default 方法。

## 先理解：接口规定能做什么

接口定义调用者可以依赖的能力。这里 `TextFormatter` 规定“接收文本并返回处理后的文本”，`UpperFormatter` 是一种具体实现。调用方用接口类型接收对象，可以在不改调用代码的情况下替换成遵守相同约定的其他实现。

## 完整例子

保存为 `InterfaceDemo.java`，编译并运行；日志写到标准错误。

```java
import java.util.logging.Logger;

public class InterfaceDemo {
    private static final Logger logger = Logger.getLogger(InterfaceDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：通过接口处理文本
         * ========================================================================
         * 数据源：一个实现接口的对象和输入文本
         * 操作：
         * 1) 创建实现类并保存为接口类型
         * 2) 调用实现方法和接口默认方法
         */
        logger.info("开始处理文本");
        // 1.1 使用接口接收实现类对象
        TextFormatter formatter = new UpperFormatter();
        // 1.2 通过同一个接口调用两种方法
        System.out.println(formatter.format("java"));
        System.out.println(formatter.name());
        logger.info("文本处理完成");
    }
}

interface TextFormatter {
    String format(String text);
    default String name() { return "文本格式化器"; }
}
class UpperFormatter implements TextFormatter {
    @Override
    public String format(String text) { return text.toUpperCase(java.util.Locale.ROOT); }
}
```

标准输出：

```text
JAVA
文本格式化器
```

## 执行过程

`TextFormatter formatter = new UpperFormatter()` 创建实现类对象，再把引用赋给接口类型变量。调用 `format("java")` 时运行 `UpperFormatter` 的实现，输出 `JAVA`。`name()` 没有在实现类中重写，因此使用接口提供的 `default` 实现。

`implements` 声明类实现接口；具体类必须实现继承到的抽象方法，否则自己也必须声明为抽象类。接口中普通方法声明隐含 `public abstract`，所以实现时用 `public`，不能降低可见性。这里 `Locale.ROOT` 避免大小写转换依赖默认地区；生产代码还应规定并校验 `null` 输入。

## 接口能包含什么

接口可以声明抽象方法，也可以提供 `default` 和 `static` 方法；Java 9 起可有用于内部复用的私有方法。接口字段隐含 `public static final`，是常量，不是每个对象独立保存的可变实例字段。`static` 接口方法以接口名调用，不靠实现类对象继承。

一个类可以实现多个接口，但只能直接继承一个类。若多个接口提供同签名的冲突默认方法，实现类需要覆盖并消除冲突。接口不能直接 `new`；匿名实现类等语法创建的仍是实现该接口的对象。

## 与抽象类的选择

接口适合定义能力和调用契约；抽象类可提供共同的实例状态、构造器和部分实现。先看是否需要共享状态及继承关系，避免为了层次而制造空接口或深层继承。

## 手练与答案

新增实现类让 `format` 返回原文，再将 `formatter` 指向新对象：第一行变为 `java`，第二行仍是“文本格式化器”。删掉实现类的 `public` 会编译失败，因为不能缩小接口方法的访问范围。

## 综合练习：手练：接口与多态


将代码保存为 `PaymentDemo.java`。先运行 `javac -encoding UTF-8 PaymentDemo.java`，再运行 `java PaymentDemo`。

```java
import java.util.logging.Logger;

public class PaymentDemo {
    private static final Logger logger = Logger.getLogger(PaymentDemo.class.getName());

    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：调用不同的支付实现
         * ========================================================================
         * 目标：观察同一接口的不同实现。
         * 数据源：两种本地模拟支付对象。
         * 操作：
         * 1) 创建接口的两个实现。
         * 2) 通过相同的接口方法处理金额。
         */
        logger.info("开始演示多态");
        // 1.1 创建两种支付对象
        Payment first = new CardPayment();
        Payment second = new WalletPayment();
        // 1.2 通过接口调用各自的实现
        System.out.println(first.pay(100));
        System.out.println(second.pay(100));
        logger.info("多态演示完成");
    }
}

interface Payment {
    String pay(int amount);
}

class CardPayment implements Payment {
    public String pay(int amount) {
        return "银行卡模拟支付: " + amount;
    }
}

class WalletPayment implements Payment {
    public String pay(int amount) {
        return "钱包模拟支付: " + amount;
    }
}
```

`Payment` 是调用方看到的接口；`new CardPayment()` 创建的实际对象决定调用哪个实现。示例仅演示调用关系，没有连接真实支付服务。

手练：为两个实现的方法加 `@Override`；再新增一个实现，检查 `main` 需要改动哪些地方。
