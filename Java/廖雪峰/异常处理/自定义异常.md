# 自定义异常

> **重要程度：高**｜**手练：需要**
> **重点**：业务含义、继承选择、错误消息与 cause。

## 解决什么问题

标准异常无法清楚表达特定业务失败时，可定义有意义的异常类型。库存不足与输入格式错误虽然都属于失败，但调用方可能需要不同的处理和错误响应。自定义类型应该有清晰的语义和使用边界，而非为每个 if 都创建异常类。

## 完整例子

保存为 `CustomExceptionDemo.java`，编译运行；日志写到标准错误。

```java
import java.util.logging.Logger;
public class CustomExceptionDemo {
    private static final Logger logger = Logger.getLogger(CustomExceptionDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：校验库存
         * ========================================================================
         * 数据源：库存数量和请求数量
         * 操作：
         * 1) 调用库存校验
         * 2) 捕获并识别业务异常
         */
        logger.info("开始校验库存");
        // 1.1 请求数量超过库存
        try {
            checkStock(2, 3);
        } catch (InsufficientStockException ex) {
            // 1.2 输出业务异常信息
            System.out.println("error=" + ex.getMessage());
        }
        logger.info("库存校验完成");
    }
    static void checkStock(int available, int requested) {
        if (requested > available) {
            throw new InsufficientStockException("库存不足");
        }
    }
}
class InsufficientStockException extends RuntimeException {
    InsufficientStockException(String message) { super(message); }
    InsufficientStockException(String message, Throwable cause) { super(message, cause); }
}
```

默认运行的标准输出：

```text
error=库存不足
```

## 执行过程

`checkStock(2, 3)` 发现请求数量大于库存，创建并抛出 `InsufficientStockException`。该类继承 `RuntimeException`，是非受检异常；调用方按这个具体类型捕获并输出说明。两个构造器分别支持只提供消息，以及同时保留底层 cause；本例没有底层异常，因此只用消息构造器。

## 设计规则

继承 `Exception` 且不属于 `RuntimeException` 的自定义异常是受检异常；继承 `RuntimeException` 是非受检异常。选择依据是调用方是否应在接口层明确处理及项目约定，不是错误严重程度。公开 API 一旦暴露异常类型，就要考虑兼容性和调用方处理方式。

转换底层异常时可传入 cause；边界层按约定映射安全的错误码和响应，内部记录足够排查的信息。不要把堆栈、密码、SQL 细节或用户隐私直接返回客户端。

## 手练与答案

请求数量改为 2：校验正常返回，catch 不执行；本例不会因此输出成功消息。将异常类改为继承 `Exception` 后，`checkStock` 必须捕获该受检异常或在方法声明中添加 `throws InsufficientStockException`。

本例只说明异常机制，真实库存扣减还需要数据库事务和并发控制，不能靠先读库存再简单判断保证不超卖。
