# 自定义异常

> **重要程度：中**｜**手练：建议**
> **重点**：业务语义、异常类型和原因链。

## 核心概念

当现有异常无法清楚表达业务失败，或调用方需要按业务类别处理时，可以定义自定义异常类。先考虑现有异常是否已经足够，避免为每一种提示文字都创建新类型。

## 工作中注意

根据调用方是否必须显式处理选择受检或非受检异常，保持项目内一致；构造异常时可接收消息和 cause。不要把底层数据库或网络异常细节直接作为公开接口响应。

## 手练

定义“库存不足”异常，触发后在服务边界转换成可理解的错误信息，同时保留日志中的原因链。
