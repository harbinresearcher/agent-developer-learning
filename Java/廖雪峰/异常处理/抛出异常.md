# 抛出异常

> **重要程度：高**｜**手练：需要**
> **重点**：throw、throws、异常链。

## 核心概念

`throw` 在代码中抛出异常对象；`throws` 写在方法声明中，向调用者声明可能抛出的受检异常。方法不必捕获自己无法处理的异常，可以把它交给知道业务上下文的上层。

## 工作中注意

将底层异常转换为业务异常时保留 cause，避免丢失根因。异常消息提供必要上下文，但不要包含密码、令牌或完整敏感数据；不要用异常替代普通条件分支。

## 手练

让数字解析函数遇到非法输入时向上抛异常；再在业务层转换异常并检查原因链。
