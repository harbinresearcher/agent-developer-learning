# 抛出异常

> **重要程度：高**｜**手练：需要**
> **重点**：throw 与 throws、异常转换、保留 cause。

## 解决什么问题

`throw` 在方法体内抛出一个异常对象，使当前正常流程中断。`throws` 写在方法声明后，声明该方法可能向外抛出的异常；调用方是否必须捕获或继续声明，取决于异常是否为受检异常。

## 完整例子

保存为 `ThrowDemo.java`，编译运行；日志写到标准错误。

```java
import java.util.logging.Logger;
public class ThrowDemo {
    private static final Logger logger = Logger.getLogger(ThrowDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：解析并转换异常
         * ========================================================================
         * 数据源：无效的年龄文本
         * 操作：
         * 1) 调用解析方法
         * 2) 在边界输出异常类型和原因
         */
        logger.info("开始解析年龄");
        // 1.1 捕获解析边界转换后的异常
        try {
            parseAge("abc");
        } catch (IllegalArgumentException ex) {
            // 1.2 核对原因是否保留
            System.out.println("message=" + ex.getMessage());
            System.out.println("cause=" + ex.getCause().getClass().getSimpleName());
        }
        logger.info("年龄解析处理完成");
    }
    static int parseAge(String input) {
        try {
            return Integer.parseInt(input);
        } catch (NumberFormatException ex) {
            throw new IllegalArgumentException("年龄必须为整数", ex);
        }
    }
}
```

标准输出：

```text
message=年龄必须为整数
cause=NumberFormatException
```

## 执行过程

`parseAge("abc")` 调用 `Integer.parseInt` 时产生 `NumberFormatException`。内部 catch 把它转换成更有业务含义的 `IllegalArgumentException`，并作为构造器的第二个参数传入，成为 cause。调用方捕获转换后的异常；`getMessage()` 返回新说明，`getCause()` 仍能读到原始异常类型。

## throw 和 throws

`throw new IllegalArgumentException("无效")` 是实际抛出；`void read() throws IOException` 是方法签名中的声明，方法执行时不一定真的抛出。受检异常通常要求捕获或在签名声明；运行时异常不要求强制声明。重写方法对受检异常的声明还受父方法契约限制。

不要为了编译通过就捕获后返回貌似有效的默认值。转换异常时保留 cause，避免丢失原始堆栈；错误消息应避免携带密码、令牌等敏感输入。业务层、接口层应约定哪些失败转成何种响应，避免每一层重复记录同一异常。

## 手练与答案

输入 `"18"` 时解析成功，catch 不执行；示例没有打印成功结果。若构造转换异常时不传 `ex`，`getCause()` 通常为 null，原始原因不再由 cause 链保留。
