# 使用断言

> **重要程度：高**｜**手练：需要**
> **重点**：断言启用方式、AssertionError、不能代替输入校验。

## 解决什么问题

`assert 条件 : 消息` 用于检查程序内部认为应该成立的假设。条件为 false 且断言已启用时，会抛 `AssertionError`。断言可能被关闭，所以它不是可靠的外部输入校验或权限检查。

## 完整例子

保存为 `AssertDemo.java`。编译后分别运行 `java AssertDemo` 和 `java -ea AssertDemo`；日志与错误输出写到标准错误。

```java
import java.util.logging.Logger;
public class AssertDemo {
    private static final Logger logger = Logger.getLogger(AssertDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：检查内部假设
         * ========================================================================
         * 数据源：演示用的负数
         * 操作：
         * 1) 运行断言表达式
         * 2) 观察断言禁用与启用的区别
         */
        logger.info("开始检查内部假设");
        // 1.1 校验示例假设
        int count = -1;
        assert count >= 0 : "count 必须非负";
        // 1.2 断言被禁用时会继续到这里
        System.out.println("continued");
        logger.info("内部假设检查完成");
    }
}
```

默认运行的标准输出：

```text
continued
```

## 执行过程

默认运行时断言通常未启用，断言表达式不执行，程序输出 `continued`。带 `-ea` 运行时，`count >= 0` 为 false，抛出 `AssertionError`，标准输出没有 `continued`；进程以非零状态退出。日志中“检查完成”也不会执行，因为异常使当前流程提前结束。

断言表达式不能承担修改状态等必要副作用：禁用断言时整个表达式不会计算。`-ea` 可按类或包配置；项目实际启动参数决定是否启用。具体异常堆栈和日志格式因环境而异。

## 工作中怎么用

输入校验应使用明确的 if、参数校验或项目框架，无论是否启用断言都要生效。单元测试通常使用测试框架的断言方法，不应把 Java 关键字 `assert` 当作 JUnit 断言的替代品。内部不可达状态也可按接口约定选择显式异常，确保生产环境能识别失败。

## 手练与答案

将 `count` 改为 0：默认运行与 `-ea` 运行均输出 `continued`。保留 -1：只有启用断言时才因 `AssertionError` 停止。
