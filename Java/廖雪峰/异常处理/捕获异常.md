# 捕获异常

> **重要程度：高**｜**手练：需要**
> **重点**：catch 匹配顺序、资源关闭、主异常与被抑制异常。

## 解决什么问题

当某段代码可能失败时，`try` 包住需要保护的操作；`catch` 针对匹配的异常处理；`finally` 可放清理代码。可关闭资源通常优先用 `try-with-resources`，让资源在退出时自动关闭。

## 完整例子

保存为 `CatchResourceDemo.java`，编译并运行。示例故意让读取和关闭都失败，日志写到标准错误。

```java
import java.io.IOException;
import java.util.logging.Logger;
public class CatchResourceDemo {
    private static final Logger logger = Logger.getLogger(CatchResourceDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：处理读取和关闭失败
         * ========================================================================
         * 数据源：模拟的可关闭资源
         * 操作：
         * 1) 触发读取失败和关闭失败
         * 2) 输出主异常及被抑制的异常
         */
        logger.info("开始读取资源");
        // 1.1 在 try-with-resources 中创建并使用资源
        try (FailingResource resource = new FailingResource()) {
            resource.read();
        } catch (IOException ex) {
            // 1.2 检查主异常和自动关闭产生的附加异常
            System.out.println("main=" + ex.getMessage());
            System.out.println("suppressed=" + ex.getSuppressed()[0].getMessage());
        }
        logger.info("资源读取处理完成");
    }
}
class FailingResource implements AutoCloseable {
    void read() throws IOException { throw new IOException("读取失败"); }
    public void close() throws IOException { throw new IOException("关闭失败"); }
}
```

标准输出：

```text
main=读取失败
suppressed=关闭失败
```

## 执行过程

1. 资源创建成功后进入 try；`read()` 抛出消息为“读取失败”的 `IOException`，try 剩余语句不会继续。
2. 离开 try 前自动调用 `close()`；它又抛出“关闭失败”。由于已有主异常，关闭异常作为 suppressed 异常附到主异常上。
3. `catch (IOException ex)` 接到主异常，输出它的消息以及第一个 suppressed 异常。本例保证同时发生两种失败，所以数组下标 0 存在；实际代码必须先检查数组长度。

## 顺序和关闭规则

多个 catch 从上到下匹配；先写具体子类，再写父类，否则父类会让后面的子类 catch 无法到达而编译失败。`finally` 在通常的退出路径运行，包括异常、return 等，但 JVM 退出或进程被强制终止时不能保证运行；不要在 finally 里随意 return 或抛新异常掩盖原结果。

`try-with-resources` 适用于实现 `AutoCloseable` 的资源，多个资源按初始化的逆序关闭。如果只在关闭时失败，该关闭异常可以成为主异常；如果 try 内已有异常，关闭异常通常被记录为 suppressed。catch 和 finally 在声明的资源关闭后执行。

## 工作中怎么用

分别处理可恢复的错误，并保留堆栈与原始原因；不要空 catch，也不要把任何异常都当成正常结果。资源管理还要考虑资源是否由当前方法负责关闭。

## 手练与答案

1. 将 `read()` 改为正常返回：关闭失败成为主异常；此时示例直接访问 `getSuppressed()[0]` 会越界，应先检查长度。
2. 两个资源依次声明 A、B：正常退出时先关闭 B，再关闭 A。
