# 抽象工厂

> **重要程度：中**｜**手练：需要**
> **重点**：产品族、工厂接口、替换产品族时的约束。

## 它解决什么问题

一组相关产品需要成套使用时，抽象工厂用同一个工厂接口创建这组产品。例子中按钮和复选框组成一个产品族；选择 `DarkFactory` 后，两者都是深色。`render` 只依赖工厂和产品接口，不需要分别挑选具体组件。


## 完整例子

保存为 `AbstractFactoryDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 AbstractFactoryDemo.java
java AbstractFactoryDemo
```

```java
import java.util.logging.Logger;
public class AbstractFactoryDemo {
    private static final Logger logger = Logger.getLogger(AbstractFactoryDemo.class.getName());
    interface Button { String draw(); }
    interface Checkbox { String draw(); }
    interface WidgetFactory { Button button(); Checkbox checkbox(); }
    static class LightFactory implements WidgetFactory {
        public Button button() { return () -> "浅色按钮"; }
        public Checkbox checkbox() { return () -> "浅色复选框"; }
    }
    static class DarkFactory implements WidgetFactory {
        public Button button() { return () -> "深色按钮"; }
        public Checkbox checkbox() { return () -> "深色复选框"; }
    }
    static void render(WidgetFactory factory) {
        System.out.println(factory.button().draw());
        System.out.println(factory.checkbox().draw());
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：创建同一主题的组件
         * 数据源：测试用深色组件工厂
         * 操作：1) 选择工厂 2) 创建并显示一组产品
         * ======================================================================== */
        logger.info("开始创建组件");
        // 1.1 工厂决定这一组组件的主题
        WidgetFactory factory = new DarkFactory();
        // 1.2 客户端通过接口使用产品
        render(factory);
        logger.info("组件创建结束");
    }
}
```

标准输出，日志单独显示：

```text
深色按钮
深色复选框
```

## 与工厂方法的区别

工厂方法通常聚焦一个产品的创建接口；抽象工厂提供多个方法，用来创建相互关联的产品。新增一种主题可以新增工厂实现；新增一种产品类型则需要修改工厂接口和各工厂实现，这是它的主要代价。

## 工作中怎么选

确实存在需要配套的产品族时再引入；单个对象或两种简单分支通常不需要整套类结构。工厂只负责创建或提供对象，不自动保证并发安全、连接关闭或资源回收。

## 动手与自查

1. 将工厂切换成 `LightFactory`，确认两个产品一起变化。
2. 新增 `Menu` 产品，列出需要修改的接口和实现。
3. 为什么客户端分别手工选择按钮与复选框更容易混用主题？
