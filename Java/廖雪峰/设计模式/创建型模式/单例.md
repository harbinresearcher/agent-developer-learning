# 单例

> **重要程度：高**｜**手练：需要**
> **重点**：私有构造、实例生命周期和多线程初始化的边界。

## 它解决什么问题

有些对象在一个应用组件内只需共享一份，比如只读配置。单例把构造入口收起来，统一提供实例。例子使用私有构造方法与 `static final` 字段，首次初始化这个类时创建对象；这是类初始化阶段的饿汉式实例，不是每次 `getInstance()` 都创建。


## 完整例子

保存为 `SingletonDemo.java`，用 JDK 11 或更高版本编译运行：

```powershell
javac -encoding UTF-8 SingletonDemo.java
java SingletonDemo
```

```java
import java.util.logging.Logger;
public class SingletonDemo {
    private static final Logger logger = Logger.getLogger(SingletonDemo.class.getName());
    static final class AppConfig {
        private AppConfig() { }
        // 类初始化时创建，JVM 保证类初始化过程的线程安全
        private static final AppConfig INSTANCE = new AppConfig();
        static AppConfig getInstance() { return INSTANCE; }
        String environment() { return "test"; }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：获取配置对象
         * 数据源：AppConfig 的静态实例
         * 操作：1) 获取两次引用 2) 比较是否为同一个对象
         * ======================================================================== */
        logger.info("开始获取配置");
        // 1.1 两次从同一个类取得实例
        AppConfig first = AppConfig.getInstance();
        AppConfig second = AppConfig.getInstance();
        // 1.2 验证引用相同并读取配置
        System.out.println("同一实例: " + (first == second));
        System.out.println("环境: " + first.environment());
        logger.info("获取配置完成");
    }
}
```

标准输出（日志单独输出）：

```text
同一实例: true
环境: test
```

## 理解边界

两个引用用 `==` 比较的是是否指向同一个对象。JVM 保证类初始化的同步，不能由此推导实例内部所有可变字段都是线程安全的。不同进程、不同类加载器下可能分别有实例；它不是分布式全局唯一，也不限制数据库中只有一条记录。

序列化、反射等机制会影响普通单例的唯一性。需要防范时可考虑枚举单例，但必须结合序列化及框架要求选择，不能把它当成跨进程锁。

## 工作中怎么选

Spring 默认 singleton 指每个容器中每个 Bean 定义的一份实例，并非整个 JVM 或集群一份。优先用容器管理对象生命周期和依赖；静态全局状态容易让测试相互影响，也会隐藏依赖。无共享需求时不要为了套模式创建单例。

## 动手与自查

1. 打印两个引用的 `==` 结果，再尝试从外部调用构造方法，观察编译错误。
2. 为实例增加可变计数器后，说明为什么类初始化安全不代表并发自增安全。
3. 两台服务器各运行一个应用，静态实例有几个？
