# 原型

> **重要程度：中**｜**手练：需要**
> **重点**：复制构造、浅拷贝与可变字段隔离。

## 它解决什么问题

当新对象大部分内容来自已有对象时，可以复制一个原型，再修改差异。例子使用复制构造器而不是 `clone()`：新草稿有独立的标签列表，所以修改副本不会修改原列表。


## 完整例子

保存为 `PrototypeDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 PrototypeDemo.java
java PrototypeDemo
```

```java
import java.util.ArrayList;
import java.util.List;
import java.util.logging.Logger;
public class PrototypeDemo {
    private static final Logger logger = Logger.getLogger(PrototypeDemo.class.getName());
    static class Draft {
        final List<String> tags;
        Draft(List<String> tags) { this.tags = new ArrayList<>(tags); }
        Draft(Draft source) { this.tags = new ArrayList<>(source.tags); }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：复制并修改草稿
         * 数据源：带一个标签的原始草稿
         * 操作：1) 复制列表 2) 只修改副本
         * ======================================================================== */
        logger.info("开始复制草稿");
        // 1.1 用复制构造器创建新草稿
        Draft original = new Draft(List.of("java"));
        Draft copy = new Draft(original);
        // 1.2 修改副本并比较两个列表
        copy.tags.add("spring");
        System.out.println("原始: " + original.tags);
        System.out.println("副本: " + copy.tags);
        logger.info("草稿复制结束");
    }
}
```

标准输出，日志单独显示：

```text
原始: [java]
副本: [java, spring]
```

## 浅拷贝与深拷贝

`new ArrayList<>(source.tags)` 复制列表容器，但不复制里面的元素。这里元素是不可变的 `String`，共享元素通常安全；如果元素本身可变，两个列表仍可能共享元素，需要按业务决定是否继续复制。所谓深拷贝要定义复制边界，不能只看有无 `new`。

数据库实体、连接、锁、线程等对象不一定适合直接复制；复制 ID 或资源句柄可能带来语义错误。Java 的 `Cloneable` 和 `Object.clone()` 有额外约定，业务代码常用明确的复制构造器或工厂方法表达需要复制的字段。

## 动手与自查

1. 把复制构造器改成直接赋值 `this.tags = source.tags`，观察原始列表如何变化。
2. 将列表元素改为可变对象，验证复制列表并不自动复制元素。
3. 复制订单对象时，订单编号是否应该沿用？为什么要由业务决定？
