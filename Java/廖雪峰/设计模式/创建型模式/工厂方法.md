# 工厂方法

> **重要程度：高**｜**手练：需要**
> **重点**：抽象产品、工厂方法和新增实现时的变化范围。

## 它解决什么问题

调用方需要一个产品接口，但产品的具体实现由子类决定。工厂方法把“创建什么”交给可重写的方法；公共流程仍可以依赖产品接口。例子中 `Sender` 是产品接口，`EmailFactory.create()` 创建具体产品，`notifyUser` 负责共用流程。


## 完整例子

保存为 `FactoryMethodDemo.java`，用 JDK 11 或更高版本编译运行：

```powershell
javac -encoding UTF-8 FactoryMethodDemo.java
java FactoryMethodDemo
```

```java
import java.util.logging.Logger;
public class FactoryMethodDemo {
    private static final Logger logger = Logger.getLogger(FactoryMethodDemo.class.getName());
    interface Sender { String send(String message); }
    static final class EmailSender implements Sender {
        public String send(String message) { return "邮件: " + message; }
    }
    abstract static class SenderFactory {
        abstract Sender create();
        String notifyUser(String message) { return create().send(message); }
    }
    static final class EmailFactory extends SenderFactory {
        Sender create() { return new EmailSender(); }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：创建发送器并通知
         * 数据源：邮件发送器工厂与测试消息
         * 操作：1) 选择工厂 2) 通过产品接口调用
         * ======================================================================== */
        logger.info("开始通知");
        // 1.1 工厂的具体类型决定创建哪种产品
        SenderFactory factory = new EmailFactory();
        // 1.2 调用公共流程，无需直接构造具体发送器
        System.out.println(factory.notifyUser("订单已创建"));
        logger.info("通知完成");
    }
}
```

标准输出（日志单独输出）：

```text
邮件: 订单已创建
```

## 运行过程

`EmailFactory` 创建后，调用 `notifyUser`，该方法再调用 `create()`；动态分派选中 `EmailFactory.create()`，得到 `EmailSender`，最后调用它的 `send`。输出只是字符串，例子没有真实发送邮件。

新增短信发送时，可新增 `SmsSender` 和对应工厂；选择哪个工厂的入口仍需配置或代码变更。工厂方法不意味着整个系统添加实现时完全不修改任何位置。

## 工作中怎么选

创建逻辑固定且简单时直接构造即可；策略可注入时优先依赖注入。需要延迟创建、隔离复杂构造或由子类确定产品时再考虑工厂方法。一个静态 `create(type)` 选择实现的简单工厂，与此处由子类覆盖创建方法的工厂方法并非同一结构。
