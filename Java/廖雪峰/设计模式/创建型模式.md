# 创建型模式

> **重要程度：高**｜**手练：需要**
> **重点**：对象创建、构造校验和五种模式的适用条件。

## 先理解共同问题

创建型模式关注对象如何创建：调用方是否需要知道具体类、多个参数如何组合、对象能否复制，以及实例由谁管理。它们不是要求所有 `new` 都替换成工厂。

- 工厂方法：将具体产品创建交给相应工厂实现；适合创建方式需要变化。
- 抽象工厂：成组创建互相关联的产品；新增产品种类通常要修改各工厂。
- 生成器：分步设置参数并集中校验，适合参数较多的对象。
- 原型：从已有对象复制，必须明确可变字段的复制边界。
- 单例：控制某个范围内的实例获取；容器、类加载器和进程范围不能混为一谈。

下面用生成器展示必需参数、默认值和最终校验。

## 完整例子

保存为 `BuilderDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 BuilderDemo.java
java BuilderDemo
```

```java
import java.util.logging.Logger;
public class BuilderDemo {
    private static final Logger logger = Logger.getLogger(BuilderDemo.class.getName());
    static final class Order {
        final String product;
        final int quantity;
        private Order(Builder builder) { product = builder.product; quantity = builder.quantity; }
        static Builder builder(String product) { return new Builder(product); }
        static final class Builder {
            private final String product;
            private int quantity = 1;
            private Builder(String product) { this.product = product; }
            Builder quantity(int value) { quantity = value; return this; }
            Order build() {
                if (product == null || product.isBlank() || quantity <= 0)
                    throw new IllegalArgumentException("订单参数无效");
                return new Order(this);
            }
        }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：构造订单
         * 数据源：商品名称与数量
         * 操作：1) 设置参数 2) 校验并创建订单
         * ======================================================================== */
        logger.info("开始创建订单");
        // 1.1 指定必需参数和可选参数
        Order order = Order.builder("键盘").quantity(2).build();
        // 1.2 读取完成校验后的对象
        System.out.println(order.product + ":" + order.quantity);
        logger.info("订单创建完成");
    }
}
```

标准输出，日志单独显示：

```text
键盘:2
```

## 结合代码理解

`Order.builder("键盘")` 指定必需参数；`quantity(2)` 设置数量；`build()` 检查名称和数量后创建对象。输出 `键盘:2`。生成器可变，已创建对象的字段不会因后续重新设置生成器而自动改变；如果字段包含可变集合，还需明确是否复制。

## 工作中怎么选

参数少而稳定时，构造器或静态工厂可能更清楚；不要为了模式增加没有变化需求的类。单例共享状态不自动线程安全；复制对象也不自动复制数据库记录或资源。

## 动手与自查

1. 不设置数量，验证默认值；设置 0 并观察校验。
2. 需要同时创建配套的按钮和复选框时，为什么可以考虑抽象工厂？
3. 为什么只复制可变列表的引用可能破坏快照隔离？
