# 策略

> **重要程度：高**｜**手练：需要**
> **重点**：可替换算法与选择。

## 核心概念

策略模式把不同算法实现放在共同接口后，由调用方或配置选择。

## 工作中注意

策略应保持一致的输入输出和错误契约；只有一个简单算法时不必过度设计。

## 手练

实现两种折扣算法并分别测试，调用方只依赖折扣接口。

来源：[教程：策略](https://liaoxuefeng.com/books/java/design-patterns/behavioral/strategy/index.html)。

## 关联知识与实践

设计模式是对常见设计问题的命名和经验，不是必须套用的代码模板。先说清楚要隔离什么变化，再判断抽象是否值得。

把多种计费规则放到策略接口后面，给每种规则写测试。再说明如果规则只有一种，额外抽象是否真的必要。

来源：[教程：设计模式](https://liaoxuefeng.com/books/java/design-patterns/index.html)。
