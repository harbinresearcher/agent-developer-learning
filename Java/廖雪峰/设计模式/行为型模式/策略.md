# 策略

> **重要程度：高**｜**手练：需要**
> **重点**：接口封装可替换算法、调用方注入、不同策略的边界。

## 它解决什么问题

同一项业务需要多种可替换的算法时，可以定义统一接口，每种算法单独实现。`Checkout` 接收一个 `Discount`，只负责调用 `apply`；它不需要知道实际使用无折扣还是固定减免。


## 完整例子

保存为 `StrategyDemo.java`，用 JDK 11 或更高版本编译运行：

```powershell
javac -encoding UTF-8 StrategyDemo.java
java StrategyDemo
```

```java
import java.math.BigDecimal;
import java.util.logging.Logger;
public class StrategyDemo {
    private static final Logger logger = Logger.getLogger(StrategyDemo.class.getName());
    interface Discount { BigDecimal apply(BigDecimal amount); }
    static final class NoDiscount implements Discount {
        public BigDecimal apply(BigDecimal amount) { return amount; }
    }
    static final class FixedDiscount implements Discount {
        public BigDecimal apply(BigDecimal amount) { return amount.subtract(new BigDecimal("10.00")); }
    }
    static final class Checkout {
        private final Discount discount;
        Checkout(Discount discount) { this.discount = discount; }
        BigDecimal total(BigDecimal amount) { return discount.apply(amount); }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：计算订单金额
         * 数据源：测试金额与指定折扣策略
         * 操作：1) 注入策略 2) 输出计算结果
         * ======================================================================== */
        logger.info("开始计算订单");
        // 1.1 同一输入分别交给两种策略
        BigDecimal amount = new BigDecimal("100.00");
        Checkout ordinary = new Checkout(new NoDiscount());
        Checkout coupon = new Checkout(new FixedDiscount());
        // 1.2 对比策略结果
        System.out.println("普通: " + ordinary.total(amount));
        System.out.println("减免: " + coupon.total(amount));
        logger.info("订单计算完成");
    }
}
```

标准输出（日志单独输出）：

```text
普通: 100.00
减免: 90.00
```

## 运行过程与边界

创建 `Checkout` 时注入策略，调用 `total` 时转交给策略计算。同一个金额分别得到 100.00 和 90.00。代码为理解模式而简化，固定减免可能让小额订单出现负数；真实订单必须制定最低金额、精度、舍入和优惠叠加规则，并验证输入。

金额使用字符串构造 `BigDecimal`，避免先经过二进制浮点数；不同币种和计算步骤需明确精度与舍入。策略是算法切换；工厂负责创建对象，两者可以结合，但职责不同。

## 工作中怎么选

支付方式、计费规则和导出格式的差异比较稳定时，策略可隔离变化并单独测试。只有两行且不会变化的判断不必强行拆成多个类。实际项目还需明确按什么规则选择策略、未知类型如何处理，以及策略实例是否有可变状态。

## 动手与自查

1. 新增九折策略，明确保留两位小数的舍入方式，用 99.99 测试。
2. 为固定减免增加最低支付金额规则，并测试输入小于 10.00。
3. 新增策略是否意味着负责选择策略的地方永远不需要修改？
