# 模板方法

> **重要程度：中**｜**手练：需要**
> **重点**：固定流程、可替换步骤与继承约束。

## 它解决什么问题

多个流程的步骤顺序相同，但某个步骤实现不同，可以在父类定义固定流程，把变化的步骤交给子类。例子中 `create()` 统一包装报告格式，调用抽象方法 `body()`；两个子类分别提供正文。`final` 防止子类改变本例模板流程。


## 完整例子

保存为 `TemplateMethodDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 TemplateMethodDemo.java
java TemplateMethodDemo
```

```java
import java.util.logging.Logger;
public class TemplateMethodDemo {
    private static final Logger logger = Logger.getLogger(TemplateMethodDemo.class.getName());
    abstract static class Report {
        final String create() { return "报告：[" + body() + "]"; }
        abstract String body();
    }
    static class SalesReport extends Report {
        String body() { return "销售额 100"; }
    }
    static class StockReport extends Report {
        String body() { return "库存 20"; }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：生成两份报告
         * 数据源：销售和库存报告实现
         * 操作：1) 使用相同流程 2) 输出不同正文
         * ======================================================================== */
        logger.info("开始生成报告");
        // 1.1 创建不同的报告实现
        Report sales = new SalesReport();
        Report stock = new StockReport();
        // 1.2 模板方法固定格式，子类提供正文
        System.out.println(sales.create());
        System.out.println(stock.create());
        logger.info("报告生成结束");
    }
}
```

标准输出，日志单独显示：

```text
报告：[销售额 100]
报告：[库存 20]
```

## 调用顺序

调用 `sales.create()` 时先进入父类方法，再动态分派到 `SalesReport.body()`，最后回到父类拼接格式。父类调用子类方法是一种回调；设计父类时需要明确子类必须遵循的输入、输出和异常契约。

## 工作中怎么选

模板方法用继承固定流程；策略通常用组合替换算法，运行时可根据设计替换不同实现。流程确实稳定且继承关系合理时可以用模板；只想替换单一步骤，组合函数或策略可能更简单。

不要在父类构造器中调用依赖子类尚未初始化状态的可覆盖方法。框架中的钩子方法应遵循框架规定，不要改变必要的初始化和清理顺序。

## 动手与自查

1. 新增用户报告，只实现 `body()`，检查公共格式是否保持一致。
2. 去掉 `final` 并覆盖 `create()`，解释固定流程可能如何被绕过。
3. 如果同一个对象运行时需要更换报告算法，组合策略为什么可能更合适？
