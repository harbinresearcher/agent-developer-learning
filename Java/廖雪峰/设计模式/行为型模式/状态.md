# 状态

> **重要程度：高**｜**手练：需要**
> **重点**：状态转换、合法操作与非法路径。

## 状态模式解决什么问题

同一操作在不同状态下行为不同时，可以让状态本身决定可执行的行为和下一状态。例子中 `NEW.pay()` 返回 `PAID`；`PAID.pay()` 拒绝重复支付。订单持有当前状态，操作委托给当前状态。


## 完整例子

保存为 `StateDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 StateDemo.java
java StateDemo
```

```java
import java.util.logging.Logger;
public class StateDemo {
    private static final Logger logger = Logger.getLogger(StateDemo.class.getName());
    enum State {
        NEW {
            State pay() { return PAID; }
        },
        PAID {
            State pay() { throw new IllegalStateException("订单已支付"); }
        };
        abstract State pay();
    }
    static class Order {
        private State state = State.NEW;
        void pay() { state = state.pay(); }
        State state() { return state; }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：尝试支付订单
         * 数据源：新建的内存订单
         * 操作：1) 支付并查看状态 2) 再次支付并检查错误
         * ======================================================================== */
        logger.info("开始订单状态实验");
        // 1.1 新订单转为已支付
        Order order = new Order();
        order.pay();
        System.out.println("当前状态: " + order.state());
        // 1.2 再次支付由当前状态拒绝
        try { order.pay(); }
        catch (IllegalStateException ex) { System.out.println("拒绝: " + ex.getMessage()); }
        logger.info("订单状态实验结束");
    }
}
```

标准输出，日志单独显示：

```text
当前状态: PAID
拒绝: 订单已支付
```

## 先画状态转换

初始状态为 `NEW`；成功支付后转为 `PAID`；再次支付抛异常，状态仍为 `PAID`。生产订单通常还有待支付、已取消、退款等状态，必须明确每个事件在每个状态下是否合法，而不是只列枚举值。

## 工作中怎么用

状态模式适合状态多、行为差异明显的对象；简单流程用 `enum` 加清晰的判断可能更容易维护。这里用枚举常量实现状态行为，避免为每个状态单建类。

内存状态检查不能保证多实例并发安全。真实系统需结合数据库条件更新、版本号或锁，保证只有一次合法转换；支付请求还需要幂等与外部系统结果核对。
