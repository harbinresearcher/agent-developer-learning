# 中介

> **重要程度：中**｜**手练：需要**
> **重点**：组件协作、中介职责、依赖方向和协调器膨胀。

## 它解决什么问题

多个组件互相改变状态时，组件之间容易形成复杂的直接依赖。中介模式把特定协作规则集中到一个协调对象中。例子中，输入框不直接操作按钮；`FormMediator` 在输入变化后，根据文本是否为空白更新按钮。

## 完整例子

保存为 `MediatorDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 MediatorDemo.java
java MediatorDemo
```

```java
import java.util.logging.Logger;
public class MediatorDemo {
    private static final Logger logger = Logger.getLogger(MediatorDemo.class.getName());
    static class Input {
        private String value = "";
        void setValue(String value) { this.value = value; }
        String value() { return value; }
    }
    static class Button {
        private boolean enabled;
        void setEnabled(boolean enabled) { this.enabled = enabled; }
        boolean enabled() { return enabled; }
    }
    static class FormMediator {
        private final Input input;
        private final Button button;
        FormMediator(Input input, Button button) { this.input = input; this.button = button; }
        void inputChanged(String value) {
            input.setValue(value);
            button.setEnabled(!input.value().isBlank());
        }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：协调输入框和按钮
         * 数据源：模拟的输入值
         * 操作：1) 输入空白 2) 输入有效文本并检查按钮状态
         * ======================================================================== */
        logger.info("开始协调表单");
        // 1.1 组件通过中介协调状态
        Input input = new Input();
        Button button = new Button();
        FormMediator mediator = new FormMediator(input, button);
        // 1.2 比较两次输入后的按钮状态
        mediator.inputChanged(" ");
        System.out.println("空白可提交=" + button.enabled());
        mediator.inputChanged("Alice");
        System.out.println("文本可提交=" + button.enabled());
        logger.info("表单协调完成");
    }
}
```

标准输出，日志单独显示：

```text
空白可提交=false
文本可提交=true
```

`inputChanged` 先更新输入值，再按规则更新按钮。示例是内存中的模型，并没有创建真实图形界面；真实 UI 还要遵循对应框架的事件与线程规则。

## 工作中怎么选

中介减少组件两两连接，但协调逻辑集中后可能变得庞大。按业务职责拆分协调器，让每个组件和事件边界清楚。只有两个简单组件时，直接调用可能更容易理解，不必为了套模式增加一层。

中介和观察者有时一起使用：观察者负责通知状态变化，中介负责决定组件如何协作；它们解决的问题不同。是否异步、是否可靠投递要看具体实现，模式本身不提供这些保证。

## 动手与自查

1. 增加密码输入框，要求两个字段都非空时按钮才可用。
2. 将规则从中介移到输入框，列出输入框需要知道哪些其他组件。
3. 如果表单包含几十个不同业务流程，为什么单个中介可能难以维护？
