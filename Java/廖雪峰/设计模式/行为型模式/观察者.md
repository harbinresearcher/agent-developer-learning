# 观察者

> **重要程度：中**｜**手练：需要**
> **重点**：订阅、发布、同步调用、异常和生命周期。

## 它解决什么问题

当状态变化后有多个对象需要响应，可以让它们订阅事件，由发布者通知观察者。例子中发布者不必写死库存和日志的具体类，只调用已注册的 `Consumer`。两个观察者按注册顺序收到同一个字符串。


## 完整例子

保存为 `ObserverDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 ObserverDemo.java
java ObserverDemo
```

```java
import java.util.ArrayList;
import java.util.List;
import java.util.function.Consumer;
import java.util.logging.Logger;
public class ObserverDemo {
    private static final Logger logger = Logger.getLogger(ObserverDemo.class.getName());
    static class EventBus {
        private final List<Consumer<String>> listeners = new ArrayList<>();
        void subscribe(Consumer<String> listener) { listeners.add(listener); }
        void publish(String event) { for (Consumer<String> listener : listeners) listener.accept(event); }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：订阅并发布事件
         * 数据源：内存中的事件列表和两个监听器
         * 操作：1) 注册监听器 2) 同步发布订单事件
         * ======================================================================== */
        logger.info("开始发布事件");
        // 1.1 注册两个观察者
        EventBus bus = new EventBus();
        bus.subscribe(event -> System.out.println("库存收到: " + event));
        bus.subscribe(event -> System.out.println("日志收到: " + event));
        // 1.2 依次在当前调用线程通知观察者
        bus.publish("订单创建");
        logger.info("事件发布结束");
    }
}
```

标准输出，日志单独显示：

```text
库存收到: 订单创建
日志收到: 订单创建
```

## 同步与异步要分清

示例的 `publish()` 是普通循环，在调用它的同一个线程同步执行；它不是消息队列，也不会自动持久化或跨进程投递。某个监听器抛异常时，当前循环会中断，后续监听器可能收不到；真实系统需要明确失败策略、重试、顺序和幂等。

## 工作中怎么用

观察者减少发布者对接收者的直接依赖，但订阅与取消订阅的生命周期必须清楚，否则长生命周期发布者可能一直持有监听器。例子中的 `ArrayList` 没有并发保护；并发注册或发布需选择明确的线程安全策略。

应用内事件与可靠消息中间件不是同一保证。事务提交失败时事件是否已被观察者处理，取决于事件发布时机；需要可靠跨服务通知时应设计持久化、幂等和故障恢复。

## 动手与自查

1. 让第一个监听器抛异常，观察第二个是否执行。
2. 给事件总线增加取消订阅，并验证取消后不再收到事件。
3. 为什么本例输出成功不能证明消息在进程重启后仍可投递？
