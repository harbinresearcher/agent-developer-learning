# 责任链

> **重要程度：高**｜**手练：需要**
> **重点**：处理顺序、短路、错误传播与职责划分。

## 它解决什么问题

一个请求可能需要按顺序经过多项处理。责任链把每项处理放进独立对象，当前处理器决定继续传给下一个，还是返回结果、终止链条。例子先检查名称，名称无效就立即返回；通过后才检查数量，因此第二条请求只得到名称错误。


## 完整例子

保存为 `ChainDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 ChainDemo.java
java ChainDemo
```

```java
import java.util.logging.Logger;
public class ChainDemo {
    private static final Logger logger = Logger.getLogger(ChainDemo.class.getName());
    static class Request {
        final String product; final int quantity;
        Request(String product, int quantity) { this.product = product; this.quantity = quantity; }
    }
    interface Check { String validate(Request request); }
    static class NameCheck implements Check {
        private final Check next;
        NameCheck(Check next) { this.next = next; }
        public String validate(Request r) {
            if (r.product == null || r.product.isBlank()) return "商品名称不能为空";
            return next.validate(r);
        }
    }
    static class QuantityCheck implements Check {
        public String validate(Request r) { return r.quantity > 0 ? "通过" : "数量必须大于零"; }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：组装并运行校验链
         * 数据源：两条测试请求
         * 操作：1) 先检查名称 2) 名称合法后检查数量
         * ======================================================================== */
        logger.info("开始校验请求");
        // 1.1 根据期望顺序连接校验器
        Check chain = new NameCheck(new QuantityCheck());
        // 1.2 对比合法和不合法请求
        System.out.println(chain.validate(new Request("键盘", 2)));
        System.out.println(chain.validate(new Request("", 0)));
        logger.info("请求校验结束");
    }
}
```

标准输出，日志单独显示：

```text
通过
商品名称不能为空
```

## 工作中怎么用

校验链、Servlet Filter 和部分拦截器链都体现了顺序处理的思想；具体是否调用下一环以及异常如何传播，以对应框架契约为准。需要一次返回所有字段错误时，本例短路方式不适合，应设计为收集错误。

顺序可能影响安全性与结果，例如先做身份认证，再判断用户权限。每个处理器应明确输入输出、是否继续和失败行为；不要让部分环节默默吞掉异常或依赖前一环未声明的副作用。

## 动手与自查

1. 输入商品名称有效但数量为 0，验证第二个校验器的结果。
2. 增加价格校验并说明它应放在链中的什么位置。
3. 如果业务要求同时展示名称和数量错误，这条短路链要怎样调整？
