# 备忘录

> **重要程度：中**｜**手练：需要**
> **重点**：状态快照、恢复、复制边界和历史记录成本。

## 它解决什么问题

需要在修改对象之后恢复先前状态时，可以保存该对象某个时刻的快照。备忘录模式让对象负责生成和恢复快照，外部负责保存快照，而不直接改写其内部字段。例子中的 `Editor` 是状态拥有者，`Snapshot` 保存文本，主方法暂存快照。

## 完整例子

保存为 `MementoDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 MementoDemo.java
java MementoDemo
```

```java
import java.util.logging.Logger;
public class MementoDemo {
    private static final Logger logger = Logger.getLogger(MementoDemo.class.getName());
    static class Editor {
        private String text = "";
        void setText(String value) { text = value; }
        String text() { return text; }
        Snapshot save() { return new Snapshot(text); }
        void restore(Snapshot snapshot) { text = snapshot.text; }
        static final class Snapshot {
            private final String text;
            private Snapshot(String text) { this.text = text; }
        }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：保存并恢复编辑器状态
         * 数据源：内存中的文本内容
         * 操作：1) 保存快照 2) 修改并恢复
         * ======================================================================== */
        logger.info("开始快照实验");
        // 1.1 保存修改前的文本
        Editor editor = new Editor();
        editor.setText("第一版");
        Editor.Snapshot snapshot = editor.save();
        // 1.2 修改当前内容后恢复快照
        editor.setText("第二版");
        System.out.println("修改后=" + editor.text());
        editor.restore(snapshot);
        System.out.println("恢复后=" + editor.text());
        logger.info("快照实验完成");
    }
}
```

标准输出，日志单独显示：

```text
修改后=第二版
恢复后=第一版
```

保存时快照记录第一版文本；修改当前文本不会改变快照，因为 `String` 不可变。`restore` 再将快照内容赋回编辑器。本例只保存一次，并未实现完整的撤销、重做或持久化。

## 工作中怎么用

如果状态含可变列表或对象，只复制引用可能让快照随当前状态一起变化；应按业务定义复制边界。大量完整快照可能占用很多内存，可以考虑限制历史数量或使用增量记录，但要验证恢复正确性。

快照可能包含敏感数据，应控制访问、保留时间和存储方式。恢复内存状态不能自动撤销已发送的消息、扣款或其他外部副作用；跨系统操作需要另行设计补偿与幂等。
