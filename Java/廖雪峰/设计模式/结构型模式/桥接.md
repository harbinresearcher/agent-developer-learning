# 桥接

> **重要程度：中**｜**手练：需要**
> **重点**：识别两个变化维度、组合接口和扩展边界。

## 它解决什么问题

当一个功能存在两个相对独立的变化维度，单靠继承容易为每种组合创建一个子类。桥接把两个维度拆开，通过对象组合连接。例子中，通知有普通和紧急两种类型；渠道有邮件和短信两种。`Notice` 持有 `Channel`，因此新增通知类型不必同时创建各渠道的通知子类。

## 完整例子

保存为 `BridgeDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 BridgeDemo.java
java BridgeDemo
```

```java
import java.util.logging.Logger;
public class BridgeDemo {
    private static final Logger logger = Logger.getLogger(BridgeDemo.class.getName());
    interface Channel { String send(String text); }
    static class Email implements Channel {
        public String send(String text) { return "邮件:" + text; }
    }
    static class Sms implements Channel {
        public String send(String text) { return "短信:" + text; }
    }
    abstract static class Notice {
        protected final Channel channel;
        Notice(Channel channel) { this.channel = channel; }
        abstract String deliver(String text);
    }
    static class NormalNotice extends Notice {
        NormalNotice(Channel channel) { super(channel); }
        String deliver(String text) { return channel.send(text); }
    }
    static class UrgentNotice extends Notice {
        UrgentNotice(Channel channel) { super(channel); }
        String deliver(String text) { return channel.send("紧急:" + text); }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：组合通知类型和渠道
         * 数据源：模拟的邮件与短信渠道
         * 操作：1) 选择不同组合 2) 输出发送结果
         * ======================================================================== */
        logger.info("开始组合通知");
        // 1.1 同一通知类型可以使用不同渠道
        Notice first = new UrgentNotice(new Email());
        Notice second = new UrgentNotice(new Sms());
        // 1.2 通过抽象通知调用渠道
        System.out.println(first.deliver("订单异常"));
        System.out.println(second.deliver("订单异常"));
        logger.info("通知组合完成");
    }
}
```

标准输出，日志单独显示：

```text
邮件:紧急:订单异常
短信:紧急:订单异常
```

两次调用使用相同的紧急通知规则，但注入不同渠道。例子只返回字符串，没有真实发送邮件或短信。普通通知也可以组合任一渠道。

## 工作中怎么选

确实有两个独立变化的维度时，桥接能减少组合类数量；如果变化很少，直接写简单实现可能更容易理解。组合不意味着所有组合都必然有效，业务需要限制不支持的组合，并处理渠道失败、重试与幂等。

桥接与策略都可能通过组合接口切换行为；桥接强调拆分可独立扩展的维度，策略强调替换某一算法。判断应看职责和变化需求，而不是只看类图。
