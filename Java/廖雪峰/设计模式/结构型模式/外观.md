# 外观

> **重要程度：中**｜**手练：需要**
> **重点**：统一入口、子系统边界和错误处理。

## 外观做什么

外观（Facade）为一组组件提供更容易使用的入口。例子把库存检查和模拟支付封装进 `CheckoutFacade`，调用方只调用 `checkout()`。子系统仍各自负责原有职责；外观协调调用顺序并返回结果。


## 完整例子

保存为 `FacadeDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 FacadeDemo.java
java FacadeDemo
```

```java
import java.util.logging.Logger;
public class FacadeDemo {
    private static final Logger logger = Logger.getLogger(FacadeDemo.class.getName());
    static class Inventory { boolean available() { return true; } }
    static class Payment { String charge() { return "支付成功"; } }
    static class CheckoutFacade {
        private final Inventory inventory;
        private final Payment payment;
        CheckoutFacade(Inventory inventory, Payment payment) { this.inventory = inventory; this.payment = payment; }
        String checkout() {
            if (!inventory.available()) return "库存不足";
            return payment.charge();
        }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：提交模拟结算
         * 数据源：内存中的库存与支付组件
         * 操作：1) 组装外观 2) 从统一入口调用
         * ======================================================================== */
        logger.info("开始模拟结算");
        // 1.1 外观组合两个子系统
        CheckoutFacade checkout = new CheckoutFacade(new Inventory(), new Payment());
        // 1.2 调用方只调用结算入口
        System.out.println(checkout.checkout());
        logger.info("模拟结算结束");
    }
}
```

标准输出，日志单独显示：

```text
支付成功
```

## 边界和取舍

例子没有真实扣库存或扣款，不能说明两者具有原子性。实际结算需处理库存并发、重复请求、支付失败、超时和补偿等问题；一个统一入口不会自动提供事务或分布式一致性。

外观适合稳定常用流程，但不要把所有业务都塞进一个巨大类。复杂流程可以拆成清晰的服务；底层接口是否对其他模块开放由架构约定决定。

## 动手与自查

1. 让库存返回 `false`，确认支付方法没有被调用。
2. 让支付失败，设计调用方应收到什么错误。
3. 为什么“检查库存成功再支付”不能保证高并发时不会超卖？
