# 享元

> **重要程度：低**｜**手练：需要**
> **重点**：共享不可变内部状态和限制缓存规模。

## 它解决什么问题

许多对象包含相同的可共享数据时，享元模式将共享部分集中复用，减少重复对象。例子把颜色名称作为可共享状态，同一工厂按名称缓存颜色；两次获取同一个键返回相同对象。


## 完整例子

保存为 `FlyweightDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 FlyweightDemo.java
java FlyweightDemo
```

```java
import java.util.HashMap;
import java.util.Map;
import java.util.logging.Logger;
public class FlyweightDemo {
    private static final Logger logger = Logger.getLogger(FlyweightDemo.class.getName());
    static final class Color {
        final String name;
        Color(String name) { this.name = name; }
    }
    static class ColorFactory {
        private final Map<String, Color> cache = new HashMap<>();
        Color get(String name) { return cache.computeIfAbsent(name, Color::new); }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：复用颜色对象
         * 数据源：单个工厂内的颜色缓存
         * 操作：1) 根据相同名称获取两次 2) 比较引用
         * ======================================================================== */
        logger.info("开始获取颜色");
        // 1.1 相同键从同一个工厂获取对象
        ColorFactory factory = new ColorFactory();
        Color first = factory.get("red");
        Color second = factory.get("red");
        // 1.2 验证对象被复用
        System.out.println("同一对象: " + (first == second));
        logger.info("颜色获取结束");
    }
}
```

标准输出，日志单独显示：

```text
同一对象: true
```

## 内部状态和外部状态

适合共享的内部状态应稳定、可安全复用；随每次使用而变化的外部状态由调用方提供。例如绘制图形时，颜色可以共享，坐标应由每次绘制提供，不应放进共享颜色对象中。

## 工作中怎么选

示例的 `HashMap` 只适合单线程演示，键无限增长也会让缓存无限变大。生产系统需要明确并发控制、容量、淘汰和生命周期；缓存有内存与一致性成本，不应为了套模式缓存一切。字符串常量池或包装类型缓存有各自规则，不能推断所有相同值一定具有同一引用。

## 动手与自查

1. 分别获取 `red` 和 `blue`，比较引用；再用第二个工厂获取 `red` 并比较。
2. 假设用户输入任意颜色名称，说明无限缓存可能出现什么问题。
3. 如果给共享对象增加可变坐标，两个使用者会如何相互影响？
