# 适配器

> **重要程度：高**｜**手练：需要**
> **重点**：接口、包装对象、调用顺序和异常边界。

## 适配器做什么

调用方需要一种接口，现有组件只提供另一种接口时，适配器负责翻译。例子中现有传感器输出华氏温度，应用约定摄氏温度；适配器组合传感器并按 `(F - 32) × 5 / 9` 转换。调用方依赖 `TemperatureSource`，不用了解传感器的方法名和单位。


## 完整例子

保存为 `AdapterDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 AdapterDemo.java
java AdapterDemo
```

```java
import java.util.logging.Logger;
public class AdapterDemo {
    private static final Logger logger = Logger.getLogger(AdapterDemo.class.getName());
    interface TemperatureSource { double celsius(); }
    static final class FahrenheitSensor {
        double readFahrenheit() { return 68.0; }
    }
    static final class SensorAdapter implements TemperatureSource {
        private final FahrenheitSensor sensor;
        SensorAdapter(FahrenheitSensor sensor) { this.sensor = sensor; }
        public double celsius() { return (sensor.readFahrenheit() - 32.0) * 5.0 / 9.0; }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：读取摄氏温度
         * 数据源：只提供华氏温度的模拟传感器
         * 操作：1) 包装传感器 2) 通过目标接口读取
         * ======================================================================== */
        logger.info("开始读取温度");
        // 1.1 将不兼容的传感器适配为应用接口
        TemperatureSource source = new SensorAdapter(new FahrenheitSensor());
        // 1.2 调用方只处理摄氏温度
        System.out.println("摄氏温度: " + source.celsius());
        logger.info("温度读取完成");
    }
}
```

标准输出（日志单独输出）：

```text
摄氏温度: 20.0
```

## 工作中怎么用

接入外部服务时，适配器可把第三方 DTO 转为内部模型、统一错误类型，并明确时间、货币、编码和单位。接口签名能转换不代表语义就一致：例如外部接口的超时、重试、幂等、缺失字段都需要单独定义。

不要用适配器悄悄吞掉异常或用默认值掩盖失败。浮点温度只是示例；金额计算应明确十进制精度和舍入规则。依赖第三方接口的测试应覆盖成功、缺字段和失败映射。

## 手练与自查

1. 将华氏值改为 32.0 和 212.0，分别验证摄氏结果。
2. 让模拟传感器抛异常，明确适配器应传播还是转换异常，并写出预期。
3. 如果两边方法名相同但温度单位不同，为什么仍需要适配？
