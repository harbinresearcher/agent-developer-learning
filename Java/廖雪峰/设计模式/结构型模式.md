# 结构型模式

> **重要程度：高**｜**手练：需要**
> **重点**：接口适配、对象组合、包装顺序和资源边界。

## 先理解共同问题

结构型模式关注类和对象如何组合。核心不是记类图，而是先区分要解决的是接口不兼容、组合树结构，还是给已有对象增加能力。

- 适配器转换接口或语义；桥接把两个可独立变化的维度组合起来。
- 组合用统一接口处理叶节点和组合节点；外观为一组组件提供简化入口。
- 装饰器包装同接口对象并叠加行为；代理侧重控制访问或调用方式。
- 享元复用可共享状态，需要同时考虑缓存大小与生命周期。

下面用装饰器比较两种包装顺序。

## 完整例子

保存为 `DecoratorDemo.java`，使用 JDK 11 或更高版本：

```powershell
javac -encoding UTF-8 DecoratorDemo.java
java DecoratorDemo
```

```java
import java.util.logging.Logger;
public class DecoratorDemo {
    private static final Logger logger = Logger.getLogger(DecoratorDemo.class.getName());
    interface TextSource { String read(); }
    static final class PlainText implements TextSource {
        public String read() { return "  java  "; }
    }
    static final class Trimmed implements TextSource {
        private final TextSource inner;
        Trimmed(TextSource inner) { this.inner = inner; }
        public String read() { return inner.read().trim(); }
    }
    static final class Bracketed implements TextSource {
        private final TextSource inner;
        Bracketed(TextSource inner) { this.inner = inner; }
        public String read() { return "[" + inner.read() + "]"; }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：组合文本处理
         * 数据源：带空格的模拟文本
         * 操作：1) 构建两种包装顺序 2) 比较结果
         * ======================================================================== */
        logger.info("开始处理文本");
        // 1.1 分别组装两条处理链
        TextSource first = new Bracketed(new Trimmed(new PlainText()));
        TextSource second = new Trimmed(new Bracketed(new PlainText()));
        // 1.2 方括号使空格差异可见
        System.out.println("先去空格: " + first.read());
        System.out.println("先加括号: " + second.read());
        logger.info("文本处理完成");
    }
}
```

标准输出，日志单独显示：

```text
先去空格: [java]
先加括号: [  java  ]
```

## 结合代码理解

`Bracketed(Trimmed(PlainText))` 先读取原文并去除两端空格，再加括号，得到 `[java]`。顺序反过来时，空格在括号内部，外层 `trim()` 不会去掉它们，得到 `[  java  ]`。包装顺序会影响结果。

## 工作中怎么选

Java IO 的包装流常用于组合缓冲和转换；要查具体类的关闭和异常契约。不要为了少量稳定逻辑建立过长包装链。代理和装饰器的结构可能相似，应根据控制访问还是叠加职责来理解。

## 动手与自查

2. 增加大写装饰器并验证结果。
3. 接口不兼容和给同接口增加功能，分别更接近哪种模式？
