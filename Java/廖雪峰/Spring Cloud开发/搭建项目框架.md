# 搭建项目框架

> **重要程度：高**｜**手练：需要**
> **重点**：Maven 模块聚合、父 POM 继承和模块依赖的区别；依赖方向；版本兼容和配置外置。

## 教程怎么拆模块

教程把公共代码、配置服务、交易 API、定序、交易引擎、行情、推送和 UI 拆为多个 Maven 模块。模块是一种构建和代码组织方式；它可以打成库，也可以打成独立应用。**有多个 Maven 模块并不自动等于多个已部署的微服务**。

一般将与业务无关且稳定的小型契约放到公共模块；不要把所有服务的实现、数据库实体和配置都塞进公共模块，否则一次改动会牵连所有服务。先确认依赖方向，再按职责拆分。

## 先弄懂三种关系

- **聚合**：根 POM 用 `<modules>` 列出模块，在根目录构建时 Maven 按依赖关系确定构建顺序。
- **继承**：子 POM 用 `<parent>` 继承父 POM 的公共配置。父 POM 常用 `packaging=pom`。
- **依赖**：API 模块显式声明依赖 common，才能在代码中引用 common 的类。仅有聚合或父子关系，不会自动让 API 获得 common 的类。

`dependencyManagement` 管理依赖版本和默认配置，本身不等于已引入依赖；真正使用时还需在 `<dependencies>` 声明。避免模块形成循环依赖。

## 手练：两个模块协作

示例只演示 Maven 关系，不包含 Spring Cloud 或网络调用。准备 JDK 17 和 Maven，目录如下：

```text
demo/
├── pom.xml
├── common/
│   ├── pom.xml
│   └── src/main/java/learn/common/Pair.java
└── api/
    ├── pom.xml
    └── src/main/java/learn/api/Main.java
```

`pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>
  <groupId>learn.exchange</groupId><artifactId>demo-parent</artifactId><version>1.0</version>
  <packaging>pom</packaging>
  <modules><module>common</module><module>api</module></modules>
  <properties><maven.compiler.release>17</maven.compiler.release><project.build.sourceEncoding>UTF-8</project.build.sourceEncoding></properties>
  <build><pluginManagement><plugins><plugin>
    <groupId>org.apache.maven.plugins</groupId><artifactId>maven-compiler-plugin</artifactId><version>3.13.0</version>
  </plugin></plugins></pluginManagement></build>
</project>
```

`common/pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>
  <parent><groupId>learn.exchange</groupId><artifactId>demo-parent</artifactId><version>1.0</version></parent>
  <artifactId>common</artifactId>
</project>
```

`api/pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>
  <parent><groupId>learn.exchange</groupId><artifactId>demo-parent</artifactId><version>1.0</version></parent>
  <artifactId>api</artifactId>
  <dependencies><dependency><groupId>learn.exchange</groupId><artifactId>common</artifactId><version>1.0</version></dependency></dependencies>
</project>
```

`common/src/main/java/learn/common/Pair.java`：

```java
package learn.common;
import java.util.Locale;
import java.util.logging.Logger;
public class Pair {
    private static final Logger logger = Logger.getLogger(Pair.class.getName());
    public static String normalize(String input) {
        /* ========================================================================
         * 步骤1：规范化交易对名称
         * 数据源：调用方提供的字符串
         * 操作：1) 去除两端空格 2) 转换为大写
         * ======================================================================== */
        logger.info("开始规范化交易对");
        // 1.1 使用固定区域规则，避免系统区域差异
        String result = input.trim().toUpperCase(Locale.ROOT);
        logger.info("交易对规范化结束");
        return result;
    }
}
```

`api/src/main/java/learn/api/Main.java`：

```java
package learn.api;
import java.util.logging.Logger;
import learn.common.Pair;
public class Main {
    private static final Logger logger = Logger.getLogger(Main.class.getName());
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：调用公共模块
         * 数据源：固定演示字符串
         * 操作：1) 调用公共代码 2) 输出结果
         * ======================================================================== */
        logger.info("开始调用公共模块");
        // 1.1 从依赖模块调用方法
        System.out.println(Pair.normalize(" btc/usd "));
        logger.info("公共模块调用结束");
    }
}
```

在 `demo` 根目录运行：

```powershell
mvn package
java -cp "api/target/classes;common/target/classes" learn.api.Main
```

标准输出为 `BTC/USD`，日志时间可能不同。示例已在 JDK 17 下用 Maven 构建并运行；此处的 Windows 类路径分隔符为分号，Linux/macOS 使用冒号。构建时无需先单独 `install` common，根聚合构建会识别模块之间的依赖。

## Spring Cloud 项目还要做什么

1. **选择版本**：先选受支持的 JDK、Spring Boot，再按 Spring Cloud 官方发布列车兼容表选择 Cloud 版本。教程里的版本是学习时的例子，不应无条件复制到新项目。
2. **依赖管理**：通过受支持的 BOM 管理相关组件版本；检查传递依赖和漏洞修复，避免各服务随意覆盖相同组件版本。
3. **配置**：开发、测试和生产环境分开；配置服务、数据库或消息中间件的密码不要提交到源码仓库。外置配置也需要访问控制和审计。
4. **部署**：每个独立应用要有启动入口、健康检查、日志、必要的资源限制和回滚方案。构建成功只说明制品生成，不能证明服务间网络、权限和数据一致性正确。
5. **测试**：公共模块做单元测试，服务边界做契约和集成测试；测试数据库和消息系统应隔离，不能误连真实业务环境。

## 自测

1. 删除 API 的 common 依赖但保留聚合关系，`import learn.common.Pair` 为什么不能编译？
2. 父 POM 的 `dependencyManagement` 管理了某依赖版本，子模块没有声明它，代码能否直接使用该依赖？
3. 两个服务共用数据库实体会产生什么升级和耦合风险？
4. 构建成功后，为何仍要验证服务启动和远程调用？
