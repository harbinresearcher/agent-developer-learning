# 设计推送系统

> **重要程度：高**｜**手练：需要**
> **重点**：WebSocket 握手与服务端主动推送；公开行情和私人订单消息的权限差别；断线恢复、消息顺序和慢客户端。

## 推送服务负责什么

推送服务把行情或业务状态变化主动发送给在线客户端，减少客户端不断轮询。公开行情可以发给订阅该市场的用户；订单和资产变化属于私人数据，只能发送给经过认证且有权查看的用户。

```text
成交事件 → 行情或订单状态 → 推送服务 → 已授权的连接 → 页面更新
                                  └→ 断线后通过查询或重放补齐
```

WebSocket 从 HTTP 握手开始，成功升级后双方可在连接上收发消息。它不是可靠消息队列：客户端掉线时消息可能没收到，重连后需要快照、序号或可重放事件支持。

教程使用 Vert.x 处理 WebSocket。本例用 Spring WebSocket 演示相同的“服务端主动发送”概念；它不是教程完整推送系统，也没有实现消息广播、订阅、登录或断线重放。

## 手练：连接后接收一条公开行情

准备 JDK 17 和 Maven，创建三个文件：

`src/main/java/learn/push/PushDemo.java`：

```java
package learn.push;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.socket.TextMessage;
import org.springframework.web.socket.WebSocketSession;
import org.springframework.web.socket.config.annotation.EnableWebSocket;
import org.springframework.web.socket.config.annotation.WebSocketConfigurer;
import org.springframework.web.socket.config.annotation.WebSocketHandlerRegistry;
import org.springframework.web.socket.handler.TextWebSocketHandler;

@SpringBootApplication
@EnableWebSocket
public class PushDemo implements WebSocketConfigurer {
    private static final Logger logger = LoggerFactory.getLogger(PushDemo.class);
    static class MarketHandler extends TextWebSocketHandler {
        @Override
        public void afterConnectionEstablished(WebSocketSession session) throws Exception {
            /* ========================================================================
             * 步骤1：向新连接推送公开演示行情
             * 数据源：固定的本地示例数据
             * 操作：1) 创建消息 2) 发送到当前连接
             * ======================================================================== */
            logger.info("开始推送示例行情");
            // 1.1 客户端无需先发送请求消息
            String tick = "{\"type\":\"tick\",\"sequence\":1,\"price\":\"100\"}";
            session.sendMessage(new TextMessage(tick));
            logger.info("示例行情推送结束");
        }
    }
    @Override
    public void registerWebSocketHandlers(WebSocketHandlerRegistry registry) {
        /* ========================================================================
         * 步骤1：注册本地 WebSocket 路径
         * 数据源：应用配置
         * 操作：1) 指定处理器 2) 限定演示来源
         * ======================================================================== */
        logger.info("开始注册推送路径");
        // 1.1 此来源仅供本机页面练习
        registry.addHandler(new MarketHandler(), "/market").setAllowedOrigins("http://localhost:8080");
        logger.info("推送路径注册结束");
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：启动本地推送演示
         * 数据源：Spring Boot 配置
         * 操作：1) 启动容器 2) 注册处理器
         * ======================================================================== */
        logger.info("开始启动推送演示");
        // 1.1 启动嵌入式服务器
        SpringApplication.run(PushDemo.class, args);
        logger.info("推送演示启动结束");
    }
}
```

`src/main/resources/static/index.html`：

```html
<!doctype html>
<html lang="zh">
<head><meta charset="UTF-8"><title>行情推送练习</title></head>
<body>
  <p id="status">正在连接</p>
  <p id="market">等待行情</p>
  <script>
    const logger = console;
    /* ========================================================================
     * 步骤1：连接本地推送服务
     * 数据源：本机 WebSocket；操作：1) 接收行情 2) 更新页面文本
     * ======================================================================== */
    logger.info("开始连接行情服务");
    // 1.1 使用当前页面的主机和端口
    const socket = new WebSocket(`ws://${location.host}/market`);
    socket.onmessage = event => {
      // 1.2 用文本显示消息，避免将消息解释为 HTML
      document.getElementById("market").textContent = event.data;
    };
    socket.onopen = () => { document.getElementById("status").textContent = "已连接"; };
    socket.onclose = () => {
      document.getElementById("status").textContent = "连接已关闭";
      logger.info("行情连接已结束");
    };
  </script>
</body>
</html>
```

项目根目录运行：

```powershell
mvn package
java -jar target/cloud-push-demo-1.0.jar --server.address=127.0.0.1 --server.port=8080
```

在浏览器打开 `http://localhost:8080/`。握手通过后，服务端会主动发送一条固定消息，页面应显示 `{"type":"tick","sequence":1,"price":"100"}`。这个 1 只是固定示例值，不是可恢复的全局序列；再次连接也会收到相同值。

已验证 HTTP 页面可获取、两个 WebSocket 连接各收到消息，以及来源 `http://localhost:8081` 被拒绝；没有自动化验证浏览器页面渲染。服务端只允许来源 `http://localhost:8080`，所以不要用 `127.0.0.1:8080` 打开页面；完成后按 Ctrl+C 停止服务。

`textContent` 将收到的数据当作文本显示；不要直接把不可信消息作为 HTML 插入页面。这个例子只适合本机明文练习，生产连接应使用 HTTPS/WSS 和经过验证的认证、权限策略。

## 公共和私有消息怎么区分

- **公开行情**：例如某交易对最新价格，可按主题订阅。应限制订阅数量、消息大小和频率。
- **私人消息**：例如订单成交和资产变化，必须基于服务端验证的用户身份路由；不能相信客户端自行声明的 userId。检查连接建立和订阅时的权限，权限变化或会话失效时应终止相应访问。
- **来源检查**：限制浏览器 `Origin` 有助于减少跨站 WebSocket 滥用，但非浏览器客户端可自行构造该头；它不是身份认证，也不能代替授权。

## 断线、乱序和恢复

假设客户端已处理序号 10，连接中断后收到序号 13：不能仅显示 13 并认定数据完整。应根据同一顺序域的协议检查缺口，查询权威快照或请求补发，再按规则合并和去重。快照版本与增量衔接点必须匹配，否则快照加载期间仍可能漏消息。

Redis Pub/Sub 适合实时广播，但订阅方断线期间错过的消息不能靠它自动重放。若业务必须恢复历史，需要有持久化事件、有效的游标、保留策略和补偿查询；私人订单最终状态应以权威订单查询为准。

慢客户端可能让发送缓冲区持续增长。应限制连接和队列容量、消息大小与发送速率；行情可以按明确规则合并或丢弃过期更新，关键订单消息则要设计可靠查询和补偿。监控连接数、断线率、积压、发送失败和恢复耗时。

教程将 Servlet 模型与大量连接的效率作了较绝对的比较。实际容量取决于容器、应用是否阻塞、消息频率、网络和资源配置，应通过负载测试决定；采用非阻塞框架也不自动解决背压或慢客户端问题。

## 自测

1. WebSocket 握手成功后，为什么服务端可以先发消息？
2. 客户端收到 10 后断线，重连收到 13，可能漏了什么？如何补齐？
3. 为什么客户端请求订阅 userId=42 不能证明它有权看该用户订单？
4. 如果推送服务广播速度高于客户端消费速度，系统应如何限制资源？
