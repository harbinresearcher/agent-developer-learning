# 项目架构设计

> **重要程度：中**｜**手练：按需**
> **重点**：服务拆分、组件和边界。

## 核心概念

教程以交易系统为例，讨论 API、定序、交易引擎、行情、推送及数据组件之间的职责。不同组件通过明确的数据流配合。

## 工作中注意

教程使用的组件版本是示例，实际项目需要重新核对支持状态；架构图不证明可用性、准确性或生产安全。

## 手练

画出订单请求从 API 到定序、交易引擎和推送的主链路。

来源：[教程：项目架构设计](https://liaoxuefeng.com/books/java/springcloud/architecture/index.html)。

## 关联知识与实践

分布式系统把多个服务放在不同进程或机器上，调用经过网络。服务拆分带来独立部署机会，也增加超时、部分失败、追踪、数据一致性和运维成本；不要只因为可以拆分就拆分。

服务调用要设超时，按操作语义设计有限重试、退避和熔断；请求可能成功但响应丢失，调用方不能仅凭超时断定没有执行。写操作需要根据业务设计幂等键、唯一约束或去重记录。消息系统可能重复投递或乱序，消费端也要处理幂等与失败恢复。
