# 设计行情系统

> **重要程度：高**｜**手练：需要**
> **重点**：成交 Tick 与 K 线；OHLC 和成交量的计算；窗口边界、重复与乱序数据处理。

## 从一笔成交到 K 线

行情系统消费交易引擎产生的成交记录（Tick），按交易对和时间窗口聚合。一个窗口中的 K 线通常包括：

- **Open**：窗口内第一笔成交价。
- **High / Low**：窗口内最高、最低成交价。
- **Close**：窗口内最后一笔成交价。
- **Volume**：窗口内成交数量之和。成交额是价格乘数量的和，和成交数量不是同一个指标。

例如某分钟按顺序成交 `100×1`、`103×3`、`98×2`、`101×1`，则开 100、高 103、低 98、收 101、成交量 7。若只看最高价和最低价，无法知道开盘和收盘价，需要明确事件先后。

## 手练：聚合一分钟成交

保存为 `CandleDemo.java`。示例假定四笔成交属于同一分钟，用秒数排序，同一秒用序号打破平局：

```java
import java.math.BigDecimal;
import java.util.Comparator;
import java.util.List;
import java.util.logging.Logger;

public class CandleDemo {
    private static final Logger logger = Logger.getLogger(CandleDemo.class.getName());
    record Tick(long second, long sequence, BigDecimal price, BigDecimal quantity) {}
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：按事件时间和序号排列成交
         * 数据源：同一分钟内的四笔示例成交
         * 操作：1) 定义成交数据 2) 确定开盘收盘顺序
         * ======================================================================== */
        logger.info("开始排列成交");
        // 1.1 输入故意乱序，排序规则需事先明确
        List<Tick> ticks = List.of(
            new Tick(20, 3, new BigDecimal("98"), new BigDecimal("2")),
            new Tick(0, 1, new BigDecimal("100"), new BigDecimal("1")),
            new Tick(40, 4, new BigDecimal("101"), new BigDecimal("1")),
            new Tick(10, 2, new BigDecimal("103"), new BigDecimal("3"))
        ).stream().sorted(Comparator.comparingLong(Tick::second)
                .thenComparingLong(Tick::sequence)).toList();
        logger.info("成交排序结束");
        /* ========================================================================
         * 步骤2：生成一分钟 K 线
         * 数据源：已排序的非空成交集合
         * 操作：1) 求最高最低价和成交量 2) 输出开收盘价
         * ======================================================================== */
        logger.info("开始聚合 K 线");
        // 2.1 首尾决定开收盘，中间逐笔更新极值与数量
        BigDecimal open = ticks.get(0).price();
        BigDecimal close = ticks.get(ticks.size() - 1).price();
        BigDecimal high = open;
        BigDecimal low = open;
        BigDecimal volume = BigDecimal.ZERO;
        for (Tick tick : ticks) {
            high = high.max(tick.price());
            low = low.min(tick.price());
            volume = volume.add(tick.quantity());
        }
        System.out.println("开=" + open + ",高=" + high + ",低=" + low
                + ",收=" + close + ",量=" + volume);
        logger.info("K 线聚合结束");
    }
}
```

```powershell
javac -encoding UTF-8 --release 17 CandleDemo.java
java '-Dfile.encoding=UTF-8' CandleDemo
```

标准输出：

```text
开=100,高=103,低=98,收=101,量=7
```

本例已用 JDK 17 编译运行并核对结果。输入刻意乱序，先排序才能正确计算开盘与收盘。

**示例边界**：集合假定非空、无重复、均在同一交易对和窗口。程序没有接入 Kafka、Redis、数据库或实时推送，也没有处理延迟事件和重新计算。

## 实际聚合要补的规则

1. **窗口**：明确起止时间，例如 UTC 下 `[10:00:00, 10:01:00)`；左闭右开使边界成交只属于一个窗口。日线和周线要明确时区。
2. **顺序**：说明采用成交事件时间还是定序顺序，以及时间相同如何排序；不能默认网络到达顺序等于成交顺序。
3. **迟到数据**：窗口结束后迟到的成交可能改变开收盘价、最高最低价及成交量。需要定义允许延迟、修正和重新推送策略，不能静默丢弃。
4. **重复消息**：根据稳定的成交 ID 去重；否则最高最低价可能看似正确，但成交量会重复累加。去重状态的持久性和保留时间也要设计。
5. **无成交窗口**：由产品规则决定不生成 K 线，还是用前收盘价生成零成交量 K 线；不要把填充数据误当成真实成交。
6. **缓存与权威数据**：Redis 可以提供近期查询，但缓存丢失或推送断线后，应能依据持久化成交或可靠的聚合结果恢复；先确认权威数据源与刷新顺序。

教程使用 Redis 脚本更新近期成交列表。Redis 在脚本运行时不会与其他命令交错，但这不等同于跨 Redis、数据库和消息系统的原子事务；Pub/Sub 断线期间消息也不保证可重放。
