# 设计交易引擎

> **重要程度：中**｜**手练：按需**
> **重点**：资产、订单、撮合和清算。

## 核心概念

交易引擎示例将资产管理、活动订单、买卖撮合和成交后的清算组织在一起。

## 工作中注意

涉及资金和订单的一致性不能由示例代码自动证明；明确事件顺序、持久化及故障恢复边界。

## 手练

用一笔买卖画出资产冻结、订单创建、撮合和清算的状态变化。

来源：[教程：设计交易引擎](https://liaoxuefeng.com/books/java/springcloud/engine/index.html)。

## 关联知识与实践

教程以交易系统为例，涉及资产、订单、撮合、清算、定序、API、行情和推送。先分清各组件职责与数据流：请求进入 API，业务处理生成状态变化，再将可发布结果传递给行情或推送。事务边界、失败恢复和消息顺序需要结合具体实现验证，不能只凭架构图认定成立。

来源：[教程：Spring Cloud开发](https://liaoxuefeng.com/books/java/springcloud/index.html)。
