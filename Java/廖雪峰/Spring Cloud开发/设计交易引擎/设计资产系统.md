# 设计资产系统

> **重要程度：高**｜**手练：需要**
> **重点**：可用余额、冻结余额、资金划转与守恒；余额不足的校验；持久化、并发与对账。

## 为什么下单要冻结资产

账户有 100 USD，用户下单需要 50 USD。如果只检查余额而不冻结，同一账户接着下两笔各需 50 USD 的订单，看起来都能下单，之后可能没有足够资产兑现。冻结把额度从可用余额转到冻结余额，防止同一额度重复使用。

```text
冻结前：可用 100 + 冻结 0  = 总额 100
冻结后：可用  50 + 冻结 50 = 总额 100
解冻20：可用  70 + 冻结 30 = 总额 100
```

冻结和解冻只在同一账户内部移动金额，正常情况下总额不变。成交清算会把资产转给对手方，此时单个账户总额会变，需按资产种类检查交易双方与其他账户的整体流水；充值、提现、手续费也需要纳入对应账户或外部边界。

买单通常冻结计价资产（BTC/USD 中的 USD），卖单冻结基础资产（BTC）。具体冻结金额、手续费和精度由交易规则决定。

## 手练：冻结和解冻

保存为 `AssetDemo.java`，用 JDK 17 编译运行：

```java
import java.math.BigDecimal;
import java.util.logging.Logger;

public class AssetDemo {
    private static final Logger logger = Logger.getLogger(AssetDemo.class.getName());
    static class Account {
        private BigDecimal available;
        private BigDecimal frozen = BigDecimal.ZERO;
        Account(String initial) { available = new BigDecimal(initial); }
        void freeze(BigDecimal amount) {
            /* ========================================================================
             * 步骤1：冻结指定数量
             * 数据源：账户可用余额与请求数量
             * 操作：1) 校验正数及余额 2) 在两个余额间划转
             * ======================================================================== */
            logger.info("开始冻结");
            // 1.1 先验证，再同时修改可用与冻结余额
            if (amount.signum() <= 0 || available.compareTo(amount) < 0) {
                logger.info("冻结失败：数量无效或余额不足");
                throw new IllegalArgumentException("invalid freeze");
            }
            available = available.subtract(amount);
            frozen = frozen.add(amount);
            logger.info("冻结结束");
        }
        void unfreeze(BigDecimal amount) {
            /* ========================================================================
             * 步骤1：解冻指定数量
             * 数据源：账户冻结余额与请求数量
             * 操作：1) 校验正数及冻结余额 2) 退回可用余额
             * ======================================================================== */
            logger.info("开始解冻");
            // 1.1 先验证，再更新两个余额
            if (amount.signum() <= 0 || frozen.compareTo(amount) < 0) {
                logger.info("解冻失败：数量无效或冻结余额不足");
                throw new IllegalArgumentException("invalid unfreeze");
            }
            frozen = frozen.subtract(amount);
            available = available.add(amount);
            logger.info("解冻结束");
        }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：演示冻结及撤单解冻
         * 数据源：初始 100 USD 的账户
         * 操作：1) 冻结 50 2) 撤销部分订单并解冻 20
         * ======================================================================== */
        logger.info("开始资产演示");
        // 1.1 执行两次余额划转
        Account account = new Account("100");
        account.freeze(new BigDecimal("50"));
        account.unfreeze(new BigDecimal("20"));
        System.out.println("可用=" + account.available + ", 冻结=" + account.frozen);
        System.out.println("总额=" + account.available.add(account.frozen));
        logger.info("资产演示结束");
    }
}
```

```powershell
javac -encoding UTF-8 --release 17 AssetDemo.java
java '-Dfile.encoding=UTF-8' AssetDemo
```

标准输出：

```text
可用=70, 冻结=30
总额=100
```

已编译运行并核对输出。`BigDecimal` 用字符串构造，避免先经过二进制浮点误差；`compareTo` 比较金额大小。冻结和解冻都先检查数量为正且余额足够，再改动余额。

**示例边界**：账户仅保存在内存，单线程运行，没有账本、数据库事务或订单关联，不能直接用于真实资金。上面的两次字段赋值不是跨线程或崩溃时的原子操作。

## 数据如何组织

一条余额通常按“账户 ID + 资产类型”定位，并区分可用和冻结金额。冻结记录还应能关联订单或业务操作：否则只知道总共冻结了多少，不知道撤销哪笔订单可以解冻多少。

流水应记录业务操作 ID、资产、变更前后或借贷方向、金额、时间、关联订单和原因。余额是当前状态，流水用于追踪与对账；二者需要在明确的事务边界内保持一致，并设置防重复约束。

教程引入系统负债账户，让每个资产在所定义的账户集合内满足记账平衡。这有助于检查内部账务，但系统内平衡不能证明链上钱包或银行账户真实存在相同资金；仍需与外部账单核对。

## 生产问题

1. **并发**：两笔请求同时读取 100 并分别冻结 80，若只在应用内读后写，可能都通过。需要单写入者、数据库行锁、条件更新或乐观锁等明确方案，并验证并发失败路径。
2. **原子性**：创建订单、冻结余额与写流水应有一致的事务或可靠状态机设计；中间崩溃不能留下无订单的冻结资金，也不能出现未冻结却已生效的订单。
3. **幂等**：相同业务请求重复到达时，用稳定业务 ID 和唯一约束防止重复冻结；单纯检查余额不足不能代替去重。
4. **精度**：按资产明确数量精度和最小变动单位；校验小数位、金额上限和舍入方式。整数最小单位也是一种选择，但要处理溢出。
5. **对账与恢复**：定期比较余额与流水、冻结额与活动订单、内部记录与外部资产；准备异常告警、锁定与人工核查流程。

## 自测

1. 可用 70、冻结 30，再冻结 80 会怎样？失败后两个余额应是多少？
2. 两个线程同时对 100 USD 各冻结 80，为什么只使用 `ConcurrentHashMap` 仍不能保证业务正确？
3. 撤单重复提交两次，如何避免将同一笔冻结额解冻两次？
4. 冻结总额和订单冻结明细不一致时，如何定位？
