# 设计订单系统

> **重要程度：高**｜**手练：需要**
> **重点**：订单字段与状态转换；部分成交和部分撤销；冻结、订单索引及幂等的一致性。

## 订单记录什么

订单表示用户的交易意图，不等于已经成交。常见字段有订单 ID、用户 ID、交易对、买卖方向、限价、原始数量、已成交数量、剩余数量、状态、定序号及创建时间。定序号可用于同价订单的先后顺序；显示时间不应未经规则定义就充当可靠排序键。

对于本文的简化状态模型，始终检查：`原始数量 = 已成交数量 + 已撤销数量 + 当前剩余数量`。真实系统可能用其他字段命名或状态定义，但必须明确每个数量的含义。

## 状态怎么变化

```text
OPEN（等待成交） ──成交一部分──→ PARTIAL（部分成交）
       │                              ├──成交剩余──→ FILLED（全部成交）
       ├──全部成交──→ FILLED          └──撤销剩余──→ PARTIAL_CANCELLED
       └──撤销全部──→ CANCELLED
```

FILLED、CANCELLED 和 PARTIAL_CANCELLED 在这个模型中都是终态；终态不能再成交。部分成交后撤单只能撤销尚未成交的部分，已成交的资产交换不能因为撤单自动倒转。

## 手练：部分成交后撤单

保存为 `OrderDemo.java`，使用 JDK 17：

```java
import java.util.logging.Logger;

public class OrderDemo {
    private static final Logger logger = Logger.getLogger(OrderDemo.class.getName());
    enum Status { OPEN, PARTIAL, FILLED, CANCELLED, PARTIAL_CANCELLED }
    static class Order {
        final int total;
        int filled;
        int remaining;
        int cancelled;
        Status status = Status.OPEN;
        Order(int quantity) {
            if (quantity <= 0) throw new IllegalArgumentException("quantity");
            total = quantity;
            remaining = quantity;
        }
        void fill(int quantity) {
            /* ========================================================================
             * 步骤1：登记一笔成交
             * 数据源：活动订单和本次成交数量
             * 操作：1) 检查状态与数量 2) 更新数量与订单状态
             * ======================================================================== */
            logger.info("开始登记成交");
            // 1.1 已结束的订单不可再次成交
            if ((status != Status.OPEN && status != Status.PARTIAL)
                    || quantity <= 0 || quantity > remaining) {
                logger.info("成交被拒绝");
                throw new IllegalStateException("invalid fill");
            }
            filled += quantity;
            remaining -= quantity;
            status = remaining == 0 ? Status.FILLED : Status.PARTIAL;
            logger.info("成交登记结束");
        }
        void cancel() {
            /* ========================================================================
             * 步骤1：撤销剩余数量
             * 数据源：活动订单
             * 操作：1) 检查当前状态 2) 记录撤销量并关闭订单
             * ======================================================================== */
            logger.info("开始撤销订单");
            // 1.1 只撤销尚未成交的数量
            if (status != Status.OPEN && status != Status.PARTIAL) {
                logger.info("撤销被拒绝");
                throw new IllegalStateException("order already closed");
            }
            cancelled = remaining;
            remaining = 0;
            status = filled == 0 ? Status.CANCELLED : Status.PARTIAL_CANCELLED;
            logger.info("订单撤销结束");
        }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：演示部分成交后撤单
         * 数据源：数量为 5 的示例订单
         * 操作：1) 成交 2 2) 撤销剩余部分
         * ======================================================================== */
        logger.info("开始订单演示");
        // 1.1 依次成交和撤单
        Order order = new Order(5);
        order.fill(2);
        System.out.println("成交后=" + order.status + ",剩余=" + order.remaining);
        order.cancel();
        System.out.println("撤单后=" + order.status + ",成交=" + order.filled
                + ",撤销=" + order.cancelled + ",剩余=" + order.remaining);
        try {
            // 1.2 验证已结束订单不能再次成交
            order.fill(1);
            throw new AssertionError("expected rejection");
        } catch (IllegalStateException expected) {
            System.out.println("终态成交被拒绝");
        }
        logger.info("订单演示结束");
    }
}
```

```powershell
javac -encoding UTF-8 --release 17 OrderDemo.java
java '-Dfile.encoding=UTF-8' OrderDemo
```

标准输出：

```text
成交后=PARTIAL,剩余=3
撤单后=PARTIAL_CANCELLED,成交=2,撤销=3,剩余=0
终态成交被拒绝
```

本例已编译运行并核对输出，包括终态再次成交被拒绝。数量用整数仅用于说明状态；没有价格、资产冻结、持久化或并发控制，不是完整订单系统。

## 创建、成交、撤单要一起看

1. **创建**：验证身份、交易对、价格和数量；买单按规则冻结计价资产，卖单冻结基础资产；生成订单并记录请求 ID。
2. **成交**：撮合给出成交明细，减少双方剩余数量并登记成交；清算按明细移动资产。单个订单可能分多笔成交。
3. **撤单**：只能处理当前尚未成交数量；撤销成功后按规则解冻对应余额。撤单与成交同时到达时，按确定顺序处理，不能让同一剩余量同时成交又撤销。
4. **历史**：活动订单从内存索引移除后仍需可查的历史订单、成交明细和资产流水；删除活动索引不等于删除历史。

教程使用订单 ID 索引和用户 ID 到订单集合的索引，加快两种查询。更新两个索引时需要保证一致，且 `ConcurrentHashMap` 只保护单次容器操作，不能自动把多个索引和余额操作变成一个原子事务。

## 失败和恢复

- 稳定请求 ID 加唯一约束，避免客户端超时重试生成两笔订单；相同 ID 内容不同时拒绝。
- 明确“订单已创建”和“资产已冻结”的提交边界；崩溃后要能恢复或补偿，不能允许有订单但没有资产保障。
- 对成交、撤单和资产流水分别设计唯一业务标识；重放事件时防止重复扣款和重复解冻。
- 订单状态更新应校验旧状态、版本或事件顺序；失败时不能覆盖别人的已提交结果。
- 实际系统还要规定订单有效期、最小数量、精度、手续费、风控、自成交与撤单拒绝原因。

## 自测

1. 总量 5 已成交 2 后撤单，已成交、已撤销和剩余分别是多少？
2. 撤单和最后一笔成交同时发生，为何需要明确顺序？
3. 客户端下单超时后重新用新 ID 下单，可能出现什么问题？
4. 内存中有两个订单索引，更新其中一个后崩溃，恢复时如何避免不一致？
