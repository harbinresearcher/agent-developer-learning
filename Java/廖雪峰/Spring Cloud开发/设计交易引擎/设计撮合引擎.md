# 设计撮合引擎

> **重要程度：高**｜**手练：需要**
> **重点**：买卖盘顺序、价格优先与时间优先、部分成交、限价判断、订单簿更新。

## 什么叫撮合

买方提交愿意出的最高价，卖方提交愿意接受的最低价。当买价不低于卖价，订单满足价格条件，就可以按交易规则成交。成交数量取双方剩余数量中较小的那个；未成交完的部分仍需按规则留在订单簿或取消。

订单簿分别维护买盘与卖盘：买盘价格越高越优先，卖盘价格越低越优先；相同价格使用定序号决定先后。教程以定序号表达先后，不能仅靠各机器本地时间判断。成交价由交易规则决定；以下示例采用先在订单簿中的卖单价格。

例如卖盘依次为 `99×1`、`100×2`、`100×2`，其中两个 100 价位分别是序号 2 和 3。新买单限价 100、数量 4，先与 99 成交 1，再与序号 2 成交 2，最后与序号 3 成交 1。买单全部成交，序号 3 的卖单剩余 1。

## 手练：用 TreeMap 表示卖盘

将代码保存为 `MatchDemo.java`：

```java
import java.math.BigDecimal;
import java.util.Comparator;
import java.util.Map;
import java.util.TreeMap;
import java.util.logging.Logger;

public class MatchDemo {
    private static final Logger logger = Logger.getLogger(MatchDemo.class.getName());
    record Key(BigDecimal price, long sequence) {}
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：按价格和序号建立卖盘
         * 数据源：三笔固定的卖单，数量单位为 BTC
         * 操作：1) 价格低者优先 2) 同价时序号小者优先
         * ======================================================================== */
        logger.info("开始建立卖盘");
        // 1.1 键同时包含价格与序号，同价订单不会互相覆盖
        Comparator<Key> order = Comparator.comparing(Key::price).thenComparingLong(Key::sequence);
        TreeMap<Key, BigDecimal> sells = new TreeMap<>(order);
        sells.put(new Key(new BigDecimal("100"), 2), new BigDecimal("2"));
        sells.put(new Key(new BigDecimal("99"), 1), new BigDecimal("1"));
        sells.put(new Key(new BigDecimal("100"), 3), new BigDecimal("2"));
        logger.info("卖盘建立结束");
        /* ========================================================================
         * 步骤2：用限价买单逐笔撮合
         * 数据源：限价 100、数量 4 的买单和已有卖盘
         * 操作：1) 检查最优卖价 2) 更新剩余量并输出成交
         * ======================================================================== */
        logger.info("开始撮合");
        // 2.1 取最优卖单并按较小剩余量成交
        BigDecimal limit = new BigDecimal("100");
        BigDecimal remaining = new BigDecimal("4");
        while (remaining.signum() > 0 && !sells.isEmpty()) {
            Map.Entry<Key, BigDecimal> best = sells.firstEntry();
            if (best.getKey().price().compareTo(limit) > 0) break;
            BigDecimal matched = remaining.min(best.getValue());
            System.out.println("成交=" + best.getKey().price().toPlainString() + ",序号="
                    + best.getKey().sequence() + ",数量=" + matched.toPlainString());
            remaining = remaining.subtract(matched);
            BigDecimal left = best.getValue().subtract(matched);
            // 2.2 成交完删除，否则更新未成交数量
            if (left.signum() == 0) sells.remove(best.getKey());
            else sells.put(best.getKey(), left);
        }
        System.out.println("买单剩余=" + remaining.toPlainString());
        System.out.println("卖单剩余=" + sells.firstEntry().getValue().toPlainString());
        logger.info("撮合结束");
    }
}
```

```powershell
javac -encoding UTF-8 --release 17 MatchDemo.java
java '-Dfile.encoding=UTF-8' MatchDemo
```

输出中应包含：

```text
成交=99,序号=1,数量=1
成交=100,序号=2,数量=2
成交=100,序号=3,数量=1
买单剩余=0
卖单剩余=1
```

已在 JDK 17 编译并核对输出。`TreeMap.firstEntry()` 取排序后的最优卖单；`compareTo` 判断价格，`min` 取可成交数量。成交完删除该卖单，否则更新其剩余数量。

键由价格和序号组成。如果只把价格作为键，第二笔同价订单会覆盖第一笔。`TreeMap` 用比较器判断键是否相同：同价且同序号比较结果为 0，因此定序号必须在该订单簿中满足唯一性约束。撤单还需要从订单 ID 找到相应的订单簿键；示例未实现索引。

**边界**：示例只模拟一笔限价买单与固定卖盘的内存撮合，不含买盘、撤单、订单状态、资金冻结、清算、持久化或并发控制。输出成交不代表资产已经转移。

## 设计时的边界

- **价格与数量**：用 `BigDecimal` 的字符串构造、明确允许的小数位和舍入规则；用 `compareTo` 判断数值大小。检查数量和价格为正、符合最小变动单位。
- **数据结构**：本例 `TreeMap` 基本插入和删除操作通常是 `O(log N)`；真实系统还需考虑订单 ID 索引、多个价格档位和同价队列。性能要用真实负载测量。
- **订单状态**：部分成交时更新双方未成交量与状态；全部成交或撤销后从活动簿移除，但成交记录和订单历史仍需要持久化。
- **确定性**：重放必须使用相同输入顺序和撮合规则；不要在影响匹配顺序的逻辑里读取未记录的当前时间或随机数。
- **一致性**：撮合、订单状态和清算输出不能各写一半就当作成功。明确事务或事件日志边界，保证重放与幂等，并用资产流水对账。
- **异常交易**：自成交、订单有效期、撤单与成交竞争、精度、风控和费用均需明确业务规则。本示例没有覆盖。
