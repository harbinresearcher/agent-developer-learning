# 设计清算系统

> **重要程度：高**｜**手练：需要**
> **重点**：撮合和清算的区别；按成交价计算资产交换与价差退款；流水、幂等、原子性和对账。

## 撮合完成不等于资产已经交换

撮合给出一条成交明细：买卖双方、成交价格、数量和关联订单。清算根据这条明细改变资产状态：买家支付 USD 并获得 BTC，卖家交出 BTC 并获得 USD；同时记录流水并更新对应订单。

假设不收手续费，买家限价 100 USD/BTC，下单买 0.5 BTC，冻结 50 USD；卖家以 90 USD/BTC 卖出 0.2 BTC，且已冻结 0.2 BTC。教程采用挂单方价格成交，假设这笔成交价是 90：

1. 这 0.2 BTC 在买单限价下对应冻结额 `100 × 0.2 = 20 USD`。
2. 实际成交额 `90 × 0.2 = 18 USD` 转给卖家；差额 `20 - 18 = 2 USD` 解冻退回买家可用余额。
3. 卖家冻结的 0.2 BTC 转给买家；买单尚未成交的 0.3 BTC 仍需冻结 `100 × 0.3 = 30 USD`。

不能把整笔订单的冻结金额一次全退回，也不能按买入限价把全部 20 USD 支付给卖家。卖单作为 taker、其他成交价规则、手续费及舍入规则需要分别设计。

## 手练：核对成交金额

保存为 `ClearingDemo.java`，用 JDK 17 运行：

```java
import java.math.BigDecimal;
import java.util.logging.Logger;

public class ClearingDemo {
    private static final Logger logger = Logger.getLogger(ClearingDemo.class.getName());
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：计算一笔买单的成交和退款
         * 数据源：买价 100、成交价 90、成交量 0.2 BTC
         * 操作：1) 校验价格和数量 2) 计算实际金额与价差
         * ======================================================================== */
        logger.info("开始计算清算金额");
        // 1.1 用字符串创建精确十进制数
        BigDecimal buyLimit = new BigDecimal("100");
        BigDecimal tradePrice = new BigDecimal("90");
        BigDecimal quantity = new BigDecimal("0.2");
        if (quantity.signum() <= 0 || tradePrice.signum() <= 0
                || buyLimit.compareTo(tradePrice) < 0) {
            logger.info("清算参数无效");
            throw new IllegalArgumentException("invalid trade");
        }
        BigDecimal reservedForFill = buyLimit.multiply(quantity);
        BigDecimal cost = tradePrice.multiply(quantity);
        BigDecimal refund = reservedForFill.subtract(cost);
        System.out.println("本次占用冻结=" + reservedForFill.toPlainString());
        System.out.println("卖家应得USD=" + cost.toPlainString());
        System.out.println("买家价差退回=" + refund.toPlainString());
        logger.info("清算金额计算结束");
        /* ========================================================================
         * 步骤2：核对部分成交后的冻结余额
         * 数据源：原订单买入 0.5 BTC，成交 0.2 BTC
         * 操作：1) 扣除本次冻结额度 2) 核对剩余订单所需额度
         * ======================================================================== */
        logger.info("开始核对剩余冻结");
        // 2.1 本示例不含手续费、其他冻结或舍入
        BigDecimal originalFrozen = buyLimit.multiply(new BigDecimal("0.5"));
        BigDecimal remainingFrozen = originalFrozen.subtract(reservedForFill);
        System.out.println("未成交冻结=" + remainingFrozen.toPlainString());
        logger.info("剩余冻结核对结束");
    }
}
```

```powershell
javac -encoding UTF-8 --release 17 ClearingDemo.java
java '-Dfile.encoding=UTF-8' ClearingDemo
```

标准输出：

```text
本次占用冻结=20.0
卖家应得USD=18.0
买家价差退回=2.0
未成交冻结=30.0
```

已编译运行并核对输出。`20.0 = 18.0 + 2.0`；剩余 30.0 USD 对应未成交订单。本例只计算，不更新账户，不证明资金真的已清算。真实系统需要校验订单与成交状态、冻结余额、允许精度和费用。

## 真正的清算操作需要哪些记录

对每笔成交生成稳定的成交 ID，关联买单、卖单、数量和价格。资产变动至少包括：买家冻结 USD 减少、卖家可用 USD 增加、卖家冻结 BTC 减少、买家可用 BTC 增加；有价差时还要将买方多冻部分退回可用余额。每个资产按系统定义记录平衡的流水。

同一成交被重复消费时，必须保证资产变动只生效一次。常见做法是在同一个数据库事务里用成交 ID 的唯一约束与账户更新、流水写入一起提交。若状态跨存储系统，不能只靠本地事务声称原子，需设计可靠事件、幂等、对账与补偿。

## 失败与恢复

- 更新双方余额时中途失败：要么同一事务回滚全部，要么用明确的状态机和补偿处理；不能只记录“清算成功”。
- 清算完成但确认消息前崩溃：重投时检查成交 ID，返回已处理结果，避免重复扣款。
- 部分成交后撤单：只解冻尚未成交部分，已成交金额按成交记录结算。
- 对账：逐资产核对相关账户的变动总和，以及成交记录、订单数量、资产流水、余额和外部账单。系统内流水平衡不自动证明外部资产真实存在。
- 精度：`BigDecimal` 并不自动规定交易规则；系统仍需定义资产小数位、舍入时机、最小单位、上限以及手续费归属。

## 自测

1. 上例成交价改为 95，买家退款多少？（1 USD。）
2. 成交量改为 0.1 BTC，原订单总量不变，剩余冻结多少？（40 USD。）
3. 同一成交消息在清算成功后重复到达，如何避免重复转账？
4. 为什么 `BigDecimal` 正确计算出 18 USD，仍不足以证明清算可靠？
