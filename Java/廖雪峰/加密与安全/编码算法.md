# 编码算法

> **重要程度：高**｜**手练：需要**
> **重点**：Base64 可逆编码、字符集、URL 变体。

## 先理解：编码不是保密

Base64 将字节转换为便于文本传输的表示，接收方可以直接解码；它不需要密钥，也不提供保密性。它适合在必须使用文本的协议中表示二进制数据，不能用来保护密码或令牌。

## 完整例子

保存为 `Base64Demo.java`，编译运行；日志写到标准错误。

```java
import java.nio.charset.StandardCharsets;
import java.util.Base64;
import java.util.logging.Logger;
public class Base64Demo {
    private static final Logger logger = Logger.getLogger(Base64Demo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：编码和解码示例数据
         * ========================================================================
         * 数据源：固定的非敏感文本
         * 操作：
         * 1) 将 UTF-8 字节编码为 Base64
         * 2) 解码并按相同字符集还原
         */
        logger.info("开始转换数据");
        // 1.1 编码受控示例文本
        byte[] data = "Java".getBytes(StandardCharsets.UTF_8);
        String encoded = Base64.getEncoder().encodeToString(data);
        // 1.2 解码并检查内容
        byte[] decoded = Base64.getDecoder().decode(encoded);
        System.out.println("encoded=" + encoded);
        System.out.println("text=" + new String(decoded, StandardCharsets.UTF_8));
        logger.info("数据转换完成");
    }
}
```

标准输出：

```text
encoded=SmF2YQ==
text=Java
```

## 执行过程

`"Java"` 先按 UTF-8 变成字节，再由基本 Base64 编码器得到 `SmF2YQ==`。解码器恢复字节，使用相同 UTF-8 解码后得到 Java。末尾的 `=` 是常见填充符，不是加密密钥。

## 变体与错误

Java 提供基本、URL/文件名安全和 MIME 变体，字符集与换行规则不同；通信双方应约定同一变体及填充规则。非法 Base64 输入可能抛 `IllegalArgumentException`，外部数据需要限制大小并处理失败。

编码前后还有“文字与字节”的字符集转换；即使 Base64 解码成功，使用错误字符集也可能造成乱码。编码通常增加传输体积，并不会自动压缩或校验数据真实性。

## 工作中怎么用

按协议要求使用 `java.util.Base64`；不要依赖已移除的内部 `sun.misc` Base64 API。密码应使用合适的密码哈希方案，敏感信息传输应使用经过认证的安全协议；不要把 Base64 文本当作安全存储。

## 手练与答案

将输入改为 `"A"`：Base64 结果为 `QQ==`，解码后仍为 A。任何拿到结果的人都可以解码，因此它不能替代加密。
