# 哈希算法

> **重要程度：高**｜**手练：需要**
> **重点**：SHA-256 摘要、完整性边界、密码存储。

## 解决什么问题

密码学哈希把任意长度输入映射为固定长度摘要。SHA-256 的摘要是 256 位，可用于检测数据变化，但摘要不是加密，也不能从普通摘要单独证明来源可信。

## 完整例子

保存为 `HashDemo.java`，编译运行；日志写到标准错误。

```java
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.util.logging.Logger;
public class HashDemo {
    private static final Logger logger = Logger.getLogger(HashDemo.class.getName());
    public static void main(String[] args) throws Exception {
        /*
         * ========================================================================
         * 步骤1：计算示例数据的摘要
         * ========================================================================
         * 数据源：固定的非敏感文本
         * 操作：
         * 1) 使用 UTF-8 编码并计算 SHA-256
         * 2) 将摘要显示为十六进制
         */
        logger.info("开始计算摘要");
        // 1.1 计算固定输入的摘要
        byte[] digest = MessageDigest.getInstance("SHA-256")
                .digest("abc".getBytes(StandardCharsets.UTF_8));
        // 1.2 格式化摘要用于观察
        StringBuilder hex = new StringBuilder();
        for (byte value : digest) {
            hex.append(String.format("%02x", value & 0xff));
        }
        System.out.println("sha256=" + hex);
        logger.info("摘要计算完成");
    }
}
```

标准输出：

```text
sha256=ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
```

## 执行过程

`MessageDigest.getInstance("SHA-256")` 获取算法实现；`digest` 对 UTF-8 字节计算摘要。每个 byte 通过 `value & 0xff` 转为 0～255 的数，再以两位十六进制格式显示。相同字节输入和算法会产生相同摘要；不同文本的字节编码若不同，摘要也不同。

## 完整性和来源边界

如果可信渠道提供预期摘要，计算并比较可帮助检测内容变化；如果攻击者能同时替换文件和摘要，普通摘要无法证明文件来自谁。需要认证的场景应使用 HMAC 或数字签名等合适机制。哈希输出可能碰撞，不能从数学上断言不同输入绝不会有相同摘要。

不要用快速 SHA-256 或 MD5 单次哈希保存用户密码；密码需要专门的、带独立随机盐及合适成本的密码哈希方案。MD5、SHA-1 等旧算法不应用于需要现代碰撞抗性的安全设计。对象的 `hashCode()` 与密码学哈希用途不同，不能替代安全摘要。

## 工作中怎么用

校验大文件时分块调用 `update`，避免一次读入全部内容，并从可信渠道获得预期值。不要把敏感明文或可用于离线猜测的摘要随意写入日志；按协议定义字节编码和算法。

## 手练与答案

相同 UTF-8 字节 `abc` 的 SHA-256 应得到示例结果；把输入改为 `abd`，摘要不同。若攻击者同时修改文件和未受保护的摘要，仅比较二者仍不能判断来源是否可信。
