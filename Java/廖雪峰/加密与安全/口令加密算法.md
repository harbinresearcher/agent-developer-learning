# 口令加密算法

> **重要程度：高**｜**手练：需要**
> **重点**：密码哈希与口令加密区别、盐、成本和升级。

## 先分清两个需求

**密码存储验证**希望服务器不保存明文密码；应使用成熟的密码哈希方案，并保存其算法与参数等信息供验证。**口令加密**则需要从口令派生加密密钥，再用合适的认证加密方案保护数据；只做密钥派生并没有完成加密。

## 完整例子：观察 PBKDF2

保存为 `PasswordKdfDemo.java`，编译运行；日志写到标准错误。示例展示 PBKDF2 API 的行为，固定盐和教学口令仅为可重复实验，不能直接作为生产密码存储实现。

```java
import java.security.MessageDigest;
import java.util.Arrays;
import javax.crypto.SecretKeyFactory;
import javax.crypto.spec.PBEKeySpec;
import java.util.logging.Logger;
public class PasswordKdfDemo {
    private static final Logger logger = Logger.getLogger(PasswordKdfDemo.class.getName());
    public static void main(String[] args) throws Exception {
        /*
         * ========================================================================
         * 步骤1：比较密码派生结果
         * ========================================================================
         * 数据源：公开的教学口令和固定测试盐
         * 操作：
         * 1) 使用相同参数派生两次
         * 2) 比较正确和错误口令的结果
         */
        logger.info("开始验证教学口令");
        // 1.1 准备测试数据；固定盐只用于演示
        byte[] salt = "0123456789abcdef".getBytes(java.nio.charset.StandardCharsets.UTF_8);
        char[] password = "demo-password".toCharArray();
        char[] wrong = "wrong-password".toCharArray();
        try {
            // 1.2 派生并比较字节，不输出口令或派生值
            byte[] stored = derive(password, salt);
            byte[] candidate = derive(password, salt);
            byte[] incorrect = derive(wrong, salt);
            System.out.println("match=" + MessageDigest.isEqual(stored, candidate));
            System.out.println("wrong=" + MessageDigest.isEqual(stored, incorrect));
        } finally {
            Arrays.fill(password, '\0');
            Arrays.fill(wrong, '\0');
        }
        logger.info("教学口令验证完成");
    }
    static byte[] derive(char[] password, byte[] salt) throws Exception {
        /*
         * ========================================================================
         * 步骤1：派生测试密钥
         * ========================================================================
         * 数据源：调用者给出的教学口令和盐
         * 操作：
         * 1) 配置 PBKDF2 参数
         * 2) 派生结果并清理参数副本
         */
        logger.info("开始派生测试值");
        // 1.1 设置成本和输出长度
        PBEKeySpec spec = new PBEKeySpec(password, salt, 600_000, 256);
        try {
            // 1.2 计算派生值
            byte[] result = SecretKeyFactory.getInstance("PBKDF2WithHmacSHA256")
                    .generateSecret(spec).getEncoded();
            logger.info("测试值派生完成");
            return result;
        } finally {
            spec.clearPassword();
        }
    }
}
```

标准输出：

```text
match=true
wrong=false
```

## 执行过程

`PBEKeySpec` 接收口令、盐、迭代次数 600000 和输出长度 256 位；`SecretKeyFactory` 使用 `PBKDF2WithHmacSHA256` 派生字节。相同口令、盐与参数得到相同派生值，因此 match 为 true；换成错误口令得到不同结果，所以 wrong 为 false。`MessageDigest.isEqual` 比较字节；示例不打印口令或派生值。

`spec.clearPassword()` 清理 PBEKeySpec 持有的口令副本；finally 清理示例 char 数组。但字符串字面量及运行时、库内部可能有其他副本，清理数组不保证所有副本都被抹除。

## 密码存储的工作做法

优先使用成熟库或框架提供的密码哈希与验证 API。OWASP 当前建议优先考虑 Argon2id；特定合规约束下可按其建议选择 PBKDF2-HMAC-SHA-256 和合适工作因子。参数需要结合部署硬件、延迟、并发容量与现行安全要求评估；算法名称本身不证明整个运行环境符合 FIPS 验证要求。

每个密码需使用独立的安全随机盐；存储算法标识、参数、盐和哈希，以便验证与未来升级。盐通常不需要保密，pepper 若使用则需与数据库分开安全管理。登录还需要限流、凭据泄露后的重置与迁移策略。绝不能把示例固定盐、测试口令或日志照搬到生产。

## 手练与答案

使用相同盐、口令和参数再次派生：结果相同；换盐或口令通常得到不同结果。固定盐不能满足每个密码独立随机盐的要求。派生字节本身不会自动加密文件。
