# 签名算法

> **重要程度：中**｜**手练：建议**
> **重点**：私钥签名、公钥验证、可信公钥与篡改。

## 解决什么问题

数字签名通常用私钥签署消息，由相应公钥验证。验证成功表明签名与消息、该公钥相匹配，可用于完整性和签名者身份认证；但公钥必须先通过可信方式绑定到预期身份。签名不对消息保密。

## 完整例子

保存为 `SignatureDemo.java`，编译运行；日志写到标准错误。示例使用临时生成的测试密钥。

```java
import java.nio.charset.StandardCharsets;
import java.security.KeyPair;
import java.security.KeyPairGenerator;
import java.security.Signature;
import java.util.logging.Logger;
public class SignatureDemo {
    private static final Logger logger = Logger.getLogger(SignatureDemo.class.getName());
    public static void main(String[] args) throws Exception {
        /*
         * ========================================================================
         * 步骤1：签名并验证消息
         * ========================================================================
         * 数据源：临时 RSA 密钥对和非敏感消息
         * 操作：
         * 1) 使用私钥签名
         * 2) 使用公钥验证原文和修改后的文本
         */
        logger.info("开始处理签名示例");
        // 1.1 生成临时密钥并对消息签名
        KeyPairGenerator generator = KeyPairGenerator.getInstance("RSA");
        generator.initialize(2048);
        KeyPair pair = generator.generateKeyPair();
        byte[] message = "order=1".getBytes(StandardCharsets.UTF_8);
        Signature signer = Signature.getInstance("SHA256withRSA");
        signer.initSign(pair.getPrivate());
        signer.update(message);
        byte[] signature = signer.sign();
        // 1.2 验证原始消息与修改后的消息
        Signature verifier = Signature.getInstance("SHA256withRSA");
        verifier.initVerify(pair.getPublic());
        verifier.update(message);
        System.out.println("original=" + verifier.verify(signature));
        verifier.initVerify(pair.getPublic());
        verifier.update("order=2".getBytes(StandardCharsets.UTF_8));
        System.out.println("modified=" + verifier.verify(signature));
        logger.info("签名示例完成");
    }
}
```

标准输出：

```text
original=true
modified=false
```

## 执行过程

`Signature.getInstance("SHA256withRSA")` 创建签名对象，`initSign` 使用私钥，`update` 输入消息字节，`sign` 产生签名。验证方用公钥初始化另一个对象，输入同样的字节后验证为 true；重新初始化并换成 `order=2`，使用原签名验证为 false。

示例验证算法调用，不建立真实身份信任。若攻击者能替换消息、签名和用于验证的公钥，验证成功也不能说明来自预期的人。真实系统需要证书链、可信密钥分发或其他身份绑定，并保护私钥。

## 工作中怎么用

双方应约定签名算法、参数、数据编码和签名的准确字节；序列化字段顺序或换行变化都可能使验证失败。`SHA256withRSA` 是示例使用的 RSA 签名方案；项目是否使用 RSA-PSS、ECDSA 或其他算法，要结合协议、平台兼容和现行安全要求，不要自行发明协议。

签名只保护被签名内容的完整性和认证，不自动保密或防重放；必要时需结合加密、时效、nonce 和业务去重。不要把私钥或敏感消息写入日志。

## 手练与答案

使用相同消息与对应公钥验证，结果应为 true；修改消息后验证原签名为 false。Base64 编码签名只是传输表示，不会让签名更安全或隐藏消息。
