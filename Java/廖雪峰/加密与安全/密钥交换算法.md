# 密钥交换算法

> **重要程度：中**｜**手练：建议**
> **重点**：ECDH 共享秘密、身份认证和 KDF 边界。

## 解决什么问题

Diffie-Hellman 类密钥协商让双方结合各自私钥与对方公钥计算共享秘密，不需要直接传输该秘密。示例使用椭圆曲线 ECDH 展示同类协商思想；它不是完整的安全通信协议。

## 完整例子

保存为 `KeyAgreementDemo.java`，编译运行；日志写到标准错误。密钥每次临时生成，示例不输出共享秘密。

```java
import java.security.KeyPair;
import java.security.KeyPairGenerator;
import java.security.MessageDigest;
import java.security.spec.ECGenParameterSpec;
import javax.crypto.KeyAgreement;
import java.util.logging.Logger;
public class KeyAgreementDemo {
    private static final Logger logger = Logger.getLogger(KeyAgreementDemo.class.getName());
    public static void main(String[] args) throws Exception {
        /*
         * ========================================================================
         * 步骤1：协商教学用共享秘密
         * ========================================================================
         * 数据源：双方临时生成的椭圆曲线密钥对
         * 操作：
         * 1) 交换公钥并各自计算共享秘密
         * 2) 比较双方结果
         */
        logger.info("开始密钥协商示例");
        // 1.1 在相同曲线上生成双方密钥对
        KeyPairGenerator generator = KeyPairGenerator.getInstance("EC");
        generator.initialize(new ECGenParameterSpec("secp256r1"));
        KeyPair alice = generator.generateKeyPair();
        KeyPair bob = generator.generateKeyPair();
        // 1.2 使用己方私钥和对方公钥各自计算
        KeyAgreement left = KeyAgreement.getInstance("ECDH");
        left.init(alice.getPrivate());
        left.doPhase(bob.getPublic(), true);
        byte[] leftSecret = left.generateSecret();
        KeyAgreement right = KeyAgreement.getInstance("ECDH");
        right.init(bob.getPrivate());
        right.doPhase(alice.getPublic(), true);
        byte[] rightSecret = right.generateSecret();
        System.out.println("same=" + MessageDigest.isEqual(leftSecret, rightSecret));
        logger.info("密钥协商示例完成");
    }
}
```

标准输出：

```text
same=true
```

## 执行过程

双方使用相同曲线生成各自密钥对。Alice 用自己的私钥初始化 KeyAgreement，并输入 Bob 的公钥；Bob 做相反操作。正确执行后，两边 `generateSecret()` 得到相同的共享秘密，所以示例输出 true。

## 安全边界

ECDH 本身不验证公钥来自谁；如果攻击者能替换交换中的公钥，可能实施中间人攻击。真实协议需要认证对方身份、验证密钥材料、协商算法和保护握手记录。不能把本例输出 true 当作双方身份已被验证。

共享秘密通常需要通过经过审查的 KDF 和协议上下文派生用途明确的密钥，不应直接截取字节当作 AES 密钥；还需设计密钥生命周期、前向保密和错误处理。曲线和算法选择要考虑协议与当前安全策略。

## 工作中怎么用

优先使用经过审查的 TLS 等标准协议，而不是自行设计密钥交换报文。示例没有网络通信、证书验证、KDF 或重放防护；不要输出私钥或共享秘密。

## 手练与答案

双方使用不兼容的参数或无效公钥，协商可能失败；双方必须按协议使用匹配的算法参数。把其中一方换成新的随机密钥对，原来的共享秘密不再对应新的参与者。
