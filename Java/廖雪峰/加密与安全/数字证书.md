# 数字证书

> **重要程度：高**｜**手练：建议**
> **重点**：证书包含的公钥和身份信息、签名、信任链、主机名校验。

## 解决什么问题

公钥加密和签名需要先知道公钥属于谁。X.509 证书把公钥与主体等信息放在一起，并由签发者签名；验证方还要依据可信根、证书链和具体协议检查身份。**能解析证书或验证一个签名，不等于证书被信任。**

## 完整例子：读取本地自签名测试证书

先在全新的空练习目录创建测试证书。下面的 `test-only` 是公开的教学口令，不可用于真实密钥；命令会在当前目录创建包含私钥的 `demo.p12` 和公开证书 `demo-cert.pem`，不要在已有用户数据的目录运行，也不要导入系统信任库。

```text
keytool -genkeypair -alias demo -keystore demo.p12 -storetype PKCS12 -storepass test-only -keypass test-only -dname "CN=notes.invalid" -keyalg RSA -keysize 2048 -validity 30 -noprompt
keytool -exportcert -rfc -alias demo -keystore demo.p12 -storepass test-only -file demo-cert.pem
```

保存以下代码为 `CertificateDemo.java`，执行 `javac -encoding UTF-8 CertificateDemo.java`，再执行 `java CertificateDemo demo-cert.pem`。日志写到标准错误。

```java
import java.io.InputStream;
import java.nio.file.Files;
import java.nio.file.Path;
import java.security.cert.CertificateFactory;
import java.security.cert.X509Certificate;
import java.util.logging.Logger;
public class CertificateDemo {
    private static final Logger logger = Logger.getLogger(CertificateDemo.class.getName());
    public static void main(String[] args) throws Exception {
        /*
         * ========================================================================
         * 步骤1：读取本地演示证书
         * ========================================================================
         * 数据源：命令行指定的公开证书文件
         * 操作：
         * 1) 解析 X.509 证书并读取主体
         * 2) 使用证书公钥验证其自签名
         */
        logger.info("开始读取演示证书");
        // 1.1 校验参数并打开证书文件
        if (args.length != 1) throw new IllegalArgumentException("需要证书文件路径");
        try (InputStream in = Files.newInputStream(Path.of(args[0]))) {
            X509Certificate cert = (X509Certificate) CertificateFactory.getInstance("X.509")
                    .generateCertificate(in);
            // 1.2 验证示例自签名并输出公开信息
            cert.verify(cert.getPublicKey());
            System.out.println("type=" + cert.getType());
            System.out.println("subject=" + cert.getSubjectX500Principal().getName());
            System.out.println("selfSignatureValid=true");
        }
        logger.info("演示证书读取完成");
    }
}
```

标准输出：

```text
type=X.509
subject=CN=notes.invalid
selfSignatureValid=true
```

示例已使用 `keytool` 生成临时证书，并用 Java 11 编译运行。练习结束后仅清理这个练习目录自己生成的文件；测试私钥和公开口令绝不能用于正式环境。

## 执行过程

`CertificateFactory` 解析指定文件为 X.509 证书；`getSubjectX500Principal` 读取主体。示例证书是由本地 keytool 生成的自签名证书，`cert.verify(cert.getPublicKey())` 用证书自身公钥验证其签名；成功只说明这份签名与该公钥匹配。

示例**没有**验证有效期、吊销状态、证书链、可信根、域名或使用用途。自行生成的自签名证书即使上述签名验证成功，也不能因此认定其身份可信。示例不建立 HTTPS 连接，也没有修改 JVM 信任库。

## 工作中怎么用

TLS 客户端通常依赖经过正确配置的信任管理器验证证书链，并核对访问主机名与证书允许的身份；有效期、算法、证书用途与吊销策略也需符合组织和协议要求。具体检查取决于客户端与部署配置，不能以“证书能解析”替代完整验证。

不要为解决证书错误而全局信任所有证书或禁用主机名校验；应定位域名、证书链、信任锚、时钟与部署配置等原因。私钥应安全保存并轮换，公开证书并不等同于私钥。

## 手练与答案

1. 把证书文件路径改成不存在的路径：读取时抛 I/O 异常；这不是证书验证通过。
2. 本例显示自签名验证成功，是否代表浏览器会信任它？不代表；还需满足信任链、域名、有效期和客户端策略等要求。
