# 非对称加密算法

> **重要程度：中**｜**手练：建议**
> **重点**：公钥加密、私钥解密、OAEP 参数与数据长度。

## 解决什么问题

非对称加密使用一对相关密钥。典型 RSA 加密中，接收方公开公钥供发送方加密，接收方使用私钥解密；私钥需要保护。公开密钥是否确属预期接收方，是证书或其他可信渠道需要解决的问题。

## 完整例子

保存为 `RsaOaepDemo.java`，编译运行；日志写到标准错误。示例生成一次性密钥对，只加密短小的非敏感文本。

```java
import java.nio.charset.StandardCharsets;
import java.security.KeyPair;
import java.security.KeyPairGenerator;
import java.security.spec.MGF1ParameterSpec;
import java.util.Arrays;
import javax.crypto.Cipher;
import javax.crypto.spec.OAEPParameterSpec;
import javax.crypto.spec.PSource;
import java.util.logging.Logger;
public class RsaOaepDemo {
    private static final Logger logger = Logger.getLogger(RsaOaepDemo.class.getName());
    public static void main(String[] args) throws Exception {
        /*
         * ========================================================================
         * 步骤1：加密并解密短消息
         * ========================================================================
         * 数据源：临时密钥对和非敏感短文本
         * 操作：
         * 1) 用公钥和明确的 OAEP 参数加密
         * 2) 用私钥解密并比较原始字节
         */
        logger.info("开始处理非对称加密示例");
        // 1.1 生成临时 RSA 密钥对和 OAEP 参数
        KeyPairGenerator generator = KeyPairGenerator.getInstance("RSA");
        generator.initialize(2048);
        KeyPair pair = generator.generateKeyPair();
        OAEPParameterSpec parameters = new OAEPParameterSpec(
                "SHA-256", "MGF1", MGF1ParameterSpec.SHA256, PSource.PSpecified.DEFAULT);
        byte[] plain = "hello".getBytes(StandardCharsets.UTF_8);
        // 1.2 公钥加密，私钥解密
        Cipher cipher = Cipher.getInstance("RSA/ECB/OAEPPadding");
        cipher.init(Cipher.ENCRYPT_MODE, pair.getPublic(), parameters);
        byte[] encrypted = cipher.doFinal(plain);
        cipher.init(Cipher.DECRYPT_MODE, pair.getPrivate(), parameters);
        byte[] restored = cipher.doFinal(encrypted);
        System.out.println("roundTrip=" + Arrays.equals(plain, restored));
        logger.info("非对称加密示例完成");
    }
}
```

标准输出：

```text
roundTrip=true
```

## 执行过程

生成 2048 位 RSA 密钥对；显式指定 OAEP 使用 SHA-256 和 MGF1-SHA-256。公钥加密后，私钥用相同参数解密，比较恢复的字节，因此输出 true。OAEP 使用随机性，密文每次可能不同，不应依赖固定密文字节。

## 参数与边界

RSA 加密对明文长度有严格上限，不适合直接加密大文件。真实系统通常使用成熟的混合加密协议：非对称机制保护对称密钥或建立会话密钥，再用认证加密处理数据；不能只拼接示例就宣称协议安全。

OAEP 的摘要、MGF 摘要和标签必须与通信对方一致；不同 provider 的默认参数可能不同，所以示例明确传入 `OAEPParameterSpec`。这里 transformation 名称中的 `ECB` 是 JCA 对 RSA 的命名形式，不表示对 RSA 使用了 AES 的 ECB 分组模式。

## 工作中怎么用

密钥管理、身份验证、协议版本、错误处理和轮换是方案的一部分。私钥不应放在源码或日志里；加密本身不证明发送方身份，也不等于数字签名。优先使用经过审查的标准协议和库，并按组织策略选择算法和密钥长度。

## 手练与答案

用错误私钥或不匹配的 OAEP 参数解密：解密应失败，而不是恢复原文。把明文换成大型文件：可能超出 RSA 单次输入上限，应使用合适的混合加密方案。
