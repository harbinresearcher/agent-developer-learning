# 对称加密算法

> **重要程度：高**｜**手练：需要**
> **重点**：认证加密、随机 nonce、密钥与篡改检测。

## 解决什么问题

对称加密使用共享密钥加密和解密。实际应用通常还需认证完整性；AES-GCM 是一种认证加密模式，解密时会检查认证标签，篡改密文会导致认证失败。加密本身不解决密钥分发、权限或重放问题。

## 完整例子

保存为 `AesGcmDemo.java`，用 Java 11 或更高版本编译运行；日志写到标准错误。例子每次生成临时密钥和随机 nonce，不保存真实数据。

```java
import java.nio.charset.StandardCharsets;
import java.security.SecureRandom;
import javax.crypto.AEADBadTagException;
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.GCMParameterSpec;
import java.util.Arrays;
import java.util.logging.Logger;
public class AesGcmDemo {
    private static final Logger logger = Logger.getLogger(AesGcmDemo.class.getName());
    public static void main(String[] args) throws Exception {
        /*
         * ========================================================================
         * 步骤1：加密并验证示例消息
         * ========================================================================
         * 数据源：临时生成的密钥、随机 nonce 和非敏感示例文本
         * 操作：
         * 1) 使用 AES-GCM 加密和解密
         * 2) 篡改密文并确认认证失败
         */
        logger.info("开始处理加密示例");
        // 1.1 生成临时密钥与随机 96 位 nonce
        KeyGenerator generator = KeyGenerator.getInstance("AES");
        generator.init(128);
        SecretKey key = generator.generateKey();
        byte[] nonce = new byte[12];
        new SecureRandom().nextBytes(nonce);
        byte[] plain = "hello".getBytes(StandardCharsets.UTF_8);
        // 1.2 加密并还原示例数据
        Cipher encrypt = Cipher.getInstance("AES/GCM/NoPadding");
        encrypt.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, nonce));
        byte[] cipherText = encrypt.doFinal(plain);
        Cipher decrypt = Cipher.getInstance("AES/GCM/NoPadding");
        decrypt.init(Cipher.DECRYPT_MODE, key, new GCMParameterSpec(128, nonce));
        byte[] restored = decrypt.doFinal(cipherText);
        System.out.println("roundTrip=" + Arrays.equals(plain, restored));
        // 1.3 篡改密文并确认认证失败
        byte[] altered = cipherText.clone();
        altered[0] ^= 1;
        Cipher verify = Cipher.getInstance("AES/GCM/NoPadding");
        verify.init(Cipher.DECRYPT_MODE, key, new GCMParameterSpec(128, nonce));
        try {
            verify.doFinal(altered);
            System.out.println("tamperRejected=false");
        } catch (AEADBadTagException ex) {
            System.out.println("tamperRejected=true");
        }
        logger.info("加密示例处理完成");
    }
}
```

标准输出：

```text
roundTrip=true
tamperRejected=true
```

## 执行过程

`KeyGenerator` 生成临时 AES 密钥，`SecureRandom` 生成 12 字节 nonce；`AES/GCM/NoPadding` 加密非敏感文本。解密时使用相同密钥和 nonce，得到原始字节，roundTrip 为 true。示例复制密文并翻转一个字节，再解密时认证标签不匹配，抛 `AEADBadTagException`，所以 tamperRejected 为 true。

## nonce、密钥与数据格式

对同一个 GCM 密钥，**绝不能重复使用 nonce**；随机生成也有碰撞概率，实际系统要设计唯一性、调用次数限制、密钥轮换以及并发/重启后的管理策略。nonce 通常不是秘密，但必须与密文和标签按协议保存或传递；不能只保存密文而丢失解密必需信息。

密钥必须独立安全生成、存放和轮换，不放在源码或日志。若需认证但不加密的关联字段，可按协议使用 AAD，双方须提供完全一致的字节。认证失败时应拒绝结果，不要继续使用未经验证的明文，也不要泄露多余的失败细节。

## 工作中怎么用

优先使用成熟协议和库，不自行拼装加密系统。示例没有处理密钥管理、版本化数据格式、AAD、密钥轮换、跨服务兼容或防重放，不能直接用于生产。不要使用 ECB 来保护一般业务数据；算法、密钥长度和模式应按现行标准与项目环境审核。

## 手练与答案

改动密文的任一位或使用错误密钥，认证通常失败；本例会进入认证失败分支。随机 nonce 使每次密文可能不同，所以示例只断言往返和篡改检测，不比较固定密文字节。
