# 加载配置文件

> **重要程度：高**｜**手练：需要**
> **重点**：类型绑定、配置优先级、缺失值与启动校验。

## 先理解配置来源

应用的服务地址、超时等不应写死在业务逻辑中。Spring Boot 可从属性文件、环境变量、命令行等来源读取配置；多个来源定义相同属性时按规定优先级合并。`application.properties` 通常放在 `src/main/resources`，打包后随应用进入类路径。

例子用 `@ConfigurationProperties` 将 `client.*` 绑定到一个类型；`@EnableConfigurationProperties` 注册它。配置名 `client.timeout-seconds` 绑定到 `timeoutSeconds`。构造器验证地址非空、秒数大于零，非法配置导致启动失败；地址只是测试字符串，程序不会发起请求。


## 完整例子

使用 JDK 17、Maven 与 Spring Boot 4.1.2。先确认 `java -version` 和 `mvn -v` 均使用 JDK 17 或以上。在新目录保存 `pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <parent>
        <groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-parent</artifactId>
        <version>4.1.2</version><relativePath/>
    </parent>
    <groupId>learn.example</groupId><artifactId>config-file-demo</artifactId><version>1.0</version>
    <properties><java.version>17</java.version></properties>
    <dependencies>
        <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter</artifactId></dependency>
    </dependencies>
    <build><plugins><plugin><groupId>org.springframework.boot</groupId><artifactId>spring-boot-maven-plugin</artifactId></plugin></plugins></build>
</project>
```

保存 `src/main/java/learn/config/ConfigFileDemo.java`：

```java
package learn.config;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.ConfigurableApplicationContext;
@SpringBootApplication
@EnableConfigurationProperties(ConfigFileDemo.ClientSettings.class)
public class ConfigFileDemo {
    private static final Logger logger = LoggerFactory.getLogger(ConfigFileDemo.class);
    @ConfigurationProperties(prefix = "client")
    record ClientSettings(String endpoint, int timeoutSeconds) {
        ClientSettings {
            if (endpoint == null || endpoint.isBlank() || timeoutSeconds <= 0)
                throw new IllegalArgumentException("客户端配置无效");
        }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：加载并检查客户端配置
         * 数据源：application.properties 和启动参数
         * 操作：1) 绑定配置对象 2) 输出校验后的结果
         * ======================================================================== */
        logger.info("开始加载配置");
        try (ConfigurableApplicationContext context = SpringApplication.run(ConfigFileDemo.class, args)) {
            // 1.1 从容器获取已绑定的配置对象
            ClientSettings settings = context.getBean(ClientSettings.class);
            // 1.2 展示非敏感示例值，不请求外部地址
            System.out.println("配置结果=" + settings.endpoint() + "," + settings.timeoutSeconds());
        }
        logger.info("配置加载结束");
    }
}
```

创建 `src/main/resources/application.properties`：

```properties
client.endpoint=https://example.test
client.timeout-seconds=5
```

在项目根目录的 PowerShell 中运行：

```powershell
mvn package
java -jar target/config-file-demo-1.0.jar
java -jar target/config-file-demo-1.0.jar --client.timeout-seconds=9
```

下面列出每次运行的关键输出；其他启动日志省略：

```text
配置结果=https://example.test,5
配置结果=https://example.test,9
```

## 看懂覆盖与类型转换

默认读到文件中的 5 秒；传入 `--client.timeout-seconds=9` 后，命令行值覆盖示例文件值。将它设置成非数字会发生绑定转换失败；设置成 0 会被构造器校验拒绝。不同配置来源的完整优先级应查对应 Boot 版本文档，不能只记某一个例子。

生产中可使用类型安全的配置类集中管理相关参数；需要更丰富校验时可配合对应版本的 Bean Validation 和 `@Validated`。敏感凭据不应提交到仓库或打印到日志；连接地址、超时单位和默认值需有明确约定。

## 动手与自查

1. 改成 `--client.timeout-seconds=0`，确认启动失败；再传入非数字，比较错误原因。
2. 删除 `client.endpoint`，观察必需值校验。
3. 为什么运行时从命令行覆盖成功，不表示所有配置源都有相同优先级？
