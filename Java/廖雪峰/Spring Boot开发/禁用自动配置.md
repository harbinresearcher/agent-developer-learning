# 禁用自动配置

> **重要程度：中**｜**手练：需要**
> **重点**：条件评估、精确排除与依赖缺失。

## 自动配置是什么

Boot 根据依赖、配置和已有 Bean 等条件，尝试提供适合当前应用的默认组件。自动配置不是强制创建所有组件；具体条件和类名随版本变化。本例使用 Boot 4.1.2、JDBC starter 与 H2：默认条件满足时得到一个内存数据源。


## 完整例子

使用 JDK 17、Maven 与 Spring Boot 4.1.2。先确认 `java -version` 和 `mvn -v` 均使用 JDK 17 或以上。在新目录保存 `pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <parent>
        <groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-parent</artifactId>
        <version>4.1.2</version><relativePath/>
    </parent>
    <groupId>learn.example</groupId><artifactId>auto-config-demo</artifactId><version>1.0</version>
    <properties><java.version>17</java.version></properties>
    <dependencies>
        <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-jdbc</artifactId></dependency>
        <dependency><groupId>com.h2database</groupId><artifactId>h2</artifactId><scope>runtime</scope></dependency>
    </dependencies>
    <build><plugins><plugin><groupId>org.springframework.boot</groupId><artifactId>spring-boot-maven-plugin</artifactId></plugin></plugins></build>
</project>
```

保存 `src/main/java/learn/config/AutoConfigDemo.java`：

```java
package learn.config;
import javax.sql.DataSource;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.ConfigurableApplicationContext;
@SpringBootApplication
public class AutoConfigDemo {
    private static final Logger logger = LoggerFactory.getLogger(AutoConfigDemo.class);
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：检查数据源自动配置
         * 数据源：当前应用的自动配置和启动参数
         * 操作：1) 创建容器 2) 统计数据源 Bean
         * ======================================================================== */
        logger.info("开始检查数据源");
        try (ConfigurableApplicationContext context = SpringApplication.run(AutoConfigDemo.class, args)) {
            // 1.1 查询容器中的数据源定义
            int count = context.getBeanNamesForType(DataSource.class).length;
            // 1.2 显示当前条件下的数量
            System.out.println("数据源数量=" + count);
        }
        logger.info("数据源检查结束");
    }
}
```

在项目根目录的 PowerShell 中运行：

```powershell
mvn package
java -jar target/auto-config-demo-1.0.jar
java -jar target/auto-config-demo-1.0.jar --spring.autoconfigure.exclude=org.springframework.boot.jdbc.autoconfigure.DataSourceAutoConfiguration
```

下面列出每次运行的关键输出；其他启动日志省略：

```text
数据源数量=1
数据源数量=0
```

## 如何精确排除

第二次运行通过 `spring.autoconfigure.exclude` 指定 Boot 4 的 `DataSourceAutoConfiguration`，该自动配置不再提供数据源，示例统计结果从 1 变为 0。这不删除依赖，也不等于禁用所有自动配置。也可在启动类上使用 `@SpringBootApplication` 的 `exclude` 或 `excludeName` 属性；类名以当前版本为准，旧版包名可能不同。

## 工作中先排查再调整

先看依赖树、配置、已有 Bean 和条件评估报告；启动参数 `--debug` 可输出条件报告。已有自定义 Bean 时某些自动配置会让步，是否如此要看具体条件。排除数据源后，依赖它的仓储或事务管理器可能缺失并导致启动失败；生产项目应提供替代实现并做集成测试。

不要为了消除报错盲目批量排除配置。示例 H2 是练习用内存数据库，不能用于推断真实数据库连接或生产行为。

## 动手与自查

1. 对比默认和排除后的数据源数量。
2. 用 `--debug` 查条件报告，找出数据源相关配置的匹配结果。
3. 在排除数据源后添加强制依赖 `DataSource` 的 Bean，观察缺失依赖错误。
