# 集成第三方组件

> **重要程度：高**｜**手练：需要**
> **重点**：依赖、配置、资源生命周期、超时和失败处理。

## 集成从哪里开始

Spring Boot 的 starter 与自动配置可以减少连接组件时的样板，但仍需核对 Boot 和组件版本、运行环境、认证、超时和资源生命周期。自动配置是否生效取决于依赖、属性和已有 Bean 等条件。

下面用隔离 Redis 实例练习字符串缓存。程序只操作本次生成的唯一测试键，运行前需要自行准备测试服务。

## 完整例子

使用 JDK 17、Maven 和 Spring Boot 4.1.2。新建目录并保存 `pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <parent>
        <groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-parent</artifactId>
        <version>4.1.2</version><relativePath/>
    </parent>
    <groupId>learn.example</groupId><artifactId>redis-demo</artifactId><version>1.0</version>
    <properties><java.version>17</java.version></properties>
    <dependencies>
        <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter</artifactId></dependency>
        <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-data-redis</artifactId></dependency>
    </dependencies>
    <build><plugins><plugin><groupId>org.springframework.boot</groupId><artifactId>spring-boot-maven-plugin</artifactId></plugin></plugins></build>
</project>
```

保存 `src/main/java/learn/redis/RedisDemo.java`：

```java
package learn.redis;
import java.time.Duration;
import java.util.UUID;
import java.util.concurrent.TimeUnit;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.ConfigurableApplicationContext;
import org.springframework.data.redis.core.StringRedisTemplate;
@SpringBootApplication
public class RedisDemo {
    private static final Logger logger = LoggerFactory.getLogger(RedisDemo.class);
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：写入并读取测试缓存
         * 数据源：显式配置的隔离 Redis 实例
         * 操作：1) 写入带过期时间的唯一键 2) 查询并清理该键
         * ======================================================================== */
        logger.info("开始 Redis 示例");
        try (ConfigurableApplicationContext context = SpringApplication.run(RedisDemo.class, args)) {
            StringRedisTemplate redis = context.getBean(StringRedisTemplate.class);
            // 1.1 使用唯一键，避免与其他练习相互覆盖
            String key = "learn:demo:" + UUID.randomUUID();
            try {
                redis.opsForValue().set(key, "Alice", Duration.ofSeconds(60));
                // 1.2 读取值并检查过期时间
                System.out.println("值=" + redis.opsForValue().get(key));
                Long ttl = redis.getExpire(key, TimeUnit.SECONDS);
                System.out.println("TTL有效=" + (ttl != null && ttl > 0));
            } finally {
                // 1.3 只删除本次生成的测试键
                redis.delete(key);
            }
        }
        logger.info("Redis 示例完成");
    }
}
```

先准备仅供测试、监听 `127.0.0.1:16379` 的 Redis 实例。确认 `java -version` 和 `mvn -v` 使用 JDK 17 或以上，在工程目录运行：

```powershell
mvn package
java -jar target/redis-demo-1.0.jar --spring.data.redis.host=127.0.0.1 --spring.data.redis.port=16379
```

日志中应看到：

```text
值=Alice
TTL有效=true
```

## 结合例子理解

`StringRedisTemplate` 通过连接工厂访问 Redis；示例写入值和 60 秒过期时间，读取结果与 TTL 后删除本次测试键。TTL 有效只说明该键设置了过期时间，不证明缓存与数据库强一致。

## 工作中怎么用

外部地址、凭据、TLS 和超时按环境配置，敏感值放在受控密钥渠道。监控连接、失败和积压，设计降级与重试；超时不一定意味着外部操作没有发生，重复操作需要业务幂等。

接口文档、缓存、邮件和消息系统各有不同的可靠性与安全边界，不能只看应用启动成功。真实依赖应在隔离环境测试连接失败和恢复。

## 动手与自查

1. 在隔离 Redis 实例运行示例并核对值和 TTL。
2. 停止测试实例后运行，观察连接失败；不要对生产实例做这个实验。
3. 为什么缓存有过期时间仍可能短暂返回旧数据？
