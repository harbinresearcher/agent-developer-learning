# 使用开发者工具

> **重要程度：中**｜**手练：需要**
> **重点**：DevTools 自动重启、重新编译、运行方式与生产边界。

## DevTools 做什么

Spring Boot DevTools 提供开发期便利功能，包括类路径变化后的自动重启和部分开发期默认配置。它观察的是编译输出等类路径资源；只修改源码但没有让 class 文件更新，通常不会触发所需的重启。

自动重启会重新启动应用上下文，不等同于保证所有状态原样保留的热替换。某些静态资源和模板变化可能不需要重启，具体行为取决于配置与运行方式。

## 完整例子

使用 JDK 17、Maven 和 Spring Boot 4.1.2。新建目录，保存 `pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <parent>
        <groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-parent</artifactId>
        <version>4.1.2</version><relativePath/>
    </parent>
    <groupId>learn.example</groupId><artifactId>devtools-demo</artifactId><version>1.0</version>
    <properties><java.version>17</java.version></properties>
    <dependencies>
        <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-webmvc</artifactId></dependency>
        <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-devtools</artifactId><optional>true</optional></dependency>
    </dependencies>
    <build><plugins><plugin><groupId>org.springframework.boot</groupId><artifactId>spring-boot-maven-plugin</artifactId></plugin></plugins></build>
</project>
```

保存 `src/main/java/learn/boot/HelloApplication.java`：

```java
package learn.boot;

import java.util.Map;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@SpringBootApplication
@RestController
public class HelloApplication {
    private static final Logger logger = LoggerFactory.getLogger(HelloApplication.class);

    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：启动应用
         * 数据源：启动参数与 Spring Boot 自动配置
         * 操作：1) 创建应用容器 2) 启动内嵌 Web 服务
         * ======================================================================== */
        logger.info("开始启动应用");
        // 1.1 根据类路径和配置启动容器
        SpringApplication.run(HelloApplication.class, args);
        logger.info("应用启动完成");
    }

    @GetMapping("/hello")
    public Map<String, String> hello() {
        /* ========================================================================
         * 步骤1：处理问候请求
         * 数据源：GET /hello
         * 操作：1) 构造响应 2) 返回 JSON 数据
         * ======================================================================== */
        logger.info("开始处理问候请求");
        // 1.1 构造固定响应，不访问外部服务
        Map<String, String> result = Map.of("message", "Hello, Spring Boot!");
        logger.info("问候请求处理完成");
        return result;
    }
}
```

确认 `java -version` 和 `mvn -v` 使用 JDK 17 或以上，在工程目录启动：

```powershell
mvn spring-boot:run "-Dspring-boot.run.arguments=--server.address=127.0.0.1 --server.port=8080"
```

另开终端请求 `curl.exe -i http://127.0.0.1:8080/hello`，确认返回 JSON。将源码中的消息改为 `Hello, restarted!`，保存后在另一个终端的同一工程目录运行 `mvn compile`。观察服务窗口的重启日志，再请求接口，确认消息变化。完成后在服务窗口按 `Ctrl+C`；端口占用时修改启动参数与请求地址。

IDE 的构建方式不同：有的保存时自动编译，有的需要手动构建。关键检查点是 classpath 中的编译产物确实更新，而不是仅确认编辑器已保存。

## 工作中注意

DevTools 是开发期工具。默认重新打包的可执行归档不包含 DevTools；直接用 `java -jar` 的生产式运行方式也不应被当作开发期自动重启的验证。依赖标记为 optional 有助于避免作为传递依赖带给其他模块，但仍应检查实际产物和项目配置。

重启会影响内存状态、连接和后台任务；涉及数据库迁移或外部副作用的代码要设计为可安全重复启动。不要把 DevTools 当作正式部署、配置管理或生产监控方案。

## 动手与自查

1. 先请求接口，再修改源码并重新编译，核对重启日志和响应。
2. 只保存源码但不更新编译产物，解释为什么可能看不到变化。
3. 执行 `mvn package` 后用 `jar tf target/devtools-demo-1.0.jar` 检查默认产物，说明它与开发期运行方式的区别。
