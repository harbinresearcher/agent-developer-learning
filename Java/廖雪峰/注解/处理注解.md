# 处理注解

> **重要程度：中**｜**手练：建议**
> **重点**：读取 RUNTIME 注解、校验与异常路径。

## 解决什么问题

定义注解只是在程序元素上放置元数据；真正的校验、路由或其他行为必须由编译期处理器或运行时框架实现。下面用反射读取字段注解，再由普通 Java 代码执行长度判断。

## 完整例子

保存为 `AnnotationValidationDemo.java`，编译运行；日志写到标准错误。

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.reflect.Field;
import java.util.logging.Logger;
public class AnnotationValidationDemo {
    private static final Logger logger = Logger.getLogger(AnnotationValidationDemo.class.getName());
    public static void main(String[] args) throws ReflectiveOperationException {
        /*
         * ========================================================================
         * 步骤1：检查用户姓名
         * ========================================================================
         * 数据源：带有长度约束的演示对象
         * 操作：
         * 1) 创建输入对象
         * 2) 调用处理器读取注解并验证
         */
        logger.info("开始校验用户");
        // 1.1 创建演示数据
        User user = new User("Ada");
        // 1.2 按注解规则校验
        System.out.println("valid=" + validate(user));
        logger.info("用户校验完成");
    }
    static boolean validate(User user) throws ReflectiveOperationException {
        /*
         * ========================================================================
         * 步骤1：读取字段规则并计算结果
         * ========================================================================
         * 数据源：用户对象的 name 字段及其注解
         * 操作：
         * 1) 查找字段和长度规则
         * 2) 读取字段并验证长度
         */
        logger.info("开始读取字段规则");
        // 1.1 查找字段和规则
        Field field = User.class.getField("name");
        MinLength rule = field.getAnnotation(MinLength.class);
        if (rule == null) throw new IllegalStateException("缺少长度规则");
        // 1.2 计算并返回校验结果
        String value = (String) field.get(user);
        boolean valid = value != null && value.length() >= rule.value();
        logger.info("字段规则检查完成");
        return valid;
    }
    @Retention(RetentionPolicy.RUNTIME)
    @Target(ElementType.FIELD)
    @interface MinLength { int value(); }
    public static class User {
        @MinLength(2)
        public String name;
        User(String name) { this.name = name; }
    }
}
```

标准输出：

```text
valid=true
```

## 执行过程

`User.name` 标注 `@MinLength(2)`，注解指定 RUNTIME 保留与 FIELD 目标。`validate` 先取得公开字段，再读取注解；如果缺少规则就抛异常，避免把未配置误当作验证通过。它读取字段值，检查非 null 且长度至少为 2。`"Ada"` 长度为 3，所以输出 true。

这里的 `length()` 是 UTF-16 代码单元数量，不一定是用户感知字符数。示例只处理一个字段和一种类型，也没有输出细粒度错误消息；真实项目应明确长度语义、空值、国际化和校验规则。

## 处理阶段和边界

运行时反射只读取运行时保留的注解；其他注解可能由编译器或构建期注解处理器处理，机制不同。查找注解时注意成员、继承和框架合成注解的规则，不要假设所有注解自动继承。

反射访问依赖可见性与模块规则；示例用公开字段便于理解，不代表生产对象应该公开可变字段。实际项目优先使用成熟校验框架和清晰的配置，而不是照搬这个简化处理器。

## 手练与答案

将姓名改为 `"A"`，输出 `valid=false`；改为 null 也返回 false。将注解改为 CLASS 保留后，运行时 `getAnnotation` 得到 null，示例抛出“缺少长度规则”，而不会悄悄验证通过。
