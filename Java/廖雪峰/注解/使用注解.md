# 使用注解

> **重要程度：中**｜**手练：建议**
> **重点**：@Override 检查、注解作用与限制。

## 注解是什么

注解给类、方法、字段等程序元素附加元数据。它本身通常不会凭空执行任务；编译器、构建工具或运行时框架需要读取它并实现相应行为。不同注解的用途和生效阶段不同。

## 完整例子

保存为 `UseAnnotationDemo.java`，编译运行；日志写到标准错误。

```java
import java.util.logging.Logger;
public class UseAnnotationDemo {
    private static final Logger logger = Logger.getLogger(UseAnnotationDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：调用重写的方法
         * ========================================================================
         * 数据源：父类类型引用与子类对象
         * 操作：
         * 1) 创建子类对象
         * 2) 调用被标记为重写的方法
         */
        logger.info("开始调用对象方法");
        // 1.1 创建父类型引用
        Animal animal = new Dog();
        // 1.2 调用子类的重写实现
        System.out.println(animal.sound());
        logger.info("对象方法调用完成");
    }
    static class Animal { String sound() { return "动物声音"; } }
    static class Dog extends Animal {
        @Override
        String sound() { return "汪"; }
    }
}
```

标准输出：

```text
汪
```

## 执行过程

`Dog.sound()` 上的 `@Override` 告诉编译器：这个方法应当重写父类或实现接口的相应方法。签名正确时编译通过；运行时父类型引用指向 Dog，所以输出“汪”。若误把方法名写成 `sounds()` 而保留 `@Override`，编译器会报错，帮助发现没有真正重写。

## 常见注解与边界

`@Deprecated` 标记不建议继续使用的 API；编译器可提示调用者，替代方式与迁移时间需看文档。`@SuppressWarnings` 抑制指定编译警告，应只对理解并确认可接受的最小范围使用，不是修复问题。

框架注解可能描述依赖注入、事务或校验，但是否生效取决于框架配置、对象创建和调用路径。例如把注解写在未被框架管理的对象上，不应假定框架自动处理。

## 工作中怎么用

先问清楚是谁读取注解、在哪个阶段读取，以及读取后执行什么动作。不要仅凭注解名称推断行为；查对应框架版本文档并通过测试验证。自定义注解的使用位置和保留时间见 [[定义注解]]。

## 手练与答案

把 `Dog.sound` 改名为 `sounds`、保留 `@Override`：编译失败。去掉 `@Override` 后可能编译成功，但它不是重写；通过 Animal 引用调用 `sound()` 将使用父类实现。
