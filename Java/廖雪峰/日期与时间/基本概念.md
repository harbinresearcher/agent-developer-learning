# 基本概念

> **重要程度：高**｜**手练：需要**
> **重点**：时刻、本地时间、偏移量与时区。

## 先区分四个概念

时刻是时间线上的一个位置；本地日期时间是日历和钟表显示，不包含时区；偏移量如 `+08:00` 表示某时刻相对 UTC 的差；地区时区如 `Asia/Shanghai` 包含一组随时间可能变化的规则。只有本地时间，无法确定全球唯一时刻。

## 完整例子

保存为 `TimeConceptDemo.java`，编译运行；日志写到标准错误。示例使用固定时间，不依赖机器当前时钟。

```java
import java.time.*;
import java.util.logging.Logger;

public class TimeConceptDemo {
    private static final Logger logger = Logger.getLogger(TimeConceptDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：区分时刻与本地时间
         * ========================================================================
         * 数据源：程序内固定的示例时间
         * 操作：
         * 1) 创建时间对象
         * 2) 转换或计算并检查结果
         */
        logger.info("开始处理时间");
        // 1.1 以一个 UTC 时刻创建两个时区表示
        Instant instant = Instant.parse("2024-01-01T00:00:00Z");
        ZonedDateTime utc = instant.atZone(ZoneOffset.UTC);
        ZonedDateTime shanghai = instant.atZone(ZoneId.of("Asia/Shanghai"));
        // 1.2 比较本地时间与时间线上的时刻
        System.out.println("utc=" + utc.toLocalDateTime());
        System.out.println("shanghai=" + shanghai.toLocalDateTime());
        System.out.println("sameInstant=" + utc.toInstant().equals(shanghai.toInstant()));
        logger.info("时间处理完成");
    }
}
```

标准输出：

```text
utc=2024-01-01T00:00
shanghai=2024-01-01T08:00
sameInstant=true
```

## 执行过程

`2024-01-01T00:00:00Z` 中 Z 表示 UTC。UTC 墙上时间是 00:00，同一时刻在上海显示 08:00。两者的本地时间不同，但都转换回同一个 `Instant`，所以 sameInstant 为 true。

## 类型怎么选

`Instant` 表示时刻；`LocalDate` 表示日期；`LocalTime` 表示钟表时间；`LocalDateTime` 是本地日期与时间但不含时区；`ZonedDateTime` 包含地区时区及该时刻的偏移。生日通常用日期而非随意加午夜时刻；跨系统事件发生时间通常需要明确时间线位置。

地区时区不等于固定偏移：某些地区受夏令时或历史政策变化影响。同一个本地时间在某时区可能不存在或出现两次；遇到预约等需要本地时间的业务，应明确如何处理空缺和重叠。

## 手练与答案

本例把 shanghai 转回 Instant，与原值相等。若只有 `2024-01-01T08:00` 而没有时区或偏移，不能唯一确定它对应哪个时刻。
