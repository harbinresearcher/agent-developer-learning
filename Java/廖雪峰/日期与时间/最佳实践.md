# 最佳实践

> **重要程度：高**｜**手练：需要**
> **重点**：固定时钟、时区边界、可测试的日期逻辑。

## 问题从哪里来

“今天”“一个月后”“当天结束”都依赖业务规则。相同时刻在不同时区可能属于不同日期；直接调用系统默认时区和当前时间，测试可能因机器或运行时刻不同而变化。

## 完整例子

保存为 `ClockDemo.java`，编译运行；日志写到标准错误。示例固定时间和地区，可重复验证。

```java
import java.time.Clock;
import java.time.Instant;
import java.time.LocalDate;
import java.time.ZoneId;
import java.util.logging.Logger;
public class ClockDemo {
    private static final Logger logger = Logger.getLogger(ClockDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：使用固定时钟比较日期
         * ========================================================================
         * 数据源：同一固定时刻和两个地区时区
         * 操作：
         * 1) 分别构造带时区的测试时钟
         * 2) 读取当地日期并比较
         */
        logger.info("开始计算当地日期");
        // 1.1 固定时刻以避免依赖系统当前时间
        Instant instant = Instant.parse("2024-01-01T23:30:00Z");
        Clock shanghai = Clock.fixed(instant, ZoneId.of("Asia/Shanghai"));
        Clock losAngeles = Clock.fixed(instant, ZoneId.of("America/Los_Angeles"));
        // 1.2 用明确时钟读取当地日期
        System.out.println("shanghai=" + LocalDate.now(shanghai));
        System.out.println("losAngeles=" + LocalDate.now(losAngeles));
        logger.info("当地日期计算完成");
    }
}
```

标准输出：

```text
shanghai=2024-01-02
losAngeles=2024-01-01
```

## 执行过程

`Clock.fixed` 固定为 2024-01-01 23:30 UTC。两个 Clock 指向同一时刻，但地区不同：上海已是 1 月 2 日，洛杉矶仍是 1 月 1 日。`LocalDate.now(clock)` 使用传入时钟的时区获取当地日期，避免隐式使用运行机器默认时区。

## 设计规则

1. 先定义业务语义：生日是日期；事件发生时间是时刻；未来地区预约还涉及本地时间、地区时区、调钟空缺与重叠的处理策略。
2. 跨服务传递时明确单位、精度、偏移或 UTC；毫秒和秒不能混用。若未来日程需要遵循地区规则，保存地区 ZoneId 和必要的本地意图。
3. 在业务组件中注入 Clock；生产可传入适当系统时钟，测试用固定 Clock。测试月底、闰年、跨时区午夜和目标地区夏令时边界。
4. 测量耗时使用单调时间源，例如 `System.nanoTime()` 的差值；不要把它作为可跨机器比较的时间戳。

日期运算应先明确是日历日、工作日还是固定小时；时区规则和节假日规则不同。序列化、数据库列类型和驱动的时间映射应在具体项目中做往返测试。

## 手练与答案

将固定时刻改为 `2024-01-01T00:00:00Z`：上海日期是 2024-01-01，洛杉矶仍是 2023-12-31。两个日期不同不表示它们引用了不同时刻。
