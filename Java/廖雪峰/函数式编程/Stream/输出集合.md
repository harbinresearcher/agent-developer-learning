# 输出集合

> **重要程度：高**｜**手练：需要**
> **重点**：collect、重复键合并、结果顺序。

## 解决什么问题

Stream 处理后常需要收集为 List、Set 或 Map。`collect` 是终止操作，通过 Collector 定义如何累积结果；收集的类型、顺序、重复键和可变性应由具体 Collector 契约决定。

## 完整例子

保存为 `CollectDemo.java`，编译运行；日志写到标准错误。

```java
import java.util.*;
import java.util.function.*;
import java.util.stream.*;
import java.util.logging.Logger;
public class CollectDemo {
    private static final Logger logger = Logger.getLogger(CollectDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：收集词频
         * ========================================================================
         * 数据源：程序中准备的固定示例数据
         * 操作：
         * 1) 创建流并配置操作
         * 2) 执行终止操作并输出结果
         */
        logger.info("开始处理示例");
        // 1.1 准备包含重复值的单词
        List<String> words = Arrays.asList("a", "b", "a");
        // 1.2 指定重复键合并规则和有序映射
        Map<String, Integer> counts = words.stream().collect(Collectors.toMap(
                Function.identity(), word -> 1, Integer::sum, LinkedHashMap::new));
        System.out.println("counts=" + counts);
        logger.info("示例处理完成");
    }
}
```

标准输出：

```text
counts={a=2, b=1}
```

## 执行过程

`Function.identity()` 使用单词自身作为键，每次出现映射为 1。重复键出现时 `Integer::sum` 合并旧值与新值；第四个参数创建 LinkedHashMap，在本例顺序流中按插入顺序显示 a、b。a 出现两次、b 一次，所以结果为 `{a=2, b=1}`。

## 边界和选择

使用未提供合并函数的 `Collectors.toMap` 遇到重复键时会抛 `IllegalStateException`。合并规则要符合业务，不能机械选第一个或最后一个；并行执行时还要考虑结合性。默认 Collector 的返回具体实现、可变性和线程安全性不能在没有契约时擅自假定。

`Collectors.toList()` 是 Java 11 可用的收集方式；较新的 `Stream.toList()` 自 Java 16 起可用，且返回列表的修改契约不同，不能不检查版本就替换。`groupingBy` 可按分类聚合；是否有序取决于所用 Map 工厂和流语义。

## 工作中怎么用

选择明确的重复策略、空值策略和结果顺序；处理大量数据时考虑内存。不要并行向普通共享 HashMap 或 ArrayList 写入，除非采用满足并发约束的机制。

## 手练与答案

新增一个 `"b"`：结果为 `{a=2, b=2}`。移除合并函数并用适当的两参数 `toMap` 重载：重复的 a 会导致 `IllegalStateException`。
