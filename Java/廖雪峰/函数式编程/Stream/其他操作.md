# 其他操作

> **重要程度：高**｜**手练：需要**
> **重点**：distinct、sorted、skip、limit 与顺序。

## 解决什么问题

Stream 提供去重、排序、截取和查找等操作。它们组合的顺序影响结果和性能；先明确业务顺序，再选择可读的流水线。

## 完整例子

保存为 `StreamOtherDemo.java`，编译运行；日志写到标准错误。

```java
import java.util.*;
import java.util.function.*;
import java.util.stream.*;
import java.util.logging.Logger;
public class StreamOtherDemo {
    private static final Logger logger = Logger.getLogger(StreamOtherDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：去重排序并截取
         * ========================================================================
         * 数据源：程序中准备的固定示例数据
         * 操作：
         * 1) 创建流并配置操作
         * 2) 执行终止操作并输出结果
         */
        logger.info("开始处理示例");
        // 1.1 准备包含重复值的列表
        List<Integer> values = Arrays.asList(4, 1, 2, 2, 3);
        // 1.2 去重排序后跳过一项、最多取两项
        List<Integer> selected = values.stream()
                .distinct()
                .sorted()
                .skip(1)
                .limit(2)
                .collect(Collectors.toList());
        System.out.println("selected=" + selected);
        logger.info("示例处理完成");
    }
}
```

标准输出：

```text
selected=[2, 3]
```

## 执行过程

输入 `[4, 1, 2, 2, 3]` 先 `distinct` 得到不重复值，再 `sorted` 为 `[1, 2, 3, 4]`；`skip(1)` 跳过 1，`limit(2)` 取 2、3。若先 limit 再排序，处理的元素集合不同，结果不一定相同。

## 其他常用操作和边界

`distinct` 按元素相等规则去重；自定义类型的 equals/hashCode 应一致。`sorted` 使用自然顺序或比较器，元素不可比较、null 处理不符合比较器规则等可能导致失败。`findFirst`、`anyMatch` 等可短路，不保证处理所有元素；空结果通常由 Optional 或布尔值表达。

`peek` 常用于诊断，但流实现可能优化掉不影响最终结果的阶段，不能依赖它执行必要的业务动作。流通常只能消费一次；需要新的一次计算应重新创建流水线。

## 工作中怎么用

排序和去重可能需要额外内存；无限流在排序等操作前需有明确边界，避免无法结束。并行处理不保证更快，也可能改变不要求保序操作的执行方式；用数据验证性能，并避免共享可变状态。

## 手练与答案

把 `skip(1)` 改为 `skip(0)`：结果 `[1, 2]`。如果先对原始流 `limit(2)` 再去重和排序：只处理 4、1，结果为 `[1, 4]`。
