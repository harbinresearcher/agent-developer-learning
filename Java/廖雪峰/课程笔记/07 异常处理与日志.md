# 异常处理与日志

> **重要程度：高**｜**手练：需要**
> **重点**：受检异常和运行时异常、异常传播、资源关闭、日志与敏感信息。

## 异常链路

代码抛出异常后，当前流程中断，向调用方寻找匹配的 `catch`；在合适的层处理，不要只记录后假装成功。`throw` 抛出异常，`throws` 声明方法可能抛出的受检异常。

`Exception` 中既有受检异常，也有 `RuntimeException` 等非受检异常。捕获多个异常时，具体子类放在父类之前。`finally` 常用于清理，但进程被强制终止时不能保证执行。

实现了 `AutoCloseable` 的资源可用 `try-with-resources` 管理；退出时自动关闭，发生多个异常时还需留意 suppressed exceptions。转换异常时保留原异常作为 cause，方便追踪。

## 工作中

`assert` 可能被运行参数关闭，不用于校验外部输入。日志记录有助定位问题的上下文和异常堆栈；不要记录密码、令牌或完整敏感数据。应用和依赖应按项目约定统一日志门面与实现；JDK Logging、SLF4J、Logback 的职责不同。

## 手练

写一个读取文本文件并解析整数的程序，分别处理文件不存在与输入格式错误；确认异常情况下文件仍被关闭。再让调用者能看到原始异常原因。
