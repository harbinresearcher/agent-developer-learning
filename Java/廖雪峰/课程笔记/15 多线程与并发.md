# 多线程与并发

> **重要程度：高**｜**手练：需要**
> **重点**：线程状态与中断、共享状态、锁、线程池、Future；理解虚拟线程适用边界。

## 线程和共享状态

调用 `start()` 启动新线程；直接调用 `run()` 只是普通方法调用。线程执行顺序由调度决定，不能依赖输出顺序。中断是一种协作式取消信号，不是强制杀死线程；捕获 `InterruptedException` 后应按调用约定传播或恢复中断状态。

多个线程读写共享可变数据时，复合操作可能发生竞态。`synchronized` 可保护临界区并提供可见性；要用同一把锁保护同一共享状态。`volatile` 提供可见性和部分有序性，不让 `count++` 这类复合操作自动原子化。多把锁需要统一获取顺序，避免死锁。

## 并发工具

`ExecutorService` 将任务提交给线程池，需明确容量、队列、拒绝策略和关闭时机。`Future` 表示异步结果；`CompletableFuture` 可组合多个阶段，但仍要处理异常、超时和线程池选择。`Atomic` 类提供特定原子操作；并发集合提供各自定义的线程安全行为，不等于所有多步业务操作都自动原子。

`wait` / `notify` 要遵守监视器规则并循环检查条件；`ReentrantLock`、`Condition`、读写锁、`Semaphore` 各适用不同同步需求。`ThreadLocal` 在线程池中要清理，防止值残留到后续任务。

Java 21 起虚拟线程正式可用，适合大量等待 IO 的任务；它不让 CPU 密集计算本身变快，也不能无限放大数据库连接等下游资源。

## 手练

实现多个任务并发计数，先观察不加同步可能出现的问题，再用锁或原子类验证；实现线程池任务超时、中断和关闭，检查是否有任务被遗留。
