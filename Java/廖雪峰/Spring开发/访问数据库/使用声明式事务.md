# 使用声明式事务

> **重要程度：高**｜**手练：需要**
> **重点**：事务代理、提交与回滚、异常规则、自调用和传播边界。

## 它解决什么问题

业务方法有多条需要一起成功的数据库修改。Spring 声明式事务把事务边界写在方法上，事务基础设施在符合条件的调用前后开始、提交或回滚事务。注解只声明意图，必须有事务管理器、事务基础设施、容器管理的对象和有效的调用路径才能生效。

本例明确使用 `@EnableTransactionManagement`、`DataSourceTransactionManager` 和同一个 `DataSource` 创建的 `JdbcTemplate`。它只操作 H2 内存数据库，不连接生产数据库。

## 完整例子

使用 JDK 17、Maven 和 Spring Framework 7.0.10。保存以下 `pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <groupId>learn.example</groupId><artifactId>spring-ioc-demo</artifactId><version>1.0</version>
    <properties><maven.compiler.release>17</maven.compiler.release><project.build.sourceEncoding>UTF-8</project.build.sourceEncoding></properties>
    <dependencies>
        <dependency><groupId>org.springframework</groupId><artifactId>spring-context</artifactId><version>7.0.10</version></dependency>
        <dependency><groupId>org.springframework</groupId><artifactId>spring-jdbc</artifactId><version>7.0.10</version></dependency>
        <dependency><groupId>com.h2database</groupId><artifactId>h2</artifactId><version>2.4.240</version></dependency>
    </dependencies>
    <build><plugins><plugin><groupId>org.apache.maven.plugins</groupId><artifactId>maven-compiler-plugin</artifactId><version>3.14.1</version></plugin></plugins></build>
</project>
```

将代码保存为 `src/main/java/DeclarativeTransactionDemo.java`：

```java
import java.util.logging.Logger;
import javax.sql.DataSource;
import org.h2.jdbcx.JdbcDataSource;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.datasource.DataSourceTransactionManager;
import org.springframework.transaction.PlatformTransactionManager;
import org.springframework.transaction.annotation.EnableTransactionManagement;
import org.springframework.transaction.annotation.Transactional;
public class DeclarativeTransactionDemo {
    private static final Logger logger = Logger.getLogger(DeclarativeTransactionDemo.class.getName());
    public static class TransferService {
        private final JdbcTemplate jdbc;
        TransferService(JdbcTemplate jdbc) { this.jdbc = jdbc; }
        @Transactional
        public void transfer(boolean fail) {
            /* ========================================================================
             * 步骤1：修改两个账户
             * 数据源：当前事务中的 accounts 表
             * 操作：1) 扣款 2) 模拟失败或收款
             * ======================================================================== */
            logger.info("开始转账");
            // 1.1 扣款并检查目标存在
            if (jdbc.update("UPDATE accounts SET balance = balance - ? WHERE id = ?", 30, 1) != 1)
                throw new IllegalStateException("付款账户不存在");
            // 1.2 模拟异常，或完成收款
            if (fail) throw new IllegalStateException("模拟收款失败");
            if (jdbc.update("UPDATE accounts SET balance = balance + ? WHERE id = ?", 30, 2) != 1)
                throw new IllegalStateException("收款账户不存在");
            logger.info("转账方法完成，等待事务提交");
        }
    }
    @Configuration
    @EnableTransactionManagement
    static class Config {
        @Bean DataSource dataSource() {
            JdbcDataSource source = new JdbcDataSource();
            source.setURL("jdbc:h2:mem:springtx;DB_CLOSE_DELAY=-1");
            return source;
        }
        @Bean JdbcTemplate jdbcTemplate(DataSource dataSource) { return new JdbcTemplate(dataSource); }
        @Bean PlatformTransactionManager transactionManager(DataSource dataSource) {
            return new DataSourceTransactionManager(dataSource);
        }
        @Bean TransferService transferService(JdbcTemplate jdbc) { return new TransferService(jdbc); }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：准备账户
         * 数据源：H2 内存数据库
         * 操作：1) 创建容器 2) 初始化账户表
         * ======================================================================== */
        logger.info("开始准备账户");
        try (AnnotationConfigApplicationContext context = new AnnotationConfigApplicationContext(Config.class)) {
            // 1.1 测试数据准备在事务方法调用之前
            JdbcTemplate jdbc = context.getBean(JdbcTemplate.class);
            jdbc.execute("CREATE TABLE accounts (id INT PRIMARY KEY, balance INT NOT NULL)");
            jdbc.update("INSERT INTO accounts VALUES (1, 100), (2, 50)");
            logger.info("账户准备完成");
            /* ========================================================================
             * 步骤2：验证回滚和提交
             * 数据源：容器提供的事务代理
             * 操作：1) 模拟失败并核对 2) 成功转账并核对
             * ======================================================================== */
            logger.info("开始验证事务");
            // 2.1 从容器取得服务，异常穿过代理后在调用方捕获
            TransferService service = context.getBean(TransferService.class);
            try { service.transfer(true); }
            catch (IllegalStateException ex) { System.out.println("失败: " + ex.getMessage()); }
            System.out.println("回滚后付款账户: " + jdbc.queryForObject("SELECT balance FROM accounts WHERE id = 1", Integer.class));
            // 2.2 重新调用，正常返回后由代理提交
            service.transfer(false);
            System.out.println("提交后付款账户: " + jdbc.queryForObject("SELECT balance FROM accounts WHERE id = 1", Integer.class));
            System.out.println("提交后收款账户: " + jdbc.queryForObject("SELECT balance FROM accounts WHERE id = 2", Integer.class));
            logger.info("事务验证完成");
        }
    }
}
```

在项目根目录运行（PowerShell）：

```powershell
mvn package
mvn org.apache.maven.plugins:maven-dependency-plugin:3.7.0:build-classpath "-Dmdep.outputFile=classpath.txt"
$springDeps = (Get-Content -Raw -Encoding UTF8 classpath.txt).Trim()
java -cp "target/classes;$springDeps" DeclarativeTransactionDemo
```

标准输出如下，日志单独显示：

```text
失败: 模拟收款失败
回滚后付款账户: 100
提交后付款账户: 70
提交后收款账户: 80
```

## 一次调用如何经过事务

1. `context.getBean` 取得容器提供的服务代理，调用 `transfer(true)` 进入事务拦截器。
2. 扣款后抛出运行时异常，异常离开事务方法；代理按默认规则回滚，调用方捕获异常后查询余额仍为 100。
3. 第二次调用正常完成扣款和收款，方法正常返回后代理提交；查询结果为 70、80。

本例的 `DB_CLOSE_DELAY=-1` 仅让内存数据库在短连接归还后存活到 JVM 结束，适合练习；真实服务的连接池和数据库配置另行设计。本例验证了单进程、单数据源、H2 下的结果，不证明其他数据库或分布式场景。

## 回滚规则和常见失效点

- Spring 默认对未处理的 `RuntimeException` 和 `Error` 回滚；受检异常默认规则不同，可按业务明确 `rollbackFor`，并核对项目是否修改了全局默认规则。
- 如果事务方法内部捕获异常后正常返回，事务拦截器可能认为调用成功；是否回滚取决于是否被标记为只回滚及具体规则。不要只看日志判断提交状态。
- 默认代理模式下，同一对象内部的 `this.otherTransactionalMethod()` 不会再次通过代理；手动 `new` 的对象也不受容器事务代理管理。公开方法和代理类型的要求依框架版本及配置而定。
- `REQUIRED` 默认加入已有事务或新建事务；`REQUIRES_NEW` 使用独立事务并可能占用额外连接。嵌套调用、异常捕获和连接池容量必须结合具体事务管理器测试。
- 数据库事务不自动覆盖已发送邮件、HTTP 调用或消息；还需结合业务选择事务消息、补偿及幂等设计。

## 动手与自查

1. 将模拟失败改为在方法内部捕获，观察余额并解释为什么结果可能不同。
2. 改用受检异常，分别对比默认规则与 `rollbackFor` 的数据库结果。
3. 从同一个类内部调用带事务注解的方法，和从容器代理外部调用做对照实验。
4. 给扣款增加余额条件并检查影响行数，解释这与事务分别解决什么问题。
