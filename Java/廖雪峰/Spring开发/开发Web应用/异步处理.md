# Spring MVC 异步请求

> **重要程度：高**｜**手练：需要**
> **重点**：请求线程与工作线程的分工；`Callable` 的完成流程；线程池、超时、错误与上下文边界。

## 先看请求如何走

普通 MVC 请求里，容器线程调用控制器并等待方法返回，之后写出响应。若方法需要等待外部服务，线程也会被占用。MVC 异步请求允许控制器先返回一个待执行任务，让容器线程退出；结果准备好后，请求会重新分派并完成响应。客户端仍在等待同一个 HTTP 响应。

```text
请求进入 → 控制器返回 Callable → MVC 交给工作线程
         → 请求线程退出等待 → 工作线程完成
         → 容器重新分派 → 写出 HTTP 响应
```

异步释放的是请求线程，不会消除工作本身：如果任务里是阻塞调用，工作线程仍会等待。它也不自动把 HTTP 接口变成消息队列，更不保证程序重启后任务继续执行。

## 手练：观察两个线程

下面的应用返回 `Callable<String>`。Spring MVC 用有界线程池运行任务；成功后响应 `hello async`。项目目录为 `mvc-async/pom.xml` 和 `mvc-async/src/main/java/learn/async/AsyncDemo.java`。

`pom.xml`：


`src/main/java/learn/async/AsyncDemo.java`：

```java
package learn.async;
import java.util.concurrent.Callable;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.servlet.config.annotation.AsyncSupportConfigurer;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@SpringBootApplication
public class AsyncDemo {
    private static final Logger logger = LoggerFactory.getLogger(AsyncDemo.class);
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：启动异步请求演示
         * 数据源：本机 HTTP 请求
         * 操作：1) 启动容器 2) 注册控制器与执行器
         * ======================================================================== */
        logger.info("开始启动演示");
        // 1.1 启动 Spring Boot 容器
        SpringApplication.run(AsyncDemo.class, args);
        logger.info("演示启动完成");
    }
}
@Configuration
class AsyncConfig implements WebMvcConfigurer {
    @Bean
    ThreadPoolTaskExecutor asyncExecutor() {
        /* ========================================================================
         * 步骤1：配置有界执行器
         * 数据源：演示用固定参数
         * 操作：1) 限制线程与队列 2) 返回托管执行器
         * ======================================================================== */
        Logger logger = LoggerFactory.getLogger(AsyncConfig.class);
        logger.info("开始配置执行器");
        // 1.1 设置小型线程池和有限队列
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(2);
        executor.setMaxPoolSize(2);
        executor.setQueueCapacity(10);
        executor.setThreadNamePrefix("mvc-async-");
        logger.info("执行器配置结束");
        return executor;
    }
    @Override
    public void configureAsyncSupport(AsyncSupportConfigurer configurer) {
        /* ========================================================================
         * 步骤1：设置异步请求边界
         * 数据源：Spring MVC 配置
         * 操作：1) 绑定执行器 2) 设置请求超时
         * ======================================================================== */
        Logger logger = LoggerFactory.getLogger(AsyncConfig.class);
        logger.info("开始配置异步请求");
        // 1.1 使用容器管理的执行器和两秒超时
        configurer.setTaskExecutor(asyncExecutor());
        configurer.setDefaultTimeout(2000);
        logger.info("异步请求配置结束");
    }
}
@RestController
class AsyncController {
    private static final Logger logger = LoggerFactory.getLogger(AsyncController.class);
    @GetMapping("/async")
    Callable<String> async() {
        /* ========================================================================
         * 步骤1：返回待异步执行的工作
         * 数据源：HTTP 请求
         * 操作：1) 记录请求线程 2) 返回延后调用的任务
         * ======================================================================== */
        logger.info("开始接收异步请求");
        // 1.1 返回 Callable，具体工作由 MVC 执行器运行
        Callable<String> task = () -> {
            /* ========================================================================
             * 步骤1：生成响应
             * 数据源：异步任务线程
             * 操作：1) 记录当前线程 2) 返回响应文本
             * ======================================================================== */
            logger.info("开始生成响应，线程={}", Thread.currentThread().getName());
            // 1.1 准备响应
            String result = "hello async";
            logger.info("响应生成结束");
            return result;
        };
        logger.info("异步任务已交给 MVC");
        return task;
    }
}
```

启动并访问：

```powershell
mvn package
java -jar target/mvc-async-1.0.jar --server.port=18080 --server.address=127.0.0.1
```

另开终端：

```powershell
Invoke-WebRequest http://127.0.0.1:18080/async
```

响应体应为 `hello async`。日志里控制器请求线程与 `mvc-async-` 开头的工作线程不同；任务很短，日志先后顺序可能因调度而变化。按 Ctrl+C 停止自己的服务；如果 18080 已被占用，改成空闲端口。

本例已用 JDK 17 和 Spring Boot 4.1.2 启动，并在隔离端口验证 HTTP 200、响应体和工作线程日志。成功路径已验证；超时、任务拒绝和异常路径尚未在这个例子中验证。

## Callable、DeferredResult 和 @Async

- `Callable<T>`：控制器返回待执行的工作，MVC 提交给配置的异步执行器，工作完成后继续处理结果。例子属于这一类。
- `DeferredResult<T>`：控制器先返回一个结果容器，之后由其他线程或回调调用 `setResult` / `setErrorResult`。需要明确超时回调、重复完成和资源清理；它不会替你创建后台工作。
- `@Async`：异步调用 Spring Bean 方法的机制，与 MVC 异步请求不是同一个功能。默认代理模式下，同一个对象内部直接调用自己的 `@Async` 方法通常不会经过代理；返回 `Future` 或 `CompletableFuture` 才方便观察异步结果和异常。

## 出错和生产环境

1. **超时**：示例将 MVC 异步请求超时设为 2 秒。请求超时不等于外部调用或后台任务一定停止；还应设置数据库、HTTP 客户端等各自的超时，并处理取消后的资源。
2. **异常**：`Callable` 抛出的异常会在异步分派时交回 MVC 异常处理机制。可用统一异常处理返回合适状态码；不要把堆栈、凭证直接返回客户端。
3. **容量**：线程数和队列必须有界，按照任务耗时与并发容量测量。队列满时要明确拒绝策略与 HTTP 响应；上例只设置边界，没有定制拒绝响应。
4. **上下文**：请求线程上的 `ThreadLocal`、日志跟踪或安全上下文不一定自动出现在工作线程；应使用框架支持的上下文传播机制，并清理线程复用时的状态。
5. **重试与持久化**：若任务必须在断线、重启后继续或需要可查询进度，应设计持久化任务状态、幂等和恢复机制；普通异步 HTTP 请求不提供这些保证。

## 自测

1. `Callable` 仍调用阻塞的外部接口时，哪个线程被占用？
2. 客户端收到超时后，后台操作一定已取消吗？若后台仍写数据库，如何防止客户端重试产生重复操作？
3. 工作线程池和队列都满时，系统需要什么策略？为什么无限增大队列也有风险？
4. 修改任务使其抛出异常，再观察 HTTP 状态与服务端日志；另外设计可控的超时实验，不要依赖生产接口。
