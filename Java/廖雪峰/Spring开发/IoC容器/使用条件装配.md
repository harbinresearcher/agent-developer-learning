# 使用条件装配

> **重要程度：中**｜**手练：需要**
> **重点**：Profile 选择、无候选与多候选的排查。

## 为什么需要条件装配

同一接口在本地、测试或生产环境可能使用不同实现。条件装配只在条件满足时注册相应 Bean。例子用 Spring Framework 的 `@Profile` 区分 `dev` 和 `prod`；在容器刷新前激活 `dev`，因此只注册开发实现。


## 完整例子

使用 JDK 17、Maven 和 Spring Framework 7.0.10。Spring 6 起要求 Java 17 或以上。新建目录，保存以下 `pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <groupId>learn.example</groupId><artifactId>spring-ioc-demo</artifactId><version>1.0</version>
    <properties><maven.compiler.release>17</maven.compiler.release><project.build.sourceEncoding>UTF-8</project.build.sourceEncoding></properties>
    <dependencies>
        <dependency><groupId>org.springframework</groupId><artifactId>spring-context</artifactId><version>7.0.10</version></dependency>
    </dependencies>
    <build><plugins><plugin><groupId>org.apache.maven.plugins</groupId><artifactId>maven-compiler-plugin</artifactId><version>3.14.1</version></plugin></plugins></build>
</project>
```

将代码保存为 `src/main/java/ConditionalBeanDemo.java`：

```java
import java.util.logging.Logger;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Profile;
public class ConditionalBeanDemo {
    private static final Logger logger = Logger.getLogger(ConditionalBeanDemo.class.getName());
    interface MessageSource { String message(); }
    @Configuration
    static class Config {
        @Bean @Profile("dev") MessageSource devMessage() { return () -> "开发环境"; }
        @Bean @Profile("prod") MessageSource prodMessage() { return () -> "生产环境"; }
    }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：选择环境并创建 Bean
         * 数据源：显式指定的 dev profile
         * 操作：1) 在刷新前激活环境 2) 获取匹配的实现
         * ======================================================================== */
        logger.info("开始创建容器");
        try (AnnotationConfigApplicationContext context = new AnnotationConfigApplicationContext()) {
            // 1.1 激活 dev 并注册配置
            context.getEnvironment().setActiveProfiles("dev");
            context.register(Config.class);
            context.refresh();
            // 1.2 查询条件匹配后的结果
            System.out.println(context.getBean(MessageSource.class).message());
            System.out.println("生产 Bean 存在: " + context.containsBean("prodMessage"));
        }
        logger.info("容器关闭完成");
    }
}
```

在项目根目录运行（PowerShell）：

先运行 `java -version` 和 `mvn -v`，确认两者都使用 JDK 17 或以上；不一致时先调整 `JAVA_HOME` 和 `PATH`。

```powershell
mvn package
mvn org.apache.maven.plugins:maven-dependency-plugin:3.7.0:build-classpath "-Dmdep.outputFile=classpath.txt"
$springDeps = (Get-Content -Raw -Encoding UTF8 classpath.txt).Trim()
java -cp "target/classes;$springDeps" ConditionalBeanDemo
```

标准输出如下，日志可能单独显示：

```text
开发环境
生产 Bean 存在: false
```

## 选择与失败边界

激活 `prod` 会切换到生产实现；如果两个 profile 同时激活，例子会产生两个同类型候选，按类型获取单个 Bean 可能报歧义。如果两者都没激活，则两个方法都不匹配，依赖该接口的对象无法获得候选。默认 profile 和实际启动参数需要检查，不能假设任何环境都自动选择一个实现。

`@Profile` 是 Spring Framework 能力；`@ConditionalOnProperty` 等常见注解属于 Spring Boot，条件评估及配置方式要按项目版本查文档。条件只决定是否注册，不能代替对生产密钥和连接地址的校验。

## 工作中排错

先核对激活的 profile、配置来源和条件，再查看容器中实际存在的 Bean；测试应覆盖匹配、缺失和意外同时匹配。不要把生产密码编码在 profile 名称或日志中。

## 动手与自查

1. 将激活环境改为 `prod`，验证输出变化。
2. 同时激活 `dev`、`prod`，观察单个类型查询的歧义。
3. 移除激活配置，解释为什么 `MessageSource` 找不到。
