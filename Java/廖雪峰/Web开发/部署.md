# 部署

> **重要程度：高**｜**手练：需要**
> **重点**：构建产物、运行环境、配置、真实请求与回滚。

## 部署需要完成什么

部署是把经过构建的应用交给目标环境运行，并验证它能处理实际请求。项目可能使用带内嵌服务器的可执行 JAR，也可能将 WAR 交给外部 Servlet 容器；具体方式由项目构建和目标环境决定。

一次构建成功不能证明部署成功：运行时 JDK、端口、配置、依赖服务、网络、权限和启动后的行为都需要检查。下面只在本机隔离目录练习，不涉及线上发布。

## 完整例子

使用 JDK 17、Maven 和 Spring Boot 4.1.2。新建工程目录，保存 `pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <parent>
        <groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-parent</artifactId>
        <version>4.1.2</version><relativePath/>
    </parent>
    <groupId>learn.example</groupId><artifactId>hello-boot</artifactId><version>1.0</version>
    <properties><java.version>17</java.version></properties>
    <dependencies>
        <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-webmvc</artifactId></dependency>
    </dependencies>
    <build><plugins><plugin><groupId>org.springframework.boot</groupId><artifactId>spring-boot-maven-plugin</artifactId></plugin></plugins></build>
</project>
```

保存 `src/main/java/learn/boot/HelloApplication.java`：

```java
package learn.boot;

import java.util.Map;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@SpringBootApplication
@RestController
public class HelloApplication {
    private static final Logger logger = LoggerFactory.getLogger(HelloApplication.class);

    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：启动应用
         * 数据源：启动参数与 Spring Boot 自动配置
         * 操作：1) 创建应用容器 2) 启动内嵌 Web 服务
         * ======================================================================== */
        logger.info("开始启动应用");
        // 1.1 根据类路径和配置启动容器
        SpringApplication.run(HelloApplication.class, args);
        logger.info("应用启动完成");
    }

    @GetMapping("/hello")
    public Map<String, String> hello() {
        /* ========================================================================
         * 步骤1：处理问候请求
         * 数据源：GET /hello
         * 操作：1) 构造响应 2) 返回 JSON 数据
         * ======================================================================== */
        logger.info("开始处理问候请求");
        // 1.1 构造固定响应，不访问外部服务
        Map<String, String> result = Map.of("message", "Hello, Spring Boot!");
        logger.info("问候请求处理完成");
        return result;
    }
}
```

先用 `java -version` 和 `mvn -v` 确认均使用 JDK 17 或以上。工程目录中运行：

```powershell
mvn package
New-Item -ItemType Directory -Force run-demo
Copy-Item target/hello-boot-1.0.jar run-demo/app.jar
Push-Location run-demo
java -jar app.jar --server.address=127.0.0.1 --server.port=8080
```

另开 PowerShell 请求：

```powershell
curl.exe -i http://127.0.0.1:8080/hello
```

应收到 HTTP 200 和包含 `Hello, Spring Boot!` 的 JSON。完成后在服务窗口按 `Ctrl+C`，再执行 `Pop-Location`。端口被占用时，启动参数和请求地址应同步修改。

## 看懂部署链路

`mvn package` 编译并创建 JAR；复制到 `run-demo` 后，从独立目录启动，说明运行不依赖源码当前工作目录。服务启动日志是一个信号，但还需真实请求验证接口。本例没有数据库、认证和外部服务，不能据此推断生产集成正常。

## 工作中需要核对

- 确认目标 JDK 与应用、依赖兼容；外部容器部署 WAR 时还要核对 Servlet/Jakarta 版本。
- 配置地址、凭据和超时；密钥由受控渠道提供，不写进源码和日志。端口暴露范围应与网关和网络策略一致。
- 观察启动日志、健康检查和核心请求；区分进程存活与依赖就绪。数据库迁移要与新旧版本兼容性一起设计。
- 保留可追溯的产物版本与回滚方案；回滚应用不一定能撤销已发生的数据迁移或外部副作用。

## 动手与自查

1. 在独立目录启动 JAR，检查状态码和正文，再停止进程。
2. 修改启动端口并同步修改请求地址，观察端口不匹配时的现象。
3. 为什么数据库迁移成功后，仅回滚应用 JAR 不一定能恢复原有数据结构？
