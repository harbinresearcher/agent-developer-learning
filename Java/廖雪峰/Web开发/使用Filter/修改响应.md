# 修改响应

> **重要程度：高**｜**手练：需要**
> **重点**：响应包装、缓存与写回、提交顺序和内存边界。

## 为什么需要包装响应

过滤器调用 `chain.doFilter` 时，下游可能直接把正文写到响应输出流。若要在下游写完后检查或转换正文，需要让下游先写入包装器的缓存，再按契约写回原始响应。本例使用 Spring 的 `ContentCachingResponseWrapper`，把已知的短 UTF-8 文本转换为大写。

示例只拦截 `/word`，目标接口返回固定小文本 `hello`。过滤器调用下游后读取缓存、清空缓冲、写入转换后的内容，最后调用 `copyBodyToResponse()`；遗漏写回会让客户端拿不到预期正文。

## 完整例子

使用 JDK 17、Maven 与 Spring Boot 4.1.2。新建目录并保存 `pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <parent>
        <groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-parent</artifactId>
        <version>4.1.2</version><relativePath/>
    </parent>
    <groupId>learn.example</groupId><artifactId>wrapper-response</artifactId><version>1.0</version>
    <properties><java.version>17</java.version></properties>
    <dependencies>
        <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-webmvc</artifactId></dependency>
    </dependencies>
    <build><plugins><plugin><groupId>org.springframework.boot</groupId><artifactId>spring-boot-maven-plugin</artifactId></plugin></plugins></build>
</project>
```

保存 `src/main/java/learn/wrapper/ResponseBodyDemo.java`：

```java
package learn.wrapper;
import java.nio.charset.StandardCharsets;
import java.util.Locale;
import jakarta.servlet.Filter;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.web.servlet.FilterRegistrationBean;
import org.springframework.context.annotation.Bean;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.util.ContentCachingResponseWrapper;
@SpringBootApplication
@RestController
public class ResponseBodyDemo {
    private static final Logger logger = LoggerFactory.getLogger(ResponseBodyDemo.class);
    @Bean FilterRegistrationBean<Filter> responseFilter() {
        Filter filter = (request, response, chain) -> {
            /* ========================================================================
             * 步骤1：包装并处理响应正文
             * 数据源：/word 的固定 UTF-8 文本响应
             * 操作：1) 缓存下游输出 2) 转换后复制回原响应
             * ======================================================================== */
            logger.info("开始处理响应体");
            try {
                // 1.1 包装响应，让下游先写入缓存
                ContentCachingResponseWrapper wrapped = new ContentCachingResponseWrapper((HttpServletResponse) response);
                chain.doFilter(request, wrapped);
                // 1.2 仅为演示转换已知的短文本，并写回原始响应
                String body = new String(wrapped.getContentAsByteArray(), StandardCharsets.UTF_8);
                byte[] converted = body.toUpperCase(Locale.ROOT).getBytes(StandardCharsets.UTF_8);
                wrapped.resetBuffer();
                wrapped.getOutputStream().write(converted);
                wrapped.copyBodyToResponse();
            } finally {
                logger.info("响应体处理结束");
            }
        };
        FilterRegistrationBean<Filter> registration = new FilterRegistrationBean<>(filter);
        registration.addUrlPatterns("/word");
        return registration;
    }
    @GetMapping(value = "/word", produces = "text/plain;charset=UTF-8")
    public String word() { return "hello"; }
    public static void main(String[] args) {
        /* ========================================================================
         * 步骤1：启动响应包装示例
         * 数据源：Boot 配置与过滤器注册信息
         * 操作：1) 启动容器 2) 提供本地测试接口
         * ======================================================================== */
        logger.info("开始启动响应包装示例");
        // 1.1 启动嵌入式 Web 服务
        SpringApplication.run(ResponseBodyDemo.class, args);
        logger.info("响应包装示例启动完成");
    }
}
```

## 本机验证

先确认 `java -version` 和 `mvn -v` 都使用 JDK 17 或以上。工程目录中运行：

```powershell
mvn package
java -jar target/wrapper-response-1.0.jar --server.address=127.0.0.1 --server.port=8080
```

另开 PowerShell：

```powershell
curl.exe -i http://127.0.0.1:8080/word
```

应收到 HTTP 200，正文为 `HELLO`；下游原本返回的是 `hello`。结束后在服务窗口按 `Ctrl+C`；端口占用时同步修改请求地址。

## 正文、编码和提交

包装器先缓存下游输出；例子按事先约定的 UTF-8 解码并重新编码，使用 `Locale.ROOT` 避免依赖默认语言环境。下游抛异常时异常继续传播，不能把一份不完整缓存当成成功响应。

这是受控教学示例，不适合直接套到所有响应。大文件、流式响应、服务端事件、压缩、HEAD、不同编码、异常响应和异步分发都需要专门处理；缓存整份正文会占用内存，修改正文后还要保证内容长度、编码和其他相关头部一致。生产项目优先使用框架内建且符合需求的机制。

## 动手与自查

1. 暂时删除 `copyBodyToResponse()`，观察客户端收到什么。
2. 将 `/word` 返回值改为其他 ASCII 文本，验证转换和实际响应长度。
3. 为什么把这个过滤器直接应用到大文件下载或流式接口有风险？
