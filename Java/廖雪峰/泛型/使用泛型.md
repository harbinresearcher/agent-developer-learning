# 使用泛型

> **重要程度：高**｜**手练：需要**
> **重点**：声明与创建泛型对象；理解类型推断、包装类型和类型不变性。

## 从一行声明开始

`List<String> names = new ArrayList<>();` 可以分成两部分看：左边声明变量按 `List<String>` 接口使用；右边创建 `ArrayList` 对象。右边的 `<>` 让编译器根据上下文推断参数类型，不代表泛型参数是空的。

写入 `names.add("小明")` 时传入的是字符串；`names.get(0)` 的结果按 `String` 使用。完整可运行代码见 [[什么是泛型]]。

## 使用时最常见的三个疑问

**为什么整数列表写 `List<Integer>`？** 泛型实参使用引用类型。`int` 是基本类型，`Integer` 是包装类；自动装箱和拆箱让两者在一些场合自动转换。

**包装类型就不会出错吗？** 不是。`Integer` 可以为 `null`；拆箱成 `int` 时如果值为 `null`，会抛 `NullPointerException`。数据来自外部时，仍要定义缺失值如何处理。

**`List<Integer>` 能直接赋给 `List<Number>` 吗？** 不能。假如可以，后者就可能加入一个 `Double`，破坏前者“元素按 Integer 使用”的约束。需要读取不同数字类型列表时，使用上界通配符；见 [[extends通配符]]。

## 工作中注意

- 新代码尽量写明泛型参数；原始类型 `List` 会削弱编译期检查。
- 泛型检查不等于业务校验，也不能保证对象深度不可变。
- 接口类型声明有助于降低对具体实现的依赖，但应确认所选实现的顺序、并发和 null 规则。

## 手练与自测

1. 建立 `List<Integer>`，加入几个整数并计算总和；再测试 null 拆箱。
2. 试把 `List<Integer>` 赋给 `List<Number>`。阅读编译错误，再用通配符表达只读需求。
3. `new ArrayList<>()` 的 `<>` 是什么意思？

**答案要点**：① 对 null 拆箱会抛 `NullPointerException`。② 两种参数化类型没有这种子类型关系。③ 编译器根据上下文推断类型参数。
