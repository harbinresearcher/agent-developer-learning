# 泛型和反射

> **重要程度：中**｜**手练：建议**
> **重点**：区分编译期泛型检查与运行时 Class；理解字段声明的泛型信息；会用 `Class<T>` 显式传递类型。

## 这篇解决什么问题

看到 `List<String>`，自然会想：运行时能不能问这个列表：“你装的是不是 `String`？”

**通常不能从列表对象本身得到这个答案。** 但是，如果某个字段声明为 `List<String>`，反射可以读取这个字段的**声明类型**。这两个结论并不矛盾：一个查询对象的运行时类，另一个查询类定义中保留的类型声明。

先补前置知识：`Class` 表示运行时类型信息；`Field` 表示类中声明的字段。泛型与擦除的基本规则见 [[擦拭法]]。

## 先看例子：两个列表是不是同一种类

假设创建两个对象：一个用 `List<String>` 接收，另一个用 `List<Integer>` 接收，实际都用 `new ArrayList<>()` 创建。调用它们的 `getClass()`，得到的都是 `ArrayList` 对应的 `Class` 对象。

这里的 `String` 和 `Integer` 帮助编译器检查代码；Java 不会因为这两个类型参数分别创建两个 `ArrayList` 类。**从 `getClass()` 不能推断列表里声明的元素类型，也不能保证列表里的数据未受原始类型等不安全操作影响。**

## 为什么会这样：类型擦除

Java 编译器会对泛型代码做类型擦除。没有上界的类型参数通常按 `Object` 处理；有上界时使用相应擦除后的上界。编译器还会在需要的地方插入类型转换，并可能生成桥接方法。

因此：

- `ArrayList<String>` 和 `ArrayList<Integer>` 不是两个独立的运行时类。
- 不能写 `List<String>.class`；`List.class` 代表 `List` 本身，不携带 `String`。
- 一般不能写 `new T()`，因为 `T` 不直接提供一个运行时可调用的构造器。
- 不能把运行时 `Class` 检查当成验证 `List<String>` 中每个元素类型的手段。

类型擦除不是“所有泛型信息从 class 文件中消失”。**声明中保留的泛型签名**可以提供给反射读取，但能读到什么取决于具体声明。

## 完整例子：对象类型、字段声明、显式类型

将下面代码保存为 `GenericReflectionDemo.java`。在文件所在目录执行：

`javac -encoding UTF-8 GenericReflectionDemo.java`

`java GenericReflectionDemo`

示例只依赖 JDK，按 Java 11 语法编写。代码使用 JDK 自带日志；日志时间和显示格式因环境而异。

```java
import java.lang.reflect.Field;
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.util.ArrayList;
import java.util.List;
import java.util.logging.Logger;

public class GenericReflectionDemo {
    private static final Logger logger = Logger.getLogger(GenericReflectionDemo.class.getName());

    public static void main(String[] args) throws ReflectiveOperationException {
        /*
         * ========================================================================
         * 步骤1：比较对象的运行时类
         * ========================================================================
         * 目标：判断不同类型参数是否对应不同的 Class。
         * 数据源：字符串列表和整数列表。
         * 操作：
         * 1) 创建两个 ArrayList 实例。
         * 2) 比较它们的 Class 对象。
         */
        logger.info("开始比较列表的运行时类型");
        // 1.1 创建类型参数不同的列表
        List<String> names = new ArrayList<>();
        List<Integer> scores = new ArrayList<>();
        // 1.2 比较实例的运行时类
        System.out.println("运行时类相同: " + (names.getClass() == scores.getClass()));
        logger.info("列表运行时类型比较完成");

        /*
         * ========================================================================
         * 步骤2：读取字段的声明类型
         * ========================================================================
         * 目标：区分字段的原始类型和泛型声明信息。
         * 数据源：Example.names 字段的类声明。
         * 操作：
         * 1) 获取字段及其两种类型信息。
         * 2) 检查并读取泛型类型参数。
         */
        logger.info("开始读取字段的泛型声明");
        // 2.1 获取字段与声明类型
        Field field = Example.class.getDeclaredField("names");
        Type declaredType = field.getGenericType();
        System.out.println("字段原始类型: " + field.getType().getTypeName());
        // 2.2 读取参数化类型中的实际类型参数
        if (declaredType instanceof ParameterizedType) {
            ParameterizedType parameterized = (ParameterizedType) declaredType;
            System.out.println("字段类型参数: " + parameterized.getActualTypeArguments()[0].getTypeName());
        }
        logger.info("字段泛型声明读取完成");

        /*
         * ========================================================================
         * 步骤3：显式传入类型并创建对象
         * ========================================================================
         * 目标：通过调用者提供的 Class 获取构造器。
         * 数据源：Person.class。
         * 操作：
         * 1) 获取可访问的无参构造器。
         * 2) 创建对象并读取其类型。
         */
        logger.info("开始根据显式类型创建对象");
        // 3.1 传入 Person 的类型令牌并创建对象
        Class<Person> type = Person.class;
        Person person = type.getDeclaredConstructor().newInstance();
        // 3.2 输出实际创建的类型
        System.out.println("创建的类型: " + person.getClass().getSimpleName());
        logger.info("对象创建完成");
    }

    static class Example {
        List<String> names;
    }

    public static class Person {
        public Person() {
        }
    }
}
```

标准输出应包含：

```text
运行时类相同: true
字段原始类型: java.util.List
字段类型参数: java.lang.String
创建的类型: Person
```

### 第一步：为什么结果是 `true`

`names` 和 `scores` 的声明分别带有 `String` 与 `Integer`，但两个对象都是 `ArrayList`。比较 `getClass()` 是比较它们的**运行时类**，并没有读取变量声明中的类型参数。

### 第二步：为什么又能读出 `String`

`Example` 类中明确声明了 `List<String> names`。`getDeclaredField("names")` 找到的是**字段声明**。

- `field.getType()` 返回字段的原始类：`List`。
- `field.getGenericType()` 返回描述声明类型的 `Type`。本例声明是 `List<String>`，因此结果实现了 `ParameterizedType`。
- `getActualTypeArguments()[0]` 读取第一个类型参数，本例得到 `String`。

注意：`getGenericType()` 的结果不一定是 `ParameterizedType`。例如字段直接声明为 `String` 时，结果可以是 `Class`；如果声明用的是类型变量，还可能得到 `TypeVariable`。所以先用 `instanceof` 判断，再转换。

这段代码读到的是**字段声明写了什么**，并不是逐个检查列表元素的实际类型。一个对象被多个不同声明的引用指向时，也不会因此改变它的运行时类。

### 第三步：为什么 `Class<T>` 有用

`Class<Person>` 表示一个与 `Person` 类型对应的 `Class` 对象。调用方把 `Person.class` 显式交给代码后，代码才能按该 `Class` 获取构造器并创建实例。

`getDeclaredConstructor().newInstance()` 在本例中使用可访问的无参构造器。实际代码可能遇到没有匹配构造器、构造器不可访问或构造器本身抛异常；示例把这些反射异常交给调用方处理，并不表示这些情况不存在。

`Class<T>` 也有边界：`String.class` 可以表达 `String`，但 `List.class` 无法单独表达 `List<String>`。框架需要保留带参数的类型时，可能使用 `Type`、`ParameterizedType` 或框架提供的类型描述对象；具体写法应按框架文档。

## 实际开发什么时候用

反射常出现在框架、序列化、依赖注入或通用工具中：程序需要根据声明读取字段类型或动态创建对象。普通业务逻辑如果已经知道类型，优先直接调用构造器和方法，类型检查更明确，也更容易调试。

读取泛型声明也不能代替外部输入校验。比如 JSON 解析成对象后，仍需检查必填字段、数据范围和业务约束。

## 手练与自测

1. 把 `Example.names` 改成 `List<Integer>`。先预测第二步输出，再运行；第一步是否会改变？
2. 把字段改成普通 `String`。`getType()` 和 `getGenericType()` 分别表示什么？为什么代码不应无条件强转为 `ParameterizedType`？
3. 删除 `Person` 的无参构造器并添加有参构造器。第三步会发生什么？如何按所需参数获取构造器？
4. 为什么读取到字段声明是 `List<String>`，仍不能证明列表中的每个运行时元素都是字符串？

**答案要点**：① 字段参数变成 `Integer`；第一步仍比较两个 `ArrayList` 的运行时类。② 普通 `String` 字段的泛型类型通常也是 `Class`，不是 `ParameterizedType`。③ 查找无参构造器会失败，需要按实际参数类型查找可访问的构造器。④ 声明信息不等于逐个检查对象内容；原始类型或其他不安全操作可能绕过编译期检查。
