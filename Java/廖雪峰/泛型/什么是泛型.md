# 什么是泛型

> **重要程度：高**｜**手练：需要**
> **重点**：理解 `List<String>` 的含义；看懂编译期类型检查；区分类型安全和业务校验。

## 先看问题：放进去的东西怎么保证类型一致

假设要保存一组姓名。希望只能放字符串，取出来后也能直接作为字符串使用。如果集合对元素类型没有约束，误放一个整数，程序可能直到取出并强制转换时才发现问题。

泛型允许把类型写进声明：`List<String>` 表示这份列表按“元素是 `String`”的约定使用。编译器会检查绝大多数正常写法：添加 `String` 可以；直接添加 `Integer` 会报编译错误。

尖括号中的 `String` 是**类型参数的实际类型**。`List` 是泛型接口，`List<String>` 是带具体类型参数的类型。它们不是“一个列表名字”和“一个元素名字”。

## 完整例子

保存为 `GenericListDemo.java`，在该目录下执行 `javac -encoding UTF-8 GenericListDemo.java`，再执行 `java GenericListDemo`。代码使用 JDK 自带日志，不需安装依赖。

```java
import java.util.ArrayList;
import java.util.List;
import java.util.logging.Logger;

public class GenericListDemo {
    private static final Logger logger = Logger.getLogger(GenericListDemo.class.getName());

    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：使用泛型集合保存字符串
         * ========================================================================
         * 目标：观察编译期约束和读取结果。
         * 数据源：两条姓名。
         * 操作：
         * 1) 创建只能按字符串使用的列表。
         * 2) 读取第一个元素并输出。
         */
        logger.info("开始使用泛型列表");
        // 1.1 创建并填充字符串列表
        List<String> names = new ArrayList<>();
        names.add("小明");
        names.add("小红");
        // 1.2 读取并输出第一个字符串
        String firstName = names.get(0);
        System.out.println("第一个姓名: " + firstName);
        logger.info("泛型列表读取完成");
    }
}
```

标准输出为：`第一个姓名: 小明`。日志显示在标准错误流，时间和格式可能不同。

### 代码做了什么

1. `List<String> names` 声明一个按字符串使用的列表；右侧 `new ArrayList<>()` 创建实际对象，菱形中的类型由上下文推断。
2. `names.add("小明")` 放入字符串。若尝试 `names.add(123)`，编译器会拒绝，因为 `123` 的类型不符合 `String`。
3. `names.get(0)` 得到的结果在代码中按 `String` 使用，因此可以赋给 `String firstName`；无需在调用处手动写强制转换。

把列表中的名字改成空字符串仍能编译：空字符串确实是 `String`，但可能不符合业务要求。**泛型负责类型约束，不负责判断姓名、年龄或金额是否符合业务规则。**

## 与不写泛型的区别

写成原始类型 `List names` 时，编译器无法像 `List<String>` 一样保证元素类型，通常会给出未检查操作警告。取值时也可能需要转换；如果放入的实际对象类型不匹配，转换时会抛 `ClassCastException`。新代码通常避免使用原始类型，维护老项目时不能只忽略警告。

注意两点：

- 泛型类型参数使用引用类型，不能写 `List<int>`；整数列表写 `List<Integer>`。
- `List<String>` 仍可能包含 `null`，泛型本身不代表值必定非空。实际约束还取决于集合实现和业务校验。

## 自测与手练

1. 将 `names.add("小明")` 改成 `names.add(123)`，编译会发生什么？为什么？
2. 创建整数列表时，为什么写 `List<Integer>` 而不是 `List<int>`？
3. `List<String>` 能否保证姓名不为空字符串？能否保证每个值不为 `null`？

**答案要点**：① 编译失败，整数不符合元素类型。② 泛型参数使用引用类型，`Integer` 是 `int` 的包装类型。③ 不能；空字符串和 `null` 是否允许要由业务或具体集合规则处理。
