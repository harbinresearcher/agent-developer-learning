# 泛型的类型擦除

> **重要程度：高**｜**手练：建议**
> **重点**：知道编译器做了什么；理解运行时限制；区分对象类型与声明元数据。

## 问题：为什么两个列表的 Class 一样

创建 `ArrayList<String>` 和 `ArrayList<Integer>` 后，分别调用 `getClass()`，两者通常得到同一个 `ArrayList` 的 Class。Java 不会为每个类型参数生成一个新的 `ArrayList` 类。

编译器仍然会在编译时检查泛型，必要时插入转换；类型参数在运行时代码中按擦除规则处理。没有上界的 `T` 擦除为 `Object`；有上界时按规则擦除为相应上界。编译器还可能生成桥接方法，以保持泛型继承下的多态。

完整可运行演示：[[泛型和反射]]。

## 对写代码有什么影响

- **不能直接 `new T()`**：`T` 本身不能提供可供调用的具体构造器。确实需要动态创建时，可按需求传入工厂或 `Class<T>`；前者不必假设类型一定有可访问无参构造器。
- **不能写 `List<String>.class`**：可以取得 `List.class`，但它不能单独表达 `String` 参数。
- **不能一般性地通过 `instanceof List<String>` 判断元素类型**：运行时类型检查不能替代逐项验证。
- **可能出现擦除后的签名冲突**：两个方法仅以不同泛型参数区分，而擦除后参数签名相同时，不能作为两个合法重载。

## 擦除了，为什么反射还能读到泛型

不要把擦除理解成“任何地方的类型信息都不存在”。类、字段、方法或父类的声明可能保留泛型签名，反射可以读取这些**声明元数据**。

例如，字段声明为 `List<String> names`，可以从该字段的 `getGenericType()` 读取参数化类型；但这不证明任何一个列表对象实际装的元素都满足类型，也不意味着每个对象都记住它最初被哪个参数化类型引用。

## 手练与自测

1. 运行 [[泛型和反射]] 的例子，比较两个列表的 Class。
2. 为什么不能直接写 `new T()`？需要创建对象时可以传入什么？
3. 为什么字段反射可能读到 `String`，但列表对象的 `getClass()` 不能给出这个答案？

**答案要点**：① 两个对象使用同一个原始类。② 类型参数不能直接提供可用构造器，可显式传入工厂或类型信息。③ 前者读取字段声明，后者读取对象的运行时类。
