# 浮点数运算

> **重要程度：高**｜**手练：需要**
> **重点**：浮点表示误差、类型转换、比较边界和金额计算。

## 为什么 0.1 + 0.2 不一定等于 0.3

Java 的 `float`、`double` 使用二进制浮点表示；不少十进制小数无法精确表示，因此计算结果可能有舍入误差。运行 [[整数运算]] 中的 `ArithmeticDemo`，最后一行会看到 `0.30000000000000004`。

`5.0 / 2` 的结果是 2.5，因为参与运算的类型使结果按浮点数计算；`5 / 2` 是整数除法，结果是 2。浮点数还存在正负无穷和 NaN 等特殊值，相关行为不能简单套用整数规则。

## 如何比较

是否允许误差要看业务。对于近似计算，可按问题规模设计绝对误差或相对误差，并明确 NaN、无穷等边界。不要把任意固定的 `0.00001` 当作所有场景都正确的通用答案。

金额、账务等需要精确十进制规则的场景，通常使用 `BigDecimal`，从适当的十进制字符串构造，并明确精度与舍入。完整例子见 [[BigDecimal]]。

## 转为整数时注意

浮点数强制转换为整数会丢弃小数部分；对超范围值以及 NaN 有明确的 Java 转换规则，不是“所有超范围值都变最大值”。转换前应按业务判断范围和合法性。
