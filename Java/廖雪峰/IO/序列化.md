# 序列化

> **重要程度：高**｜**手练：需要**
> **重点**：Serializable、transient、版本和反序列化风险。

## 解决什么问题

Java 原生对象序列化可以把实现 `Serializable` 的对象图写入字节流，再由 `ObjectInputStream` 还原。它与 JSON 等通用数据格式不同，依赖 Java 类型和序列化规则。理解旧项目时可能遇到，但不应把不可信字节直接交给原生反序列化。

## 完整例子

保存为 `SerializationDemo.java`，编译运行；日志写到标准错误。示例只读取当前程序刚创建的内存数据，不从网络或用户文件接收对象。

```java
import java.io.ByteArrayInputStream;
import java.io.ByteArrayOutputStream;
import java.io.ObjectInputStream;
import java.io.ObjectOutputStream;
import java.io.Serializable;
import java.util.logging.Logger;
public class SerializationDemo {
    private static final Logger logger = Logger.getLogger(SerializationDemo.class.getName());
    public static void main(String[] args) throws Exception {
        /*
         * ========================================================================
         * 步骤1：序列化可信示例对象
         * ========================================================================
         * 数据源：当前程序创建的对象和内存字节
         * 操作：
         * 1) 将对象写入内存流
         * 2) 从本程序产生的字节读取并观察字段
         */
        logger.info("开始处理示例对象");
        // 1.1 创建对象并写入内存
        ByteArrayOutputStream buffer = new ByteArrayOutputStream();
        try (ObjectOutputStream out = new ObjectOutputStream(buffer)) {
            out.writeObject(new User("Ada", "secret"));
        }
        // 1.2 仅读取本程序刚刚产生的可信字节
        try (ObjectInputStream in = new ObjectInputStream(new ByteArrayInputStream(buffer.toByteArray()))) {
            User restored = (User) in.readObject();
            System.out.println("name=" + restored.name);
            System.out.println("token=" + restored.token);
        }
        logger.info("示例对象处理完成");
    }
    static class User implements Serializable {
        private static final long serialVersionUID = 1L;
        private final String name;
        private transient String token;
        User(String name, String token) { this.name = name; this.token = token; }
    }
}
```

标准输出：

```text
name=Ada
token=null
```

## 执行过程

`User` 实现 Serializable，`ObjectOutputStream.writeObject` 将对象写到内存。`name` 是普通实例字段，按默认序列化规则保存；`token` 标记为 transient，不由默认字段序列化写入。读取回来后 name 为 Ada，token 是 null。输出的 `secret` 只是演示字符串，真实系统仍不应把令牌写入日志或随意放在对象序列化数据中。

`serialVersionUID` 是版本兼容检查的一部分：它一致不保证任意字段变更都安全或语义兼容，升级需要测试真实数据。static 字段属于类，不是对象的普通实例字段。定制 `writeObject` 等机制可能改变默认行为，不能认为 transient 就能阻止所有自定义代码泄露数据。

## 安全与工作用法

反序列化可能触发类加载及对象重建相关逻辑；不可信输入会带来严重风险。系统边界通常优先选择结构明确的数据格式，并做字段、类型、大小和业务校验。若因兼容性必须使用原生序列化，应限制输入来源与大小、配置合适的 `ObjectInputFilter`，并评估可用类型与依赖；过滤并不自动消除所有风险。

资源需关闭，读取时可能出现类型不匹配、数据损坏、类版本不兼容等异常。不要对来源不明的文件或网络字节照搬本例。

## 手练与答案

把 `token` 的 transient 去掉：默认序列化会保存该字段，读回后输出 token=secret；这展示了为什么敏感字段需要专门设计，而不是推荐存储秘密。更改 name 后重新序列化并读取，读回值对应写入时的对象状态。
