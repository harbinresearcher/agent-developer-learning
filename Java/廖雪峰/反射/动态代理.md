# 动态代理

> **重要程度：中**｜**手练：建议**
> **重点**：接口代理、InvocationHandler、返回值和异常。

## 解决什么问题

需要在调用业务方法前后增加共同逻辑，例如记录调用或检查权限时，代理可把这些逻辑放在调用入口。JDK 动态代理按接口生成代理对象，把接口方法调用转交给 `InvocationHandler`；它不直接代理没有实现接口的普通类。

## 完整例子

保存为 `ProxyDemo.java`，编译运行；日志写到标准错误。

```java
import java.lang.reflect.InvocationTargetException;
import java.lang.reflect.Proxy;
import java.util.logging.Logger;
public class ProxyDemo {
    private static final Logger logger = Logger.getLogger(ProxyDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：创建和调用接口代理
         * ========================================================================
         * 数据源：通知接口和真实实现
         * 操作：
         * 1) 创建代理并委托真实对象
         * 2) 调用接口方法并读取结果
         */
        logger.info("开始创建通知代理");
        // 1.1 创建真实对象及其接口代理
        Notifier target = new EmailNotifier();
        Notifier proxy = (Notifier) Proxy.newProxyInstance(
                Notifier.class.getClassLoader(), new Class<?>[]{Notifier.class},
                (instance, method, arguments) -> {
                    // 1.2 在真实调用前后附加日志，并传递目标异常
                    logger.info("开始调用通知方法");
                    try {
                        Object result = method.invoke(target, arguments);
                        logger.info("通知方法调用完成");
                        return result;
                    } catch (InvocationTargetException ex) {
                        throw ex.getCause();
                    }
                });
        // 1.3 调用代理接口
        System.out.println(proxy.send("Ada"));
        logger.info("通知代理演示完成");
    }
    public interface Notifier { String send(String name); }
    public static class EmailNotifier implements Notifier {
        public String send(String name) { return "邮件给 " + name; }
    }
}
```

标准输出：

```text
邮件给 Ada
```

## 执行过程

`target` 是真实的邮件通知对象。`Proxy.newProxyInstance` 接收类加载器、需要实现的接口数组和处理器，返回代理对象；这里把结果转换为 Notifier。调用 `proxy.send("Ada")` 时，处理器获得方法对象与参数数组，先记录日志，再用 `method.invoke(target, arguments)` 委托给真实对象，最后返回真实结果。

目标方法抛异常时，`Method.invoke` 用 `InvocationTargetException` 包装；示例将 cause 重新抛出，避免把反射包装类型当成业务异常。代理接口的受检异常声明仍影响调用边界；不符合接口声明的受检异常可能被包装为 `UndeclaredThrowableException`，应按接口契约处理。

## 关键边界

动态代理实现的是指定接口，不会自动为任意类创建子类。`equals`、`hashCode`、`toString` 等 Object 方法也可能进入处理器，生产代码应明确身份和委托策略。`arguments` 在无参数方法中可能为 null；不能无条件读取 `arguments[0]`。示例只处理一个普通接口调用，不展示完整 Object 方法策略。

方法调用如果绕过代理对象，例如真实对象内部直接调用自己的其他方法，通常不会再次经过这个代理处理器。框架的 AOP、事务等是否生效取决于具体代理与调用路径，不能只看注解。

## 工作中怎么用

代理适合为多个实现提供一致的横切行为，但异常、返回值、资源和身份语义必须与接口约定一致。不要记录敏感参数；优先使用框架提供的成熟机制，并为代理调用、内部调用和异常路径写可观察的测试。

## 手练与答案

将调用改为 `proxy.send("Bo")`：标准输出 `邮件给 Bo`，日志仍经过处理器。若直接调用 `target.send("Ada")`，不会经过这个代理处理器中的前后日志。
