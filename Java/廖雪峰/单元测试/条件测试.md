# 条件测试

> **重要程度：高**｜**手练：需要**
> **重点**：条件启用、跳过与通过的区别。

## 解决什么问题

某些测试只能在特定操作系统、JDK 或显式配置下运行。条件注解可以让测试在条件不满足时被跳过，但跳过不等于通过，也不证明相关功能可用。

## 完整例子

保存为 `ConditionalTest.java`。

```java
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.condition.EnabledIfSystemProperty;
import java.util.logging.Logger;
import static org.junit.jupiter.api.Assertions.assertTrue;

class ConditionalTest {
    private static final Logger logger = Logger.getLogger(ConditionalTest.class.getName());
    @Test
    void alwaysRuns() {
        /*
         * ========================================================================
         * 步骤1：验证普通测试
         * ========================================================================
         * 数据源：固定布尔条件
         * 操作：
         * 1) 读取固定值
         * 2) 断言为真
         */
        logger.info("开始普通测试");
        // 1.1 检查固定条件
        assertTrue(true);
        logger.info("普通测试完成");
    }
    @Test
    @EnabledIfSystemProperty(named = "notes.mode", matches = "test")
    void runsOnlyWhenConfigured() {
        /*
         * ========================================================================
         * 步骤1：验证条件启用后的配置
         * ========================================================================
         * 数据源：notes.mode 系统属性
         * 操作：
         * 1) 读取启动属性
         * 2) 断言值符合启用条件
         */
        logger.info("开始条件测试");
        // 1.1 读取并核对启动参数
        assertTrue("test".equals(System.getProperty("notes.mode")));
        logger.info("条件测试完成");
    }
}
```

## 运行方式

本例使用 JUnit Platform Console Standalone 1.14.4（包含 JUnit Jupiter），可在 Java 11 运行。将 [standalone jar](https://repo.maven.apache.org/maven2/org/junit/platform/junit-platform-console-standalone/1.14.4/junit-platform-console-standalone-1.14.4.jar) 放在源码所在目录，然后运行：

```text
javac -encoding UTF-8 -cp junit-platform-console-standalone-1.14.4.jar ConditionalTest.java
java -jar junit-platform-console-standalone-1.14.4.jar execute --class-path . --select-class ConditionalTest --details summary --disable-ansi-colors
```

本示例已用 Java 11 和上述 jar 验证。JUnit 5 系列可在 Java 11 上运行；JUnit 6 要求 Java 17 或更高，项目应按 JDK 和构建配置选兼容版本。日志写到标准错误，测试报告格式可能因版本而异。

启用条件测试时，将第二条命令开头改为 `java -Dnotes.mode=test -jar`，其余参数不变。

默认运行结果：1 个测试成功、1 个跳过、0 个失败。

## 执行过程

不设置 `notes.mode` 时，普通测试运行，条件测试被跳过。命令行运行时若在 `-jar` 前加 `-Dnotes.mode=test`，条件满足，两条测试都会运行并通过。系统属性是在启动 JVM 时设置的，不是普通环境变量；`matches` 使用注解约定的正则匹配。

## 工作中怎么用

针对真实平台要求使用条件测试，并在 CI 中明确在哪些环境执行。不要用跳过掩盖错误；报告时区分 discovered、skipped、started、successful 和 failed。涉及外部服务时还要避免把密钥写入启动参数或日志。

JUnit 的 `@Disabled` 可明确禁用测试，条件注解还可按系统属性、环境变量、操作系统或 JRE 条件启用；具体规则以项目使用的 JUnit 版本为准。

## 手练与答案

默认运行应看到 1 个测试成功、1 个跳过；加入 `-Dnotes.mode=test` 应看到 2 个成功、0 个跳过。若把属性设置为 `prod`，条件测试仍被跳过，并不证明其断言通过。
