# 异常测试

> **重要程度：高**｜**手练：需要**
> **重点**：assertThrows、异常类型和消息、失败路径。

## 解决什么问题

只验证正常返回无法证明错误输入被正确拒绝。`assertThrows` 运行给定代码，并要求它抛出指定类型或其子类型的异常；返回的异常对象可进一步检查消息、错误码或 cause。

## 完整例子

保存为 `ExceptionTest.java`。

```java
import org.junit.jupiter.api.Test;
import java.util.logging.Logger;
import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertThrows;

class ExceptionTest {
    private static final Logger logger = Logger.getLogger(ExceptionTest.class.getName());
    @Test
    void rejectsNegativeQuantity() {
        /*
         * ========================================================================
         * 步骤1：验证负数输入被拒绝
         * ========================================================================
         * 数据源：负数数量
         * 操作：
         * 1) 调用被测方法并捕获预期异常
         * 2) 检查异常消息
         */
        logger.info("开始测试负数数量");
        // 1.1 检查异常类型与稳定消息
        IllegalArgumentException ex = assertThrows(IllegalArgumentException.class, () -> validate(-1));
        assertEquals("数量不能为负", ex.getMessage());
        logger.info("负数数量测试完成");
    }
    @Test
    void acceptsZero() {
        /*
         * ========================================================================
         * 步骤1：验证零值被接受
         * ========================================================================
         * 数据源：数量零
         * 操作：
         * 1) 调用被测方法
         * 2) 断言返回值
         */
        logger.info("开始测试零值数量");
        // 1.1 检查正常返回
        assertEquals(0, validate(0));
        logger.info("零值数量测试完成");
    }
    static int validate(int quantity) {
        if (quantity < 0) throw new IllegalArgumentException("数量不能为负");
        return quantity;
    }
}
```

## 运行方式

本例使用 JUnit Platform Console Standalone 1.14.4（包含 JUnit Jupiter），可在 Java 11 运行。将 [standalone jar](https://repo.maven.apache.org/maven2/org/junit/platform/junit-platform-console-standalone/1.14.4/junit-platform-console-standalone-1.14.4.jar) 放在源码所在目录，然后运行：

```text
javac -encoding UTF-8 -cp junit-platform-console-standalone-1.14.4.jar ExceptionTest.java
java -jar junit-platform-console-standalone-1.14.4.jar execute --class-path . --select-class ExceptionTest --details summary --disable-ansi-colors
```

本示例已用 Java 11 和上述 jar 验证。JUnit 5 系列可在 Java 11 上运行；JUnit 6 要求 Java 17 或更高，项目应按 JDK 和构建配置选兼容版本。日志写到标准错误，测试报告格式可能因版本而异。

默认运行结果：2 个测试成功、0 个跳过、0 个失败。

## 执行过程

负数用例通过 lambda 调用 `validate(-1)`，断言抛 `IllegalArgumentException`，再核对消息。零值用例检查正常边界 `0`。如果没有抛异常或抛出不兼容的异常，第一条测试失败。

`assertThrows` 接受子类型；如果接口必须要求精确的异常类，JUnit 还提供 `assertThrowsExactly`。只检查异常类型不能证明数据没有被错误修改；有状态操作还应核对失败前后状态或数据库事务结果。

## 工作中怎么用

在独立的边界用例里验证空值、非法格式、权限等明确失败路径。只有消息是接口契约、稳定且不含敏感信息时才精确断言消息；否则检查异常类型、错误码或结构化字段更稳妥。

## 手练与答案

移除 `validate` 中抛异常的 if：负数用例失败，零值用例仍通过。将断言类型换成与实际异常无继承关系的类型：异常用例失败。
