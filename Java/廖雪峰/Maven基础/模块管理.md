# 模块管理

> **重要程度：高**｜**手练：需要**
> **重点**：聚合与继承、模块依赖、Reactor 构建顺序和部分构建。

## 解决什么问题

一个仓库可能有多个相关制品，例如公共库和应用。Maven 多模块项目用聚合 POM 列出模块，用依赖声明表达模块之间的关系；父 POM 还能统一配置。**聚合**决定一起构建哪些模块，**继承**决定子项目继承哪些配置，它们是不同概念。

## 完整例子

创建下面的目录；本例无第三方业务依赖。需要 Maven 和 JDK，示例按 Java 11 目标编译。

```text
multi/
├── pom.xml
├── core/
│   ├── pom.xml
│   └── src/main/java/demo/core/Message.java
└── app/
    ├── pom.xml
    └── src/main/java/demo/app/Main.java
```

`根目录 pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>
  <groupId>example.notes</groupId><artifactId>parent</artifactId><version>1.0.0</version><packaging>pom</packaging>
  <modules><module>core</module><module>app</module></modules>
  <properties><maven.compiler.release>11</maven.compiler.release><project.build.sourceEncoding>UTF-8</project.build.sourceEncoding></properties>
  <build><pluginManagement><plugins>
    <plugin><groupId>org.apache.maven.plugins</groupId><artifactId>maven-compiler-plugin</artifactId><version>3.14.1</version></plugin>
    <plugin><groupId>org.apache.maven.plugins</groupId><artifactId>maven-surefire-plugin</artifactId><version>3.5.4</version></plugin>
  </plugins></pluginManagement></build>
</project>
```

`core/pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"><modelVersion>4.0.0</modelVersion>
  <parent><groupId>example.notes</groupId><artifactId>parent</artifactId><version>1.0.0</version></parent>
  <artifactId>core</artifactId>
</project>
```

`app/pom.xml`：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"><modelVersion>4.0.0</modelVersion>
  <parent><groupId>example.notes</groupId><artifactId>parent</artifactId><version>1.0.0</version></parent>
  <artifactId>app</artifactId>
  <dependencies><dependency><groupId>example.notes</groupId><artifactId>core</artifactId><version>1.0.0</version></dependency></dependencies>
</project>
```

`core/src/main/java/demo/core/Message.java`：

```java
package demo.core;
import java.util.logging.Logger;
public class Message {
    private static final Logger logger = Logger.getLogger(Message.class.getName());
    public static String text() {
        /*
         * ========================================================================
         * 步骤1：生成模块示例文本
         * ========================================================================
         * 数据源：固定演示字符串
         * 操作：
         * 1) 准备文本
         * 2) 返回给调用者
         */
        logger.info("开始准备文本");
        // 1.1 获取固定文本
        String result = "hello";
        logger.info("文本准备完成");
        return result;
    }
}
```

`app/src/main/java/demo/app/Main.java`：

```java
package demo.app;
import demo.core.Message;
import java.util.logging.Logger;
public class Main {
    private static final Logger logger = Logger.getLogger(Main.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：使用 core 模块
         * ========================================================================
         * 数据源：core 模块的消息
         * 操作：
         * 1) 调用公开方法
         * 2) 输出返回的文本
         */
        logger.info("开始读取消息");
        // 1.1 读取并输出消息
        System.out.println(Message.text());
        logger.info("消息读取完成");
    }
}
```

在根目录运行 `mvn verify`。要只选择 app 及它依赖的项目，可运行 `mvn -pl app -am verify`。构建成功后，在 Windows PowerShell 中运行：

```text
java -cp "app/target/classes;core/target/classes" demo.app.Main
```

标准输出是 `hello`，日志写到标准错误。本例已用 Maven 3.9.16、JDK 17 和 Java 11 编译目标验证两个构建命令与运行；首次构建仍可能需要下载插件。JAR 未配置 Main-Class，因此这里使用类路径启动，不声称可直接 `java -jar`。

## 执行过程

根 POM 的 packaging 为 `pom`，`modules` 列出 core 和 app。两个子模块通过 `<parent>` 继承公共坐标和编译配置；app 还通过 `<dependency>` 明确依赖 core。Reactor 按模块依赖关系确定构建顺序，先构建 core，再构建 app；仅在 `modules` 中列出 core 并不会自动让 app 获得它作为依赖。

`-pl app` 选择 app；`-am` 同时构建所需的上游模块。若只单独构建 app 而没有可用的 core 制品，依赖解析可能失败；具体还取决于本地或远程仓库中是否已有相应版本。

## 工作中怎么用

按清晰职责划分模块，而非为了模块数量而拆分。父 POM 中的 `dependencyManagement` 管理版本等默认配置，不会自动让子模块引入所有依赖；`pluginManagement` 也主要管理插件配置，插件是否执行还取决于生命周期绑定或显式配置。检查模块循环依赖、版本一致性和实际构建范围。

## 手练与答案

1. 删除 app 中对 core 的 dependency：即使根 POM 仍列出两个模块，app 源码也无法解析 `demo.core.Message`。
2. 将命令改成 `mvn -pl app -am verify`：Reactor 同时构建 app 所需的 core；它不意味着会运行所有未选模块的检查。
