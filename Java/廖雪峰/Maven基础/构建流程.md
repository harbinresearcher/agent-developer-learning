# 构建流程

> **重要程度：高**｜**手练：需要**
> **重点**：生命周期、phase 与 goal、clean/test/package/verify/install 的区别。

## 先理解：阶段是顺序，插件做具体事

Maven 的默认生命周期按阶段组织构建，例如 `validate → compile → test → package → verify → install → deploy`。执行某个阶段时，会先经过同一生命周期中排在它之前的阶段；实际做什么取决于项目类型、默认绑定及插件配置。`clean` 属于独立生命周期，不是默认生命周期的第一个阶段。

## 可复现练习

先按 [[Maven介绍]] 创建其中的完整 calculator 示例，在包含 pom.xml 的目录依次运行：

```text
mvn clean verify
mvn test
mvn package
```

`clean verify` 会清理该项目的构建输出并运行到 verify；示例的 JUnit 测试应显示 1 条运行、0 条失败，并生成 `target/calculator-1.0.0.jar`。`test` 运行到测试阶段；`package` 继续到打包阶段。示例已用 Maven 3.9.16、JDK 17 和 Java 11 编译目标验证 `clean verify`；输出与实际项目的插件和测试数量有关。

## 各阶段有什么区别

- `compile`：编译主源码；本身不证明测试通过。
- `test`：按配置运行测试；如果没有测试、测试被跳过或插件未正确配置，阶段成功不等于业务已充分验证。
- `package`：生成 JAR 等包；是否可执行、是否包含依赖取决于项目配置。
- `verify`：运行到验证阶段；只有绑定到该阶段及之前的检查实际执行才有证据。集成测试插件可能需要单独配置。
- `install`：将制品装入本地 Maven 仓库，供本机其他项目按坐标解析；不等于发布到远程。
- `deploy`：将制品部署到配置的目标仓库；可能是远程写操作，需确认目标与权限。

## 工作中怎么判断构建结果

查看实际命令、退出码、测试数量、失败和跳过数量、产物路径及插件日志。`-DskipTests` 常用于跳过测试执行；`maven.test.skip` 等选项与其作用不同，具体取决于插件。跳过测试的成功不能作为测试通过的证据。

`mvn clean` 会删除项目配置的构建输出目录，使用前确认所在项目与构建配置。不要把 `install` 和生产部署混为一谈；网络或依赖下载失败也不能直接推断代码有错。

## 手练与答案

1. 只运行 `mvn compile`：主代码可能已编译，但测试与打包没有因此被证明完成。
2. 运行 `mvn package`：在默认生命周期中此前阶段会先执行，但实际测试是否运行仍要看报告。
3. 在示例中改错测试预期后执行 `mvn verify`：测试阶段失败，构建应以非零状态结束。
