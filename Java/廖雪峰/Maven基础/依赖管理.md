# 依赖管理

> **重要程度：高**｜**手练：需要**
> **重点**：坐标、依赖范围、传递依赖、版本调解和依赖树。

## 解决什么问题

项目需要第三方库时，Maven 根据坐标从仓库解析制品及其传递依赖。依赖声明不仅决定使用什么库，也决定库在哪些构建阶段和类路径中可用。

## 完整例子：查看依赖树

在空目录创建以下 `pom.xml`。它与入门构建示例使用相同坐标、JUnit 测试依赖及插件配置，可单独运行依赖树命令。

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <groupId>example.notes</groupId>
    <artifactId>calculator</artifactId>
    <version>1.0.0</version>
    <properties>
        <maven.compiler.release>11</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>
    <dependencies>
        <dependency>
            <groupId>org.junit.jupiter</groupId>
            <artifactId>junit-jupiter</artifactId>
            <version>5.14.4</version>
            <scope>test</scope>
        </dependency>
    </dependencies>
    <build><plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <version>3.14.1</version>
        </plugin>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-surefire-plugin</artifactId>
            <version>3.5.4</version>
        </plugin>
    </plugins></build>
</project>
```

在 pom 所在目录执行：

```text
mvn org.apache.maven.plugins:maven-dependency-plugin:3.7.0:tree
```

应看到根项目 `example.notes:calculator` 下包含 `org.junit.jupiter:junit-jupiter:5.14.4:test` 及其传递依赖。示例已用 Maven 3.9.16 和隔离本地仓库验证；首次执行需要下载插件与依赖。依赖树不要求项目一定有源码，但不证明业务代码或测试已经编译运行。

## 按顺序理解

`groupId`、`artifactId`、`version` 标识所需制品；`scope=test` 表示本例 JUnit 用于测试，不应假设它会自动成为生产运行所需依赖。JUnit 自己还依赖其他组件，这些是传递依赖；依赖树能帮助查找其来源。

常见范围包括 `compile`、`test`、`runtime`、`provided`，它们在编译、测试、运行和传递时的可见性不同，应按实际需求及 Maven 文档选择。`optional` 和 `exclusions` 也会影响下游，但排除依赖前要确认运行时仍满足需要。

## 版本冲突与工作用法

多个路径引入同一制品的不同版本时，Maven 有依赖调解规则，例如选择较近的声明；同深度等细节以 Maven 版本与实际依赖树为准。`dependencyManagement` 管理依赖的版本等配置，但单独写在其中不等于实际引入该依赖；子项目仍需在 dependencies 中声明所需库。

定期检查依赖树和官方安全公告，核对 JDK、框架与依赖兼容性；不要盲目升级单个传递依赖或把仓库凭据写进 pom。构建仓库和镜像配置可能改变实际下载来源，应检查项目设置。

## 手练与答案

1. 在依赖树中找到 `junit-jupiter`：scope 为 test，且下有其他 JUnit 组件。
2. 将 JUnit 只写到 `dependencyManagement` 而从 `dependencies` 删除：不会仅因管理声明就自动加入项目依赖。
3. 构建找不到依赖时，先核对坐标、仓库、网络和版本，不能直接认定源码有错。
