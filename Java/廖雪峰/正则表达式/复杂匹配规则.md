# 复杂匹配规则

> **重要程度：高**｜**手练：需要**
> **重点**：分支、非捕获分组、可选项。

## 解决什么问题

规则有多个选择或一部分可省略时，可以组合分支和分组。示例匹配 cat 或 dog，并允许词尾带一个 s；它只是演示组合语法，不是完整的自然语言单词识别器。

## 完整例子

保存为 `RegexComplexDemo.java`，编译运行；日志写到标准错误。

```java
import java.util.regex.Matcher;
import java.util.regex.Pattern;
import java.util.logging.Logger;
public class RegexComplexDemo {
    private static final Logger logger = Logger.getLogger(RegexComplexDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：组合多个匹配条件
         * ========================================================================
         * 数据源：程序内的固定模式与文本
         * 操作：
         * 1) 构造正则表达式及匹配器
         * 2) 匹配、读取或替换并输出结果
         */
        logger.info("开始处理文本");
        // 1.1 创建两种单词及可选复数的模式
        Pattern pattern = Pattern.compile("(?:cat|dog)s?");
        Matcher matcher = pattern.matcher("cats and dog");
        // 1.2 依次查找匹配片段
        while (matcher.find()) {
            System.out.println("found=" + matcher.group());
        }
        logger.info("文本处理完成");
    }
}
```

标准输出：

```text
found=cats
found=dog
```

## 执行过程

`(?:cat|dog)` 在 cat 与 dog 之间选择；`?:` 表示非捕获分组，仅用于组织表达式，不生成可读取的捕获组。`s?` 让尾部 s 出现零次或一次。`find()` 依次在输入中找到 cats 和 dog。

本例没有要求单词边界；在更长单词内部也可能找到片段。如果业务需要完整词或完整输入，应明确边界或使用 `matches()`。大小写、Unicode、换行和区域设置也会影响实际规则。

## 组合和性能边界

`|` 的作用范围受分组影响，例如把多个候选放在 `(?:...)` 中可以明确共同的后续部分。`^` 和 `$` 的具体行为受匹配区域、行模式及输入结尾规则影响；验证整个默认区域通常可直接用 `matches()`，不要只靠对锚点的直觉。

避免对不可信的长输入使用含嵌套重复和大量重叠分支的表达式，某些模式可能发生灾难性回溯；限制输入长度并用最坏情况测试。不要用复杂正则替代合适的结构化解析器。

## 手练与答案

输入 `"cat dogs"` 会找到 cat 和 dogs；输入 `"bird"` 不会找到结果。`(?:...)` 不产生捕获组，如需读取某段内容可使用捕获组，见 [[分组匹配]]。
