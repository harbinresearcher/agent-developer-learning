# 非贪婪匹配

> **重要程度：高**｜**手练：需要**
> **重点**：贪婪与非贪婪、终止条件和解析边界。

## 解决什么问题

量词会影响一次匹配覆盖多长文本。贪婪量词通常优先尝试更长范围；非贪婪量词优先尝试更短范围，再根据后续规则需要扩展。最终结果仍取决于整个表达式和匹配方法。

## 完整例子

保存为 `RegexGreedyDemo.java`，编译运行；日志写到标准错误。

```java
import java.util.regex.Matcher;
import java.util.regex.Pattern;
import java.util.logging.Logger;
public class RegexGreedyDemo {
    private static final Logger logger = Logger.getLogger(RegexGreedyDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：比较量词匹配范围
         * ========================================================================
         * 数据源：程序内的固定模式与文本
         * 操作：
         * 1) 构造正则表达式及匹配器
         * 2) 匹配、读取或替换并输出结果
         */
        logger.info("开始处理文本");
        // 1.1 准备两个标签片段
        String input = "<a>one</a><b>two</b>";
        Matcher greedy = Pattern.compile("<.*>").matcher(input);
        Matcher reluctant = Pattern.compile("<.*?>").matcher(input);
        // 1.2 各查找一次并显示结果
        if (greedy.find()) System.out.println("greedy=" + greedy.group());
        if (reluctant.find()) System.out.println("reluctant=" + reluctant.group());
        logger.info("文本处理完成");
    }
}
```

标准输出：

```text
greedy=<a>one</a><b>two</b>
reluctant=<a>
```

## 执行过程

输入中有多个尖括号片段。`<.*>` 的 `.*` 贪婪，示例匹配从第一个 `<` 到最后一个 `>`；`<.*?>` 的 `.*?` 非贪婪，在当前起点先找到能使整个模式成功的最短范围 `<a>`。两次分别使用独立 Matcher，互不依赖查找状态。

## 边界与性能

非贪婪不等于“只匹配一个字符”，也不等于整体匹配一定最短；它只是量词尝试顺序不同。`.` 默认不匹配某些行终止符，启用 DOTALL 等标志后行为不同。需要逐个查找时循环调用 `find()`，每次成功后读取 group。

此示例只展示字符串匹配，不是可靠的 HTML 解析方案。真实 HTML 可有属性引号、注释、嵌套和不完整输入，应使用适当解析器。非贪婪也不自动消除所有性能风险，应约束输入并测试最坏情况。

## 手练与答案

对 `"<x><y>"`，第一次 find：贪婪模式得到 `<x><y>`，非贪婪得到 `<x>`。在同一个非贪婪 Matcher 上再调用一次 find，可找到 `<y>`。
