# 正则表达式简介

> **重要程度：高**｜**手练：需要**
> **重点**：Pattern、Matcher、完整匹配与查找。

## 解决什么问题

正则表达式描述文本中的匹配规则，例如“一个或多个数字”。Java 的 `Pattern` 是编译后的模式，`Matcher` 保存对某个输入的匹配状态。先区分要验证整个输入，还是从长文本中找一段。

## 完整例子

保存为 `RegexIntroDemo.java`，编译运行；日志写到标准错误。

```java
import java.util.regex.Matcher;
import java.util.regex.Pattern;
import java.util.logging.Logger;
public class RegexIntroDemo {
    private static final Logger logger = Logger.getLogger(RegexIntroDemo.class.getName());
    public static void main(String[] args) {
        /*
         * ========================================================================
         * 步骤1：比较完整匹配和片段查找
         * ========================================================================
         * 数据源：程序内的固定模式与文本
         * 操作：
         * 1) 构造正则表达式及匹配器
         * 2) 匹配、读取或替换并输出结果
         */
        logger.info("开始处理文本");
        // 1.1 编译数字模式
        Pattern pattern = Pattern.compile("[0-9]+");
        // 1.2 对同一输入分别执行完整匹配和查找
        System.out.println("matches=" + pattern.matcher("id=42").matches());
        Matcher matcher = pattern.matcher("id=42");
        if (matcher.find()) {
            System.out.println("found=" + matcher.group());
        }
        logger.info("文本处理完成");
    }
}
```

标准输出：

```text
matches=false
found=42
```

## 执行过程

`[0-9]+` 表示一个或多个 ASCII 数字。`matches()` 要求整个匹配区域符合模式，`id=42` 还有前缀，所以为 false。另建 Matcher 后 `find()` 找到子串 `42`；只有成功匹配后才能用 `group()` 读取当前结果。

`matches()`、`find()`、`lookingAt()` 的起始位置与范围不同；本例使用默认的整个输入作为区域。Matcher 有状态，不应在多个线程间无保护共享；Pattern 可复用。正则无法自动保证日期、邮箱等复杂业务数据的语义合法，仍需后续校验。

## 工作中怎么用

先写清允许的字符、长度、是否完整匹配和错误处理，再覆盖正常、边界、空串、特殊字符和较长输入。避免对不可信输入使用容易产生大量回溯的表达式，并限制输入大小；需要结构化解析时优先使用合适解析器。

## 手练与答案

输入改成 `"42"`：默认区域下 matches 为 true，find 也能找到 42。若对匹配失败的 Matcher 直接调用 group，会抛 `IllegalStateException`。
