# 正则表达式 · 笔记

## 先搞清楚：它到底解决什么问题

判断一个字符串是不是合法邮箱，你可以手动找 `@`、切前缀后缀、再逐字符判断——写出来又长又散，换一种格式就得重写一遍。正则表达式换了个思路：**用一串“描述规则”的字符，把“什么算合法”直接声明出来**。规则写一次，任何字符串扔进去，它告诉你匹配还是不匹配。它不是某个函数，是一种**独立的描述性小语言**，Python 的 `re` 模块只是这门语言的一个执行器。

## 基本语法：先学会“读”一条正则

不用背表，先看一条复杂的，拆开了读，其余都是它的零件。

`r'\d{3}\s+\d{3,8}'` 匹配的是“以任意个空格隔开的带区号电话号码”，比如 `010 1234567`。从左往右读：

```python
r'\d{3}\s+\d{3,8}'
# \d    匹配一个数字
# {3}   重复 3 次 → 三个数字，如 010
# \s+   一个或多个空白符（空格、Tab 都算）
# \d{3,8}  3 到 8 个数字
```

这条表达式几乎用到了最核心的零件。把它们归一下类，你只需要记住**四组**：

**第一组：字符匹配**。`\d` 是一个数字，`\w` 是字母/数字/下划线，`\s` 是空白符，`.` 是除换行外的任意字符。直接写 `py` 就是精确匹配 `py` 这两个字母本身。

**第二组：数量限定**。`*` 零次或多次，`+` 至少一次，`?` 零次或一次，`{n}` 恰好 n 次，`{n,m}` 是 n 到 m 次。注意 `*` 和 `+` 都**允许**前面的东西出现，但 `+` 不允许“零次”，这是它俩唯一的区别。

**第三组：范围与分支**。`[0-9a-zA-Z\_]` 表示“方括号里任意一个字符”，`A|B` 表示“A 或 B”。Python 合法变量名的规则 `[a-zA-Z\_][0-9a-zA-Z\_]*` 就是这么写出来的：**第一个字符不能是数字，后面可以跟任意个数字/字母/下划线**。

**第四组：位置锚点**。`^` 表示“必须从行首开始”，`$` 表示“必须到行尾结束”。单独写 `py`，它能在 `python` 里匹配到 `py` 那一段；但写成 `^py$`，就**只认整行恰好是 `py` 的字符串**，`python` 直接不匹配。锚点管的不是字符内容，是位置。

## `re` 模块：五个函数，分工完全不同

Python 的正则功能全在 `re` 模块里。你不需要记很多函数，但**下面五个的分工必须一次分清**，因为选错函数，逻辑直接错。

**`re.match`：从字符串开头匹配，只试一次。** 匹配成功返回 `Match` 对象，失败返回 `None`。所以“判断是否匹配”的标准写法就是拿它当条件：

```python
import re
if re.match(r'^\d{3}\-\d{3,8}$', '010-12345'):   # 注意用了 ^ 和 $ 锁定整行
    print('ok')
else:
    print('failed')
```

这里 `^` 和 `$` 不是装饰，是**让 `match` 变成“整串校验”而不是“前缀检查”**。没有 `$`，`010-12345abc` 也会匹配成功。

**`re.search`：从头到尾扫，找第一个能匹配的位置。** 它不要求从开头开始。`match` 和 `search` 都只返回**第一个**匹配结果，区别就一条：`match` 只试开头，`search` 全串扫。

**`re.split`：按正则规则切分字符串。** 它比 `str.split` 强的地方在于**能识别连续空白**。`'a b c'.split(' ')` 遇到多个空格会产生空字符串，而 `re.split(r'\s+', 'a b c')` 直接得到 `['a', 'b', 'c']`。

**`re.findall`：返回所有匹配结果的列表。** `match` 和 `search` 只找一个，`findall` 找全部。要“把字符串里所有符合条件的片段都捞出来”，用它。

**`re.sub`：按正则规则替换。** 把匹配到的部分换成别的内容，用途是“正则版的 `str.replace`”。

一句话总结这五个：**校验用 `match`（配锚点），找第一个用 `search`，切分用 `split`，找全部用 `findall`，替换用 `sub`。**

## 分组：用括号把匹配结果“拆开”

正则不仅能说“匹配/不匹配”，还能**把匹配到的东西按括号拆成几块**。`Match` 对象的 `.groups()` 或 `.group(n)` 拿的就是括号里的内容。

```python
m = re.match(r'^(\d{3})-(\d{3,8})$', '010-12345')
m.group(0)      # '010-12345'，整个匹配
m.group(1)      # '010'，第一个括号
m.group(2)      # '12345'，第二个括号
```

**括号就是捕获组**。校验邮箱时，你可以用分组顺手把 `@` 前面的用户名和后面的域名拿出来，不用匹配完再切一遍。

## 坑一：贪婪匹配是默认行为，而且会吃掉你不想让它吃的东西

这是整页**最容易写出错误结果**的地方。正则的数量限定符默认是**贪婪**的：`\d+` 会尽可能多地吞数字，直到吞不下为止。

```python
re.match(r'^(\d+)(0*)$', '102300').groups()
# ('102300', '')    \d+ 把 0 全吞了，0* 只能匹配空字符串
```

你本来可能想让 `\d+` 匹配 `1023`、`0*` 匹配 `00`，但贪婪的 `\d+` 把后面的 0 也当成数字吞掉了。解法是**在数量限定符后面加一个 `?`**，变成非贪婪匹配：

```python
re.match(r'^(\d+?)(0*)$', '102300').groups()
# ('1023', '00')    非贪婪的 \d+? 一到能满足整体匹配就停手
```

**记住：`*`、`+`、`{n,m}` 都是贪婪的，后面加 `?` 才变成非贪婪。** 写提取规则、尤其是分组提取时，如果结果里某一段“多吃了”，第一反应就该是它。

## 坑二：字符串转义和正则转义叠在一起

Python 字符串本身把 `\` 当转义符，正则表达式也把 `\` 当转义符。你要匹配一个真正的 `-`，写 `'\\-'` 在 Python 字符串里，才等于正则看到的 `\-`。不写 `r` 前缀，转义层数一多就完全数不清。

**解法只有一个：所有正则字符串一律加 `r` 前缀。** `r'\d{3}\-\d{3,8}'` 里写的是什么，正则看到的就是什么，不用替 Python 的字符串转义操心。
