盐，就是**算哈希前拼在密码后面的一段随机串**：`hash(password + salt)`。

它只干两件事：**让黑客预先算好的“密码→哈希”表失效**；**让两个用相同密码的用户，存进库里的哈希也不同**。

记住三条铁律：

1. **盐不用保密**，明文存数据库都行，它的作用不是藏起来，是打乱哈希。
2. **每个用户必须有自己独立的随机盐**，全站共用一个盐等于白加。
3. **盐要够长够随机**，太短等于没加。

和密钥的区别一句话：**盐是公开的、每用户不同的；密钥是保密的、双方共享的。** 盐泄露顶多降低一点安全性，密钥泄露整个认证就废了。

HMAC 就是“带密钥的哈希”的标准化做法，那个 key 干着盐的活，但比盐要求更高——它必须保密。

## 哈希到底是什么：单向的“指纹”

哈希算法（也叫摘要算法）干的事，就是**把任意长度的数据，压缩成一个固定长度的“指纹”**。原文举的例子很直观：你写了一篇文章，算出它的哈希是 `2d73d4f1...`。如果有人把文章改了，哪怕只改一个作者名字，算出来的哈希会**完全不同**，你一眼就能看出被篡改了。

它之所以能干这件事，靠的是两个性质：**单向**和**雪崩**。单向意味着“算指纹容易，通过指纹反推原文几乎不可能”；雪崩意味着“原文改一个 bit，指纹面目全非”。这两条是所有应用的地基。

但这里要先钉死一个原文在结尾专门强调的定性：**哈希不是加密**。加密能解密，哈希**不能**反推原文，所以它只能用来“验真”和“比对”，不能用来“保护后还能还原”。

## 基本用法：MD5 / SHA1 都长一个样

`hashlib` 的调用模式是统一的，换算法只换函数名：

```python
import hashlib
md5 = hashlib.md5()                                    # 创建 MD5 哈希对象
md5.update('how to use md5 in python hashlib?'.encode('utf-8'))   # 喂数据，必须是 bytes
print(md5.hexdigest())                                 # d26a53750bc40b38b65a520292f69306
```

**`update()` 吃的是 `bytes`**，字符串要先 `.encode('utf-8')`。**`hexdigest()` 返回十六进制字符串**，这是最常见的输出形式；`digest()` 返回原始字节，需要存二进制时用。

MD5 产出 **128 bit（16 字节）**，用 32 位十六进制字符串表示。SHA1 的调用完全一样，产出 **160 bit（20 字节）**，对应 40 位十六进制。

**大文件不用一次读完**。`update()` 可以分块多次调用，最后结果和一次性喂进去**完全等价**：

```python
md5 = hashlib.md5()
md5.update('how to use md5 in '.encode('utf-8'))       # 第一块
md5.update('python hashlib?'.encode('utf-8'))           # 第二块，累加进去
print(md5.hexdigest())                                  # 和一次性 update 结果一样
```

这是处理大文件时的标准写法：**读一块、`update` 一块，内存不用扛整个文件**。

## 坑一：哈希会“碰撞”，但这不是你该操心的

原文提了一句：**任何哈希算法都是把无限多的输入映射到有限长度的输出，所以“不同的数据算出相同哈希”是完全可能的**，这叫碰撞。

但注意原文的措辞：**“非常非常困难”**。MD5 的碰撞已经被实际构造出来了，SHA1 也不再安全，所以**不要用 MD5/SHA1 做安全相关的签名或证书**。但对于“防意外篡改”和“密码比对”这类场景，碰撞在实践中的威胁远小于“密码本身太弱”和“数据库泄露”，后者才是你真正要防的。**选算法时，SHA256/SHA512 比 MD5/SHA1 更安全，但更慢、产出更长**，按场景权衡。

## 重头戏：存密码，从“明文”到“加盐”到“随机盐”

原文后半截才是这页真正的干货，它用“存密码”这个场景，把哈希的用法从“会用”推到了“用对”。

### 第一层：明文存储，最蠢但最常见的错

```python
# 数据库里存的是：michael | 123456
```

数据库一旦泄露，**所有人的密码直接裸奔**。而且就算没泄露，**运维人员能直接看到所有人的密码**，这在内部就是巨大的风险。

### 第二层：存哈希，解决了“明文泄露”，但没解决“弱口令”

正确做法是**只存密码的哈希**，登录时算用户输入的哈希，和库里的比对。

```python
def calc_md5(password):
    return hashlib.md5(password.encode('utf-8')).hexdigest()   # 算出密码的 MD5
```

这样即使库泄露，黑客拿到的只是一串哈希。**但问题来了**：原文说得很直白——黑客根本不用“破解”，他们**事先算好常用密码的哈希，做成一张反查表**：

```python
hash_to_plain = {
    'e10adc3949ba59abbe56e057f20f883e': '123456',      # 123456 的 MD5
    '21218cca77804d2ba1922c33e0151105': '888888',      # 888888 的 MD5
    '5f4dcc3b5aa765d61d8327deb882cf99': 'password',    # password 的 MD5
}
```

拿到你的哈希，**查表就知道明文**。用户越爱用简单密码，这张表命中率越高。

### 第三层：加盐，让“预计算”失效

解法是**在密码后面拼一个只有你知道的字符串（Salt），再算哈希**：

```python
def calc_md5(password):
    return get_md5(password + 'the-Salt')               # 密码拼上固定盐再哈希
```

这样黑客的预计算表就**对不上了**，因为表里存的是“纯密码的哈希”，而你库里存的是“密码+盐的哈希”。

**但固定盐有一个新问题**：如果两个用户都用了 `123456`，他们拼上同一个盐，算出来的哈希**完全相同**。黑客一看就知道“这两个人密码一样”，而且只要盐泄露，一张新表就能把所有人打穿。

### 第四层：每个用户独立随机盐，最终形态

**盐不能是全局固定的，必须每个用户不一样**。原文给的方案有两种，核心思想一致：

**方案一：用户名当盐的一部分**（前提是用户名不可改）：

```python
def register(username, password):
    db[username] = get_md5(password + username + 'the-Salt')   # 盐 = 用户名 + 固定串
```

这样即使两个用户密码相同，**用户名不同，哈希就不同**。

**方案二：每个用户生成一个随机盐，存进用户对象**：

```python
class User:
    def __init__(self, username, password):
        self.username = username
        self.salt = ''.join([chr(random.randint(48, 122)) for i in range(20)])   # 20位随机盐
        self.password = get_md5(password + self.salt)                              # 密码拼随机盐再哈希
```

登录时，**用这个用户自己存的盐去算输入密码的哈希**，再和 `self.password` 比对。盐不需要保密，**它只要“每个用户不同”就够了**，因为它的作用是让“预计算表”和“相同密码识别”同时失效。

---

## 一句话收束整页

**哈希是单向指纹，不是加密。用它存密码，只存哈希不存明文；但光存哈希挡不住弱口令查表，所以要加盐；盐不能全局固定，要每个用户不同（用户名或随机盐），才能同时挡住“预计算”和“相同密码识别”两件事。**
