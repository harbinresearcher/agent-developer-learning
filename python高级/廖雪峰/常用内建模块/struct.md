这页的核心其实是一个**痛点**：Python 没有 C 语言那种“把一段内存按 `int`、`float` 解释”的原生能力。你想把一个整数塞进 4 个字节，手动写位运算又长又容易错；想处理浮点数更是几乎没法手动做。`struct` 就是把“Python 值和字节序列之间来回转换”这件事，从**位运算地狱**里救出来的工具。

---

# struct · 笔记

## 先看它救你于什么水火

把一个 32 位无符号整数 `10240099` 变成 4 个字节，不靠 `struct` 的话，你得这么写：

```python
n = 10240099
b1 = (n & 0xff000000) >> 24
b2 = (n & 0xff0000) >> 16
b3 = (n & 0xff00) >> 8
b4 = n & 0xff
bs = bytes([b1, b2, b3, b4])
# b'\x00\x9c@c'
```

四行位运算，只为了干一件事。而且这还只是整数，换成浮点数，位运算直接无能为力。

`struct` 用一行替你干完：

```python
import struct
struct.pack('>I', 10240099)
# b'\x00\x9c@c'
```

**`struct` 的全部价值，就是让你不用碰位运算，也能在 Python 值和字节之间自由转换。**

---

## 核心就两个函数：pack 和 unpack

### `pack`：Python 值 → 字节

`pack(格式, 值1, 值2, ...)` 按格式把值打包成 `bytes`。

```python
struct.pack('>I', 10240099)
# b'\x00\x9c@c'
```

`>` 表示大端字节序，`I` 表示 4 字节无符号整数。**值的个数必须和格式串里描述的类型完全匹配**，多一个少一个都会报 `struct.error`。

### `unpack`：字节 → Python 值

`unpack(格式, 字节串)` 按格式把 `bytes` 拆回值。

```python
struct.unpack('>IH', b'\xf0\xf0\xf0\xf0\x80\x80')
# (4042322160, 32896)
```

`I` 吃掉前 4 个字节，`H` 吃掉后 2 个字节，**返回一个元组**。

### 必须钉死的一条：unpack 永远返回元组，哪怕只有一个值

这是新手最常翻车的地方。`struct.unpack('>I', b'\x00\x9c@c')` 返回的是 `(10240099,)`，不是 `10240099`。**即使格式串只描述了一个值，结果也是元组**，你要么用 `[0]` 取，要么解包赋值 `(value,) = struct.unpack(...)`。如果直接拿它当数字用，会得到 `TypeError`。

---

## 格式字符串：你只需要会读“前缀 + 类型”

格式串由两部分组成：**可选的字节序前缀，加上类型描述**。

### 字节序前缀：写文件、走网络必须显式指定

| 前缀 | 含义 |
|---|---|
| `<` | 小端（低字节在前） |
| `>` | 大端（高字节在前） |
| `!` | 网络序，**等同于 `>`** |
| 不写 | 本机字节序 + 本机对齐，**跨平台不可移植** |

**写文件、和别的系统通信时，不要依赖默认的本机字节序**。x86 是小端，网络协议和很多文件格式（比如 BMP）是大端或规定死了某种顺序。不写前缀，你在 Mac 上跑得好好的代码，到另一台机器上解析出来的数字就是乱码。

### 类型字符：常用的一组

**整数**：`b`/`B`（1 字节，有/无符号），`h`/`H`（2 字节），`i`/`I`（4 字节），`q`/`Q`（8 字节）。**小写有符号，大写无符号**。

**浮点数**：`f`（4 字节单精度），`d`（8 字节双精度）。

**字符串/字节**：`s` 是固定长度字节串，前面带数字指定长度，比如 `4s` 表示“固定 4 个字节的字节串”。注意 `s` 代表的是**字节**，不是 `str`。

数字前缀表示“重复次数”：`2I` 等于 `I I`，`3s` 等于 `3s`，`4H` 等于 `H H H H`。

## 实战：用 `struct.unpack` 读 BMP 文件头

廖雪峰用 BMP 文件头把前面所有知识点串了起来。BMP 的前 30 个字节结构是固定的：`BM` 标记（2 字节）、文件大小（4 字节整数）、保留位（4 字节）、图像偏移（4 字节）、Header 大小（4 字节）、宽（4 字节）、高（4 字节）、颜色平面（2 字节）、颜色数（2 字节）。

用格式串拼出来：

```python
struct.unpack('<ccIIIIIIHH', s)
# (b'B', b'M', 691256, 0, 54, 40, 640, 360, 1, 24)
```

`<` 是因为 BMP 用小端存储；`c` 是单字节，两个 `c` 分别拿到 `b'B'` 和 `b'M'`；后面按顺序 `I`、`H` 对应各自字段。解包结果直接告诉你：**这是 Windows 位图，尺寸 640×360，24 色**。

**这一段的价值不在于记 BMP 格式，而在于让你看到：只要知道一段二进制的字段顺序和每个字段的宽度，格式串就能把它变成一组可读的 Python 值。**

## 坑一：字节对齐，会让 `pack` 出来的长度比你“算”的多

这是 `struct` 里最隐蔽的一个坑，而且**只在你不写字节序前缀时出现**。

默认情况下，`struct` 会模拟 C 语言的内存对齐规则，在字段之间插入**填充字节**。比如 `struct.calcsize('2I3sI')` 结果是 **16**，但你手算：4+4+3+4 = 15。多出来的 1 个字节，是因为 3 字节的字符串后面被填充到了 4 字节边界，后面的 `I` 才能对齐。

更极端的例子：`calcsize('3B2H1B4H2B')` 结果是 **20**，而把每一段的 size 单独算出来再加，是 **18**。中间差的两个字节，全是填充。

**怎么避开**：**只要格式串以 `<`、`>`、`=` 或 `!` 开头，对齐方式就变成“标准对齐”，不再插入本机填充字节**。换句话说，**显式写字节序前缀，不仅解决跨平台问题，还顺手把对齐坑一起填了**。写文件、走网络、和外部格式打交道，永远带上前缀，不要省略。

## 坑二：`unpack` 要求的字节数必须和格式严格匹配

`unpack` 不会“读多少算多少”。格式串要求多少字节，你传入的 `bytes` 就必须恰好是多少字节。`struct.unpack('>I', b'\x00\x9c')` 会直接报 `struct.error: unpack requires a buffer of 4 bytes`。你要自己保证**切出来的片段长度正确**，或者先用 `calcsize` 算好该读多少。

---

## 一句话收尾

`struct` 的定位非常明确：**当你需要和“二进制格式”打交道时——读文件头、解析网络协议、和 C 扩展交换数据——它就是 Python 里最直接的工具**。核心就两个动作：`pack` 把值变成字节，`unpack` 把字节变成元组。格式串决定字节序和布局，**显式写前缀、记住元组返回值、别跟对齐较劲**，这三件事做到，这页就稳了。
