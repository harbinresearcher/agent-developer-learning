# base64 · 笔记

## 先把它定性：编码，不是加密

Base64是一种**用64个字符来表示任意二进制数据的方法**，核心作用只有一个：**把二进制数据变成纯文本，好让它在邮件正文、网页、URL、Cookie这些“只认文本”的地方安全传输**。它**不提供任何安全性**，任何人都能轻松解码，所以**绝不能用来保护敏感信息**。这个认知先立住，后面所有用法才不会跑偏。

## 它怎么工作：3字节 → 4字符

原理一句话：**每3个字节（24 bit）一组，切成4段6 bit，每段查一张64字符表，变成4个字符**。所以编码后的长度是原来的 **4/3，也就是增加了33%**。

如果数据不是3的倍数，末尾会**补 `\x00` 字节凑够3个**，然后在编码结果的末尾加上**1个或2个 `=`**，表示补了几个字节。解码时，这些 `=` 会被自动去掉，原始数据恢复原样。

## Python 怎么用：四个核心函数

常用编码函数接收 bytes-like 对象并返回 `bytes`；解码函数还可接收仅含 ASCII 的字符串，返回 `bytes`。这是第一个容易踩的点。

```python
import base64

# 标准编码：bytes 进去，bytes 出来
encoded = base64.b64encode(b'binary\x00string')   # b'YmluYXJ5AHN0cmluZw=='
decoded = base64.b64decode(b'YmluYXJ5AHN0cmluZw==')   # b'binary\x00string'
```

`b64encode` 返回的是 `bytes`，如果你要把它放进 URL 参数或 JSON 里，**需要自己 `.decode('ascii')` 转成字符串**。反过来，`b64decode` 只接受 `bytes` 或 ASCII 范围的字符串，传中文进去会报错。

## URL 安全变体：`+` 和 `/` 换成 `-` 和 `_`

标准 Base64 的字符表里有 `+` 和 `/`，这两个字符在 URL 里有特殊含义，直接当参数会出问题。`urlsafe_b64encode` 做的事很简单：**把 `+` 换成 `-`，把 `/` 换成 `_`**，其余完全一样。

```python
base64.b64encode(b'i\xb7\x1d\xfb\xef\xff')          # b'abcd++//'
base64.urlsafe_b64encode(b'i\xb7\x1d\xfb\xef\xff')   # b'abcd--__'
```

**什么时候用哪个**：数据要放进 URL、文件名、Cookie 值里，用 `urlsafe_b64encode`；普通场景（比如编码一段二进制存数据库、走 API 的 JSON 字段）用标准 `b64encode` 就行。

## 最重要的一条：不能用于加密

原文专门用粗体强调了一句：**“Base64是一种通过查表的编码方法，不能用于加密，即使使用自定义的编码表也不行”**。原因很硬：**没有密钥**，编码规则是公开的，任何人拿到字符串就能解开。

自定义编码表只是换了一张字符对照表，**本质仍然是“可逆的查表变换”**，安全性为零。用 Base64 “加密”密码、令牌、个人信息，是实际项目里常见的安全漏洞来源。**哈希不等于加密；需要保密时使用成熟加密库和合适的密钥管理。Base64 只负责编码，不提供保密性。**

## 去掉等号：URL 和 Cookie 的常见处理

`=` 出现在 URL 或 Cookie 值里会造成歧义，所以很多系统在输出 Base64 时会**把末尾的 `=` 去掉**。但 Python 的 `b64decode` **要求输入长度是4的倍数**，少一个 `=` 就会报 `binascii.Error: Incorrect padding`。

**解码前补回来**，标准做法是**补齐到4的倍数**：

```python
def safe_b64decode(s):
    # 把缺少的 = 补回去，使长度变成4的倍数
    return base64.b64decode(s + '=' * (-len(s) % 4))
```

`-len(s) % 4` 算出“还差几个字符到4的倍数”，差1个补 `=`，差2个补 `==`，差0个不补。这个逻辑不区分输入里原本有没有 `=`，统一补齐是最稳的写法。

## 几个容易踩的点

**1. `b64encode` 的入参是 bytes-like 对象。** 传字符串 `'hello'` 会直接 `TypeError`，要先 `.encode('utf-8')`。

**2. `b64decode` 默认不严格校验。** 一些非法字符可能被忽略，需要严格校验时用 `validate=True`，但注意它只接受标准 Base64 字符，`urlsafe` 的 `-` 和 `_` 会被拒绝。

**3. `urlsafe_b64encode` 仍然会带 `=`**，它只换了 `+` 和 `/`，**没有去掉填充**。如果需要完全无填充的输出，还得自己 `.rstrip(b'=')`，解码时再按上面的方法补回来。

**4. 大数据需要考虑开销。** 原文明确说它“适用于小段内容的编码，比如数字证书签名、Cookie的内容等”。大文件（几十MB的图片、视频）用 Base64 会让体积膨胀33%，而且编解码本身占用CPU和内存，这时候应该直接传二进制，不要在文本层套 Base64。
