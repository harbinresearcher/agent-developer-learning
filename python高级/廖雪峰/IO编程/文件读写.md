> **重要程度：高**｜**手练：需要**
> 重点：with、编码、文本和二进制、异常处理。

由于CPU和内存的速度远远高于外设的速度，所以，在IO编程中，就存在速度严重不匹配的问题。举个例子来说，比如要把100M的数据写入磁盘，CPU输出100M的数据只需要0.01秒，可是磁盘要接收这100M数据可能需要10秒，怎么办呢？有两种办法：

第一种是CPU等着，也就是程序暂停执行后续代码，等100M的数据在10秒后写入磁盘，再接着往下执行，这种模式称为同步IO；

另一种方法是CPU不等待，只是告诉磁盘，“您老慢慢写，不着急，我接着干别的事去了”，于是，后续代码可以立刻接着执行，这种模式称为异步IO。

# 文件读写 · 笔记

## 先搞清楚：你在操作谁

读写文件不是 Python 自己干活，是**你请求操作系统打开一个文件对象（文件描述符），然后通过这个对象读或写**。Python 的 `open()` 就是帮你向操作系统要这个对象的。所有文件操作，本质上都是在跟这个“文件对象”打交道。

---

## 读文件：open → read → close

```python
f = open('/Users/michael/test.txt', 'r')   # 打开文件，'r' 表示只读（默认模式，不写也行）
content = f.read()                          # 一次性读出全部内容，返回字符串
print(content)                              # Hello, world!
f.close()                                   # 关闭，释放操作系统资源
```

**文件不存在时 `open()` 直接抛 `FileNotFoundError`**，不会给你一个空文件对象。

`read()` 是**一次性全读**。文件小没问题，但如果文件有几个 G，内存直接爆。所以更稳的做法是**分批读**：

```python
while True:
    chunk = f.read(1024)   # 每次最多读 1024 字节（或字符，文本模式下是字符）
    if not chunk:          # 读完了，read 返回空字符串
        break
    # 处理 chunk
```

还有两个按行读的写法，用途不同：

```python
line = f.readline()        # 读一行，适合手动逐行处理
lines = f.readlines()      # 一次读完，按行返回列表，适合配置文件
```

**选择原则**：文件小用 `read()` 最省事；大小不确定用 `read(size)` 循环；配置文件用 `readlines()` 或直接 `for line in f:`。

---

## 关闭文件：为什么必须用 with

手动 `f.close()` 的问题是：**一旦读写过程中抛异常，`close()` 就轮不到执行**，文件句柄泄漏。老写法用 `try...finally` 兜底，但太啰嗦。

`with` 就是 Python 给你的自动关闭机制：

```python
with open('/path/to/file', 'r') as f:   # 进入 with 块，f 是打开的文件对象
    print(f.read())                      # 块内随便用
# 出了 with 块，文件自动关闭，不管有没有异常
```

`with` 背后的机制是**上下文管理器**：`open()` 返回的对象实现了 `__enter__` 和 `__exit__`，进入 `with` 调 `__enter__`，离开时无论正常结束还是异常，都调 `__exit__` 把文件关掉。**记住结论就够了：用 `with open(...) as f:`，不要手动 `close()`。**

---

## 写文件：模式决定命运

写文件和读文件结构一样，区别在 `open()` 的第二个参数：

```python
with open('/Users/michael/test.txt', 'w') as f:   # 'w' 表示写文本
    f.write('Hello, world!')                       # 写入字符串
```

**`'w'` 是“覆盖写”**：如果文件已存在，**内容直接被清空**，相当于删了重写。如果你不想丢原有内容，用 `'a'`（append）：

```python
with open('log.txt', 'a') as f:   # 'a' 追加到文件末尾，不覆盖
    f.write('new line\n')
```

完整模式速查（只列最常用的）：

| 模式 | 含义 | 文件存在 | 文件不存在 |
|---|---|---|---|
| `'r'` | 只读（默认） | 从头读 | `FileNotFoundError` |
| `'w'` | 只写 | **清空重写** | 创建 |
| `'a'` | 追加写 | 末尾追加 | 创建 |
| `'r+'` | 读写 | 保留内容，从头开始 | `FileNotFoundError` |

`'b'` 后缀是二进制模式，下面单独说。

---

## 二进制文件：`'rb'` / `'wb'`

图片、视频、音频这些**不是文本**，不能用文本模式读写。文本模式会在底层做**编码解码和换行符转换**，这对二进制数据是灾难性的，会损坏文件。

```python
with open('/Users/michael/test.jpg', 'rb') as f:   # 'rb'：二进制只读
    data = f.read()                                 # 返回 bytes，不是 str
    print(data[:10])                                # b'\xff\xd8\xff\xe1...' 十六进制字节
```

二进制模式下，`read()` 返回 `bytes`，`write()` 也只接受 `bytes`。**文本和二进制不能混**：往文本流写 `bytes` 或往二进制流写 `str`，都会 `TypeError`。

---

## 编码：文本文件最大的坑

默认编码取决于 Python 版本、UTF-8 模式和系统设置。Python 3.15 起默认启用 UTF-8 模式，旧版本在未启用该模式时可能使用系统区域编码。跨版本读写文本时，明确指定文件的实际编码，例如 UTF-8。参考：[Python 3.15 编码变化](https://docs.python.org/3.15/whatsnew/3.15.html#pep-686-python-now-uses-utf-8-as-the-default-encoding)。

**解法：永远显式指定 `encoding`**：

```python
with open('gbk.txt', 'r', encoding='gbk') as f:     # 读 GBK 编码的文件
    content = f.read()

with open('output.txt', 'w', encoding='utf-8') as f:  # 写 UTF-8 编码的文件
    f.write('测试')
```

还有一个 `errors` 参数，处理编码不规范的文件：

```python
with open('dirty.txt', 'r', encoding='utf-8', errors='ignore') as f:
    content = f.read()   # 跳过无法解码的字节，不抛 UnicodeDecodeError
```

`errors='ignore'` 是**兜底手段**，不是常规操作。正常情况下应该搞清楚文件到底是什么编码，用正确的 `encoding` 去读。

Python 3.15 开始，`open()` 的默认编码会统一成 UTF-8，但在那之前，**显式写 `encoding='utf-8'` 是跨平台代码的基本修养**。

---

## file-like Object：不是文件，但能当文件用

`open()` 返回的对象有一个特点：它有 `read()` 方法。Python 里，**只要一个对象有 `read()`（以及配套的 `write()` 等），不管它是不是磁盘上的真文件，都可以当文件用**。这叫 `file-like Object`，是鸭子类型的典型应用。

`StringIO` 和 `BytesIO` 就是**内存里的 file-like 对象**：

```python
from io import StringIO, BytesIO

f = StringIO()              # 在内存里创建一个“文本文件”
f.write('hello')
f.seek(0)                   # 把读写位置拨回开头，才能读到刚写的内容
print(f.read())             # hello

b = BytesIO()               # 内存里的“二进制文件”
b.write(b'\x00\x01')
b.seek(0)
print(b.read())             # b'\x00\x01'
```

`StringIO` 处理文本（`str`），`BytesIO` 处理字节（`bytes`），**两者不能混用**。它们的用途是：当你需要一个“文件对象”但不想真的落到磁盘上时（临时缓冲、测试、拼接数据），用它们。

---

## 几个容易踩的点

**1. `'w'` 会清空原文件，不是“打开准备编辑”。** 想保留内容用 `'a'` 或 `'r+'`。

**2. 默认编码可能因版本和设置而不同。** 跨版本读写时显式指定文件实际编码。

**3. 文本模式和二进制模式不能混。** 图片用 `'rb'`，文本用 `'r'`，别用文本模式去读图片。

**4. `with` 块外文件已经关了。** `with open(...) as f:` 里 `f` 只在块内有效，出了块再去 `f.read()` 会报 `ValueError: I/O operation on closed file`。

**5. `read()` 无参是“全读”，大文件慎用。** 不确定大小时用 `read(size)` 或按行迭代。
