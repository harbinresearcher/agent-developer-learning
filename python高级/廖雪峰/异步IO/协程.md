这节廖雪峰老师讲的是异步 IO 的**底层基石：协程**。原文虽然提到了“微线程”，但它的实现思路和多线程完全不同。咱们顺着**“函数调用的限制→ 怎么实现中途暂停 → Python 的生成器怎么做到的 → 实战代码里的玄机 → 它在 FastAPI 里的真面目”**这条线来梳理。

---

## 先搞清楚痛点：普通函数，只能“一口气跑完”

传统的子程序（普通函数）调用，永远是**层级式**的：A 调用 B，B 必须跑完返回，A 才能继续往下走。函数一旦开始执行，中途是没法“暂停”去干别的事的。

但协程打破了这个规则：**它可以在执行中途主动让出控制权，切去执行别的任务，等合适的时候再切回来接着往下跑**。

如果你听过“微线程”这个词，要知道它的本质：**协程是纯单线程运行的**。它只是把多个任务的代码拆碎了交替执行，并非开了多个线程同时跑。

---

## 底层揭秘：Python 靠什么实现“中途暂停”？

早期 Python 并没有原生的 `async/await`，它的异步能力是**靠生成器（`yield`）演变来的**。

普通函数用 `return` 只能返回一次，函数就结束了；而生成器函数用的是 `yield`。`yield` 有两个超能力：
1. **暂停**：执行到 `yield` 时，函数挂起，把值抛给外部。
2. **唤醒并接收数据**：外部调用 `.send(数据)` 时，能让函数从刚才暂停的地方恢复执行，并且 `yield` 这一句能**接收到外部传进来的数据**。

正是 `.send()` 让单向输出的生成器，变成了**可以和外部双向通信的协程**。

---

## 代码拆解：生产者-消费者模型

廖老师用一段经典代码演示了协程的运作方式：

```python
def consumer():
    r = ''
    while True:
        n = yield r  # 核心：交出执行权，并等待外部通过 send() 传 n 进来
        if not n:
            return
        print(f'[消费者] 消费 {n}...')
        r = '200 OK'

def produce(c):
    c.send(None)  # 1. 启动生成器（第一次只能传 None，让它跑到第一个 yield 处停下）
    n = 0
    while n < 5:
        n += 1
        print(f'[生产者] 生产 {n}...')
        r = c.send(n)  # 2. 唤醒消费者，把 n 传给 yield，并把 yield 返回的 r 赋给当前变量
        print(f'[生产者] 消费者返回: {r}')
    c.close()

c = consumer()
produce(c)
```

**代码里的几个关键动作**：
* `c.send(None)` 起到**预激活**的作用：先让消费者跑到 `yield` 处停下来，准备好接收数据。
* 后续的 `c.send(n)` 相当于给消费者的暂停点“投递”一个值，消费者处理完后通过 `yield r` 又暂停，把处理结果返还给生产者。

## 为什么协程比多线程更高效？

原文总结了协程相较于多线程的两个关键优势：

1. **没有线程切换的开销**：线程切换是由操作系统强制调度的，需要保存寄存器、切换上下文，非常耗时；而协程的切换完全由代码自身控制，极轻量。
2. **不需要加锁**：协程全都在**一个线程**里跑，同一时刻永远只有一个协程在执行。既然不会发生并发冲突，自然不需要互斥锁（`Lock`）。

## 结合 FastAPI 实战：现在协程长什么样？

在早期的 `yield/send` 方案中，写异步代码比较繁琐。所以 Python 3.5 引入了原生语法 `async/await`，**它的底层依然是生成器那一套，只是换了一套更简洁的外衣**。

到了 FastAPI 里，你写的所有 `async def` 函数就是协程。每个请求进来，FastAPI 会把你的任务包装成一个协程挂到事件循环中：
* 状态切换：协程被编译为生成器对象，根据执行情况在 **Pending（等待）→ Running（运行中）→ Suspended（因 `await` 挂起）→ Completed（完成）** 之间流转。
* 当你的接口代码遇到 `await` 时，当前协程会让出执行权；事件循环会保存它的上下文，切去执行其他就绪的任务。等 I/O 操作完成，事件循环再把它唤醒，继续执行未完成的逻辑。
