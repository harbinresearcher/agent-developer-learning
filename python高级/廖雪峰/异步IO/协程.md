# 协程

> **重要程度：高**｜**手练：需要**
> 重点：区分协程对象和 Task，练习 `await`、并发调度、取消和共享状态保护。

## 执行过程

调用普通的 `async def` 协程函数会得到协程对象，函数体不会因此立即执行。用 `await` 等待，或交给 `asyncio.create_task()`、`TaskGroup` 等调度，才会推进执行。`await` 可能让出控制权，但等待的对象如果已经就绪，也不保证每次都会切换任务。

一个事件循环通常在一个线程中交替推进多个任务；一个程序可以使用多个事件循环、线程或进程。协程并不自动让 CPU 密集运算变快。耗时同步代码会阻塞当前事件循环。

## 为什么仍需要同步

任务在 `await` 处可能交错：一个任务读取共享状态后等待，另一个任务可能修改该状态，第一个任务恢复后再写入就可能覆盖更新。跨等待点需要保持不变量时，可以用 `asyncio.Lock`；它用于协程间同步，不能代替线程锁或跨进程锁。

## 取消与清理

任务取消会在合适的等待点引发 `asyncio.CancelledError`。用 `try/finally` 释放资源；如果显式捕获取消异常，清理后通常应继续抛出，避免破坏超时和 `TaskGroup` 的取消机制。

生成器的 `yield` / `send()` 是理解历史设计的辅助材料；日常异步 IO 优先掌握 `async def` / `await`。可运行例子见 [[asyncio]]。
