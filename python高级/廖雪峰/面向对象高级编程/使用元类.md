# 元类（metaclass）· 笔记

## 先搞清一件事：类也是对象

平时说“类创建实例”，这没问题。但类本身是谁创建的？答案是 `type`。

```python
class Hello:
    def hello(self):
        pass

h = Hello()

type(h)        # <class '__main__.Hello'>，h 是 Hello 的实例
type(Hello)    # <class 'type'>，Hello 是 type 的实例
```

**`Hello` 这个类，本身是 `type` 创建出来的一个对象**。记住这个，下面全通。因为类也是对象，所以“谁来创建类”这个问题才有意义，元类就是干这个的。

---

## `type()` 的第二副面孔：动态创建类

`type()` 有两个用法。平时你用它查类型：`type(123)` 得 `int`。但它还能**创建类**，接受三个参数：

```python
def fn(self, name='world'):            # 先定义函数，待会儿当作方法
    print(f'Hello, {name}.')

Hello = type('Hello', (object,), dict(hello=fn))   # 用 type 创建 Hello 类
```

三个参数依次是：

1. **类名**：`'Hello'`，字符串；
2. **父类元组**：`(object,)`，**只有一个父类时这个逗号不能省**，否则 `(object)` 只是个括号里的 `object`，不是元组；
3. **方法字典**：`dict(hello=fn)`，把函数 `fn` 绑到方法名 `hello` 上。

创建出来的 `Hello` 和你手写 `class Hello` 一模一样，能实例化、能调方法。为什么一样？因为**你写 `class` 的时候，解释器也只是扫描语法，然后调 `type()` 去造类**。`class` 关键字是语法糖，`type()` 才是底层动作。

---

## 元类：创建类的“模板”

原文那句话说得最清楚：**“先定义 `metaclass`，就可以创建类，最后创建实例”**。你可以把类看成是元类创建出来的“实例”。

默认情况下，所有类的元类都是 `type`。你想插手“类是怎么被造出来的”，就自定义一个元类，**它必须继承 `type`**。

```python
class ListMetaclass(type):                     # 元类必须从 type 派生
    def __new__(cls, name, bases, attrs):      # 创建类时自动调用
        attrs['add'] = lambda self, value: self.append(value)   # 塞一个新方法进去
        return type.__new__(cls, name, bases, attrs)            # 调父类真正把类造出来
```

`__new__` 的四个参数，是你理解元类的钥匙：

- `cls`：**当前要创建的那个类**（注意不是实例，相当于类层面的 `self`）；
- `name`：类名，字符串；
- `bases`：父类元组；
- `attrs`：**类的属性字典**，方法、类属性都在里面，你在这动手脚就是改类的定义。

用法就是 `class` 定义时传 `metaclass=`：

```python
class MyList(list, metaclass=ListMetaclass):   # 指示用 ListMetaclass 来造这个类
    pass

m = MyList()
m.append(1)        # list 自带的方法
m.add(2)           # ListMetaclass 动态塞进去的
print(m)           # [1, 2]
```

`MyList` 自己一行方法都没写，但 `add` 有了，因为元类在**造类的时候**替它塞进去了。这就是元类的本质：**不是改实例，是改类本身**。

---

## 坑：`__new__` 必须返回类对象

`__new__` 里最后那句 `return type.__new__(...)` **不能省，也不能随便返回别的**。`__new__` 的职责就是“造出并返回这个类对象”，你不返回，`MyList` 就是 `None`，后面全崩。你可以在返回之前对 `attrs` 随意增删改，但**最终必须把父类 `__new__` 造好的类交回去**。

## 重头戏：用元类写 ORM

原文后半截的 ORM 例子，是元类唯一有说服力的使用场景。先搞清 ORM 要干什么：**把数据库表映射成类，一行记录映射成实例**。`User` 类对应 `user` 表，`id`、`name` 这些类属性对应字段。

目标长这样：

```python
class User(Model):
    id = IntegerField('id')
    name = StringField('name')

u = User(id=123, name='Michael')
u.save()        # 生成并执行 INSERT INTO user (id, name) VALUES (123, 'Michael')
```

写 `save()` 的难点在于：**父类 `Model` 的方法里，拿不到子类 `User` 定义了哪些字段**。`Model` 是先定义的，那时候 `User` 还不存在，它没法知道子类后来加了什么。这就是必须用元类的原因——**元类在“造 `User` 这个类”的那一刻，能拿到 `attrs`，把所有 `Field` 收集起来**。

### 第一步：字段类，只存名字

```python
class Field:
    def __init__(self, name):
        self.name = name        # 字段名
        self._value = None      # 字段值，先占位
```

### 第二步：元类，把字段收集到 `_mappings`

```python
class ModelMetaclass(type):
    def __new__(cls, name, bases, attrs):
        if name == 'Model':                  # Model 本身不收集，跳过
            return type.__new__(cls, name, bases, attrs)
        mappings = {}                        # 收集本类里的所有字段
        for k, v in attrs.items():
            if isinstance(v, Field):         # 只挑 Field 类型的属性
                mappings[k] = v
        for k in mappings.keys():
            attrs.pop(k)                     # 从类属性里删掉，避免和实例属性冲突
        attrs['__mappings__'] = mappings     # 存进类属性，实例能通过 self 访问到
        attrs['__table__'] = name.lower()    # 类名小写当表名
        return type.__new__(cls, name, bases, attrs)
```

**两个动作要盯住**：字段**从 `attrs` 里 pop 掉**，然后存进 `__mappings__`。pop 的原因是，如果留在类属性里，`self.name` 可能拿到 `Field` 对象而不是字段值，会跟实例属性打架。

### 第三步：`Model` 基类，负责 `save()`

```python
class Model(metaclass=ModelMetaclass):       # Model 自己也用这个元类，但元类里跳过了它
    def __init__(self, **kw):
        for k, v in kw.items():
            setattr(self, k, v)              # 把传进来的字段值设成实例属性

    def save(self):
        fields = []
        params = []
        args = []
        for k, v in self.__mappings__.items():   # 遍历元类收集好的字段
            fields.append(v.name)                # 字段名
            params.append('?')                   # 占位符
            args.append(getattr(self, k, None))  # 从实例上取对应的值
        sql = f'insert into {self.__table__} ({",".join(fields)}) values ({",".join(params)})'
        print(sql)                               # 这里只打印，真实框架会交给驱动执行
        print(args)
```

### 第四步：业务类，只声明字段

```python
class User(Model):
    id = IntegerField('id')
    name = StringField('name')

u = User(id=123, name='Michael')
u.save()
# insert into user (id,name) values (?,?)
# [123, 'Michael']
```

---

## 整条链子串起来

1. 定义 `User` 时，`metaclass=ModelMetaclass` 生效，**元类先跑**；
2. 元类从 `attrs` 里挑出 `IntegerField`、`StringField`，存进 `__mappings__`，并把类名小写设成 `__table__`；
3. `User` 类造好了，`User` 的实例调用 `save()` 时，走的是**父类 `Model` 的 `save`**；
4. `save` 里通过 `self.__mappings__` 拿到字段，拼 SQL、取实例上的值，一条 `INSERT` 就出来了。

**元类在这里的唯一价值**：在“类诞生的那一刻”截胡，把子类声明的字段收集起来。父类方法做不到这件事，这就是必须上元类的原因。

---

## 几个容易踩的点

- **`metaclass` 会隐式继承**：`User` 没写 `metaclass=`，但它继承 `Model`，而 `Model` 指定了 `ModelMetaclass`，所以 `User` 自动走这个元类。这就是为什么 `User` 只写字段、不写元类也能被收集。
- **字段要从 `attrs` 里 pop**：不 pop 的话，`self.id` 会优先拿到类属性上的 `Field` 对象，而不是实例值，`getattr(self, k)` 拿到的就全错了。
- **`__new__` 必须返回类对象**：不管是 `type.__new__` 还是 `super().__new__`，不返回，类就没了。
- **原文自己都说了，日常几乎用不到**：元类主要用于写框架（Django ORM、SQLAlchemy），业务代码里基本不碰。学它是为了“看得懂”，不是“用得上”。
