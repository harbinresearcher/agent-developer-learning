线程是最小的执行单元，而进程由至少一个线程组成。如何调度进程和线程，完全由操作系统决定，程序自己不能决定什么时候执行，执行多长时间。

多进程和多线程的程序涉及到同步、数据共享的问题，编写起来更复杂。

## 先搞清楚：进程是什么，为什么需要它

你的程序默认只在**一个进程**里跑，CPU 同一时刻只能干一件事。想让程序“同时”干几件事——比如一边下载一边处理数据——就需要开出多个进程，让操作系统把 CPU 时间切着分给它们。操作系统轮流让各个任务交替执行，每个跑 0.01 秒切下一个，因为切换太快，你感觉像是同时在跑。

Python 这边，**Unix/Linux 上可以用 `os.fork()`，但 Windows 没有这个调用**。所以跨平台写多进程，统一用 `multiprocessing` 模块，它是 `fork` 的跨平台封装。这页的主线就是 `multiprocessing` 的三件套：**Process 开单个进程，Pool 开一批进程，Queue 让进程之间说话**。

---

## `fork()`：背景知识，知道就行，别用它写代码

`fork()` 是 Unix/Linux 的系统调用，**调用一次，返回两次**：父进程拿到子进程的 ID，子进程拿到 `0`。父进程靠这个 ID 记住自己开了哪个子进程，子进程靠 `getppid()` 找爸爸。

```python
import os

pid = os.fork()          # 调用一次，父子进程各返回一次
if pid == 0:             # 子进程：pid 为 0
    print('我是子进程')
else:                    # 父进程：pid 是子进程的 ID
    print('我是父进程')
```

这段代码**在 Windows 上直接跑不了**，因为 Windows 没有 `fork`。所以日常写 Python 多进程，**跳过 `fork`，直接用 `multiprocessing`**，它是跨平台的，Windows 和 Linux 都能跑。

---

## `Process`：开一个子进程，就三步

`multiprocessing.Process` 代表一个进程对象。创建子进程的标准流程是：**写一个函数 → 创建 `Process(target=函数, args=参数)` → `start()` 启动**。

```python
from multiprocessing import Process   # 导入 Process 类
import os

def run_proc(name):                   # 子进程要执行的函数
    print(f'子进程 {name} ({os.getpid()}) 在跑')   # getpid() 拿当前进程 ID

if __name__ == '__main__':            # Windows 下必须放在这个判断里，下面单独说
    print(f'父进程 {os.getpid()}')
    p = Process(target=run_proc, args=('test',))   # 创建 Process 实例，target 是函数，args 是参数元组
    p.start()                          # 启动子进程，它开始跑 run_proc
    p.join()                           # 父进程在这里等，直到子进程跑完才继续
    print('子进程结束')
```

**两个关键方法**：`start()` 是“点火”，调用后子进程才开始跑；`join()` 是“等待”，父进程会**阻塞在 `join()` 这一行，直到子进程结束**才往下走。如果你不写 `join()`，父进程不会等子进程，可能父进程都退出了子进程还在后台跑。

**`if __name__ == '__main__':` 不是可选的**。Windows 创建子进程的方式和 Unix 不同，它需要“模拟” `fork` 的效果，子进程会重新导入主模块。如果创建进程的代码不放在这个判断里，子进程一导入模块就又执行一遍 `Process(...)`，无限递归。

## `Pool`：一次开一批，比手动循环 `Process` 省事

如果你要开 10 个子进程，手动 `for` 循环创建 `Process` 当然可以，但 `Pool` 更省事：**你给池子一个大小，把任务扔进去，它自己调度**。

```python
from multiprocessing import Pool      # 导入进程池
import os, time, random

def long_time_task(name):             # 每个子进程要干的活
    print(f'任务 {name} ({os.getpid()}) 开始')
    start = time.time()
    time.sleep(random.random() * 3)   # 随机睡 0~3 秒，模拟耗时
    end = time.time()
    print(f'任务 {name} 耗时 {end - start:.2f} 秒')

if __name__ == '__main__':
    print(f'父进程 {os.getpid()}')
    p = Pool(4)                       # 创建一个最多同时跑 4 个进程的池子
    for i in range(5):
        p.apply_async(long_time_task, args=(i,))   # 把任务丢进池子，异步执行
    print('等待所有子进程...')
    p.close()                         # 关闭池子：不再接受新任务
    p.join()                          # 等待池子里所有任务跑完
    print('全部完成')
```

**执行逻辑**：池子大小是 4，所以**前 4 个任务立刻并行跑，第 5 个任务要等前面某个跑完、空出一个位置才能开始**。这就是 `Pool` 的意义：**用有限的进程数，排队处理更多的任务**，避免一次性开太多进程把系统拖垮。

**`close()` 和 `join()` 的顺序不能反**：`close()` 是“停止往池子里加新任务”，`join()` 是“等池子里现有的任务全跑完”。**不先 `close()` 就 `join()`，`join()` 会一直等下去**，因为它不知道你还要不要加新任务。

`Pool()` 不写参数时，默认大小是 **CPU 的核数**。你 4 核机器，`Pool()` 就是 4；想同时跑更多，显式写 `Pool(5)`。

## 进程间通信：`Queue`

进程之间的内存是**隔离的**，一个进程改了变量，另一个进程看不见。要传数据，得走操作系统提供的通信机制。`multiprocessing` 包装了这些机制，最常用的是 `Queue`。

```python
from multiprocessing import Process, Queue
import os, time, random

def write(q):                         # 写进程
    for value in ['A', 'B', 'C']:
        print(f'写入 {value}')
        q.put(value)                  # 把数据放进队列
        time.sleep(random.random())

def read(q):                          # 读进程
    while True:
        value = q.get(True)           # 从队列取数据，True 表示“队列空了就等着”
        print(f'读出 {value}')

if __name__ == '__main__':
    q = Queue()                       # 父进程创建队列
    pw = Process(target=write, args=(q,))   # 把队列传给写进程
    pr = Process(target=read, args=(q,))    # 把队列传给读进程
    pw.start()                        # 启动写进程
    pr.start()                        # 启动读进程
    pw.join()                         # 等写进程写完
    pr.terminate()                    # 读进程是死循环，等不到它自己结束，强行终止
```

**关键点**：`Queue` 是在**父进程里创建**的，然后作为参数传给子进程。`put()` 写，`get()` 读，`get(True)` 里的 `True` 表示“如果队列空着，我就阻塞等着，直到有数据”。

## Windows 的一个坑：pickle

Unix/Linux 下 `multiprocessing` 底层直接用 `fork`，很轻。**Windows 没有 `fork`，`multiprocessing` 需要把父进程的所有 Python 对象用 `pickle` 序列化后传给子进程**。所以如果你在 Windows 下用 `multiprocessing` 报错，**第一反应应该是：你传的东西是不是不能被 pickle 序列化**（比如 lambda、某些打开的文件句柄）。

---

## 这页记住三件事就够

1. **开单个进程用 `Process(target=函数, args=参数)`，`start()` 启动，`join()` 等待**，创建代码放在 `if __name__ == '__main__':` 里。
2. **开一批进程用 `Pool`，`apply_async` 丢任务，`close()` 停止接收，`join()` 等全部跑完**；池子大小默认是 CPU 核数。
3. **进程之间传数据用 `Queue`，父进程创建，子进程 `put`/`get`**；Windows 下注意 pickle 序列化问题。
