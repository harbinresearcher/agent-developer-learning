# 进程、线程与异步 IO

> **重要程度：高**｜**手练：需要**
> 重点：为 CPU 密集和 IO 密集任务选择方案，练习线程池、进程池和异步任务的异常处理。

## 怎么选

- **进程**：地址空间通常隔离，适合普通 CPython 下的纯 Python CPU 密集任务。进程创建、数据传输和序列化有开销。
- **线程**：同一进程内共享内存，适合阻塞 IO；共享可变状态需要同步。普通 CPython 的 GIL 限制同一解释器内 Python 字节码的并行执行；某些原生扩展会释放 GIL。
- **异步 IO**：事件循环在任务等待异步 IO 时调度其他任务，适合大量并发 IO。阻塞操作放进事件循环会拖慢该循环，必要时交给线程或进程。

实际选择要测量耗时、吞吐、内存、依赖是否支持异步，以及外部服务的并发上限。线程数量或进程数量并非越多越好；CPU 核数可作为进程池初始参考，最终以测量为准。

## GIL 的范围

GIL 是 CPython 的实现细节，不等于所有 Python 实现都有相同限制。Python 3.13 起提供可选的自由线程构建，能关闭 GIL；普通构建仍默认启用。自由线程构建的扩展兼容性和实际性能需单独检查。

## 故障与共享状态

进程隔离通常能缩小单个工作进程崩溃的影响，但共享数据库、文件或外部服务仍可能受影响。普通 Python 线程出现未捕获异常通常只结束该线程；进程级崩溃或共享状态损坏则可能影响其他线程。
