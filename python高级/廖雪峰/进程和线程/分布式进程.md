这一页其实是前面多进程知识的升级版——把进程从**一台机器**扩展到**多台机器**。核心就一句话：**用 `multiprocessing.managers` 把 `Queue` 通过网络暴露出去，让另一台机器上的进程也能往里面读写数据**。

---

# 分布式进程 · 笔记

## 先聊动机：为什么要把进程分布出去

前面学多进程，所有进程都跑在同一台机器上。但原文开篇就点了一个关键事实：**在 Thread 和 Process 之间，应当优先选 Process**，因为 Process 更稳定（子进程崩了不影响别人），而且 **Process 可以分布到多台机器上，Thread 最多只能分布到同一台机器的多个 CPU 上**。

所以当一台机器忙不过来时，自然的需求就是：**让一台机器负责任务调度，另一台机器负责执行任务**，两边通过网络通信。Python 的 `multiprocessing.managers` 子模块就是干这个的——它**封装了网络通信的细节，你不需要懂 socket 编程，就能写出跨机器的多进程程序**。

---

## 核心机制：把 `Queue` 注册到网络上

原来在同一台机器上，进程之间靠 `Queue` 通信，这个 `Queue` 是本地对象，别的机器访问不到。**分布式进程的关键操作是：把这个 `Queue` 通过 `BaseManager` 注册到网络上，暴露成一个网络服务**，别的机器连上来之后，就能像操作本地 `Queue` 一样操作它。

所以整个架构就两个角色：

- **服务进程（Master）**：创建 `Queue`，把它注册到网络，往里写任务，从结果 `Queue` 里读结果；
- **任务进程（Worker）**：通过网络连接到 Master，从任务 `Queue` 里取任务，把结果写回结果 `Queue`。

**中间的通信全部由 `BaseManager` 帮你封装好了，你只管调 `put()` 和 `get()`。**

---

## 服务进程（`task_master.py`）逐段拆

先看 Master 的完整代码，我按功能块拆开讲。

```python
import random, time, queue                        # 导入所需模块
from multiprocessing.managers import BaseManager  # 导入 BaseManager，分布式进程的核心

task_queue = queue.Queue()                        # 发送任务的队列
result_queue = queue.Queue()                      # 接收结果的队列

class QueueManager(BaseManager):                  # 继承 BaseManager，定义一个空的子类
    pass                                          # 不需要加任何东西，基类已经够用

QueueManager.register('get_task_queue', callable=lambda: task_queue)     # 把任务队列注册到网络
QueueManager.register('get_result_queue', callable=lambda: result_queue) # 把结果队列注册到网络
```

**这几行的意思**：`register` 是在告诉 `QueueManager`，“**如果有人通过网络来要一个叫 `get_task_queue` 的东西，你就把 `task_queue` 这个本地 `Queue` 交给他**”。`callable` 参数是一个函数，返回你要共享的 `Queue` 对象。

```python
manager = QueueManager(address=('', 5000), authkey=b'abc')   # 绑定本机所有IP的5000端口，验证码是abc
manager.start()                                             # 启动网络服务，开始监听

task = manager.get_task_queue()                             # 拿到任务队列的网络接口
result = manager.get_result_queue()                         # 拿到结果队列的网络接口
```

**`address=('', 5000)`** 表示监听本机所有网络接口的 5000 端口。**`authkey` 是连接密码**，Worker 那边必须用一模一样的 `authkey` 才能连上来。

```python
for i in range(10):                                         # 放10个任务进去
    n = random.randint(0, 10000)
    task.put(n)                                             # 往任务队列写
    print(f'Put task {n}...')

for i in range(10):                                         # 等10个结果
    r = result.get(timeout=10)                              # 从结果队列读，最多等10秒
    print(f'Result: {r}')

manager.shutdown()                                          # 关掉服务
```

**这里有一个必须钉死的点**：在分布式环境下，**你不能直接对原始的 `task_queue` 调 `put()`**，那样就绕过了 `QueueManager` 的网络封装，数据根本传不到另一台机器。**必须用 `manager.get_task_queue()` 返回的那个网络接口来操作**。

## 任务进程（`task_worker.py`）逐段拆

Worker 的代码结构对称，但**注册时只提供名字，不提供  `callable`**，因为它不创建 `Queue`，只是从网络上取现成的。

```python
class QueueManager(BaseManager):                  # 同样继承 BaseManager
    pass

QueueManager.register('get_task_queue')           # 只注册名字，不要 callable
QueueManager.register('get_result_queue')         # 因为 Worker 不创建 Queue，只是从网上拿

m = QueueManager(address=('127.0.0.1', 5000), authkey=b'abc')   # 指向 Master 的 IP 和端口
m.connect()                                       # 发起网络连接
```

**`address` 里填的是 Master 的 IP**，如果是同一台机器测试，就写 `'127.0.0.1'`。**`authkey` 必须和 Master 完全一致**，否则连不上。

```python
task = m.get_task_queue()                         # 从网络拿到任务队列
result = m.get_result_queue()                     # 从网络拿到结果队列

for i in range(10):
    try:
        n = task.get(timeout=1)                   # 取一个任务，最多等1秒
        r = f'{n} * {n} = {n*n}'                  # 执行任务
        result.put(r)                             # 把结果写回结果队列
        time.sleep(1)                             # 模拟耗时
    except queue.Empty:                           # 队列空了，任务取完了
        print('task queue is empty.')
```

Worker 这边**完全不需要知道 `Queue` 是怎么创建的**，它只知道自己连上了一个网络服务，从上面 `get` 一个 `Queue` 接口来用就行。

## 启动顺序和坑

**先启动 Master，再启动 Worker**。Master 先跑起来，`Queue` 注册好、网络服务启动好，Worker 才能连上去。反过来 Worker 会连不上。

几个容易踩的地方：

**1. 直接操作 `task_queue` 而不是网络接口**。这是这页最核心的坑。在分布式环境下，**必须用 `manager.get_task_queue()` 拿到的接口来 `put`/`get`**，操作原始的本地 `Queue` 对象是无效的，数据不会经过网络。

**2. `authkey` 不一致**。Master 设了 `b'abc'`，Worker 也必须写 `b'abc'`，差一个字节都连不上。

**3. `address` 的 IP 写错**。Worker 的 `address` 要指向 **Master 所在机器的 IP**，写 `127.0.0.1` 只能在本机测试，跨机器要写实际 IP。

**4. 忘了 `manager.shutdown()`**。Master 跑完不关，端口会一直被占用，下次再启动可能报端口冲突。

---

## 这页记住三件事

1. **`BaseManager` 把本地 `Queue` 注册到网络上**，别的机器就能像用本地 `Queue` 一样用它，网络细节全被封装了。
2. **Master 负责创建 `Queue`、注册、写任务、读结果；Worker 负责连上来、取任务、写结果**，两边靠 `authkey` 和 `address` 对齐。
3. **在分布式环境下，必须通过 `manager.get_task_queue()` 返回的网络接口来操作 `Queue`**，不能直接碰原始的本地 `Queue` 对象。
