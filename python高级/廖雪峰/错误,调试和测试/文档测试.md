# doctest 文档测试 · 笔记

## 先聊痛点：示例代码和真实行为会脱节

你写一个函数，习惯在 docstring 里留几个例子：

```python
def abs(n):
    """
    Example:
    >>> abs(1)
    1
    >>> abs(-1)
    1
    """
    return n if n >= 0 else (-n)
```

问题在于：**这些例子只是“注释”，代码改了、例子忘了更新，文档就成了谎言**。doctest 要做的就是——**把 docstring 里 `>>>` 后面的代码和下一行的预期输出，提取出来自动跑一遍**，跑不过就报错。运行 doctest 能检查被发现的示例，但没有运行或没有覆盖的示例仍可能过时。

---

## 最小例子：给 `Dict` 类加 doctest

接着上一页 `Dict` 类的例子，把测试用例直接写进类的 docstring：

```python
class Dict(dict):
    '''
    Simple dict but also support access as x.y style.

    >>> d1 = Dict()
    >>> d1['x'] = 100
    >>> d1.x
    100
    >>> d1.y = 200
    >>> d1['y']
    200
    >>> d2 = Dict(a=1, b=2, c='3')
    >>> d2.c
    '3'
    '''
    def __init__(self, **kw):
        super().__init__(**kw)

    def __getattr__(self, key):
        try:
            return self[key]
        except KeyError:
            raise AttributeError(r"'Dict' object has no attribute '%s'" % key)

    def __setattr__(self, key, value):
        self[key] = value
```

然后文件末尾加两行，让 doctest 跑起来：

```python
if __name__ == '__main__':
    import doctest
    doctest.testmod()      # 自动提取并执行所有 docstring 里的 >>> 示例
```

运行时无输出可能表示没有发现失败，也可能没有发现测试；用详细模式检查发现和运行的示例数量。

---

## 关键行为：doctest 怎么判断“对不对”

**它严格按照交互式命令行的输入和输出来判断**。`>>>` 后面是输入代码，紧接着的下一行（或几行）是**预期输出**，一字不差才算通过。

所以上面 `d2.c` 的预期输出写的是 `'3'`（带引号的字符串），不是 `3`。如果你写成 `3`，doctest 就会报失败——因为交互环境里字符串会带引号显示。

---

## 异常怎么测：用 `...` 省略烦人的中间输出

测异常时，完整的 traceback 又长又丑，doctest 允许用 `...` 表示“中间这一大段我不管”，只盯住**最后那行错误信息**：

```pycon
>>> d2['empty']
Traceback (most recent call last):
    ...
KeyError: 'empty'

>>> d2.empty
Traceback (most recent call last):
    ...
AttributeError: 'Dict' object has no attribute 'empty'
```

`...` 就是“这里省略了若干行”，doctest 会自动跳过中间内容，只检查 `KeyError` 或 `AttributeError` 那一行对不对。

---

## 失败长什么样

如果你把 `__getattr__` 方法注释掉，再跑 `python mydict2.py`，doctest 会精确告诉你哪一行失败了：

```
Failed example:
    d1.x
Exception raised:
    ...
    AttributeError: 'Dict' object has no attribute 'x'

1 items had failures:
   2 of 9 in __main__.Dict
***Test Failed*** 2 failures.
```

它把**哪个示例、期望什么、实际抛了什么**全列出来，定位问题非常直接。

---

## 一个很重要的安全机制

注意 `if __name__ == '__main__':` 这个条件。**doctest 只在“命令行直接运行这个文件”时才执行**；如果这个模块是被 `import` 进来的，doctest 不会跑。

所以你在生产代码里留 doctest 是**安全的**，不会因为别人 import 你的模块就莫名其妙跑一遍测试。

---

## 坑：`__name__` 为 `__main__` 时才能触发

这是唯一一个容易翻车的地方。你把 `doctest.testmod()` 写在 `if __name__ == '__main__':` 里面，用 `python mydict2.py` 能跑；但如果用 `python -m unittest` 或导入模块的方式，它就不跑了。**想让 doctest 跟着单元测试一起跑，需要额外配置**，或者手动 `doctest.testmod()`。日常用“直接跑文件”的方式最简单。

## 练习：给 `fact(n)` 写 doctest

原文最后留了一个练习，把 `?` 填上正确的预期输出：

```python
def fact(n):
    '''
    Calculate 1*2*...*n

    >>> fact(1)
    1
    >>> fact(10)
    3628800
    >>> fact(-1)
    Traceback (most recent call last):
        ...
    ValueError
    '''
    if n < 1:
        raise ValueError()
    if n == 1:
        return 1
    return n * fact(n - 1)

if __name__ == '__main__':
    import doctest
    doctest.testmod()
```

三个 `?` 分别是：`fact(10)` 的返回值 `3628800`，以及 `fact(-1)` 的异常 `ValueError`。运行测试时确认发现的示例数量，并检查退出状态。
