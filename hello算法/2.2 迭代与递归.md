**笔记：迭代与递归**

```
┌──────────┬──────────────────────┬──────────────────────────┐
│ 维度     │ 迭代                 │ 递归                     │
├──────────┼──────────────────────┼──────────────────────────┤
│ 实现     │ for / while 循环     │ 函数调用自身             │
│ 时间     │ 通常更快             │ 有函数调用开销           │
│ 内存     │ 通常固定             │ 调用层数越深，栈越大     │
│ 适合     │ 重复、线性流程       │ 树、图、分治、回溯       │
└──────────┴──────────────────────┴──────────────────────────┘
```

```
[重复任务] ──┬── 迭代 ── 循环条件不满足时结束
             └── 递归 ── 规模变小 ── 触发终止条件 ── 逐层返回
```

1. 迭代

迭代就是按条件重复执行代码。

- `for`：提前知道遍历范围或次数时用。例如遍历数组、循环 `n` 次。
- `while`：停止条件或每轮更新更灵活时用。例如变量可能每轮做多次变化。
- 嵌套循环：外层跑 `n` 次，内层每次也跑 `n` 次，总操作次数约为 `n²`。

判断：题目是“从头到尾重复做一件事”，优先想循环。

2. 递归的三个必备部分

```
终止条件：何时不再调用自己
递归调用：下一层问题必须更小或更简单
返回结果：当前层如何利用下一层答案
```

少一个都会出问题：

- 没终止条件：无限调用，最终栈溢出。
- 参数没变小：看似有终止条件，实际上永远到不了。
- 返回关系写错：能结束，但答案错误。

求 `1 + 2 + ... + n` 的递归关系：

```
f(n) = n + f(n - 1)
f(1) = 1
```

执行时间线：

```
递：f(4) → f(3) → f(2) → f(1)
归：1 → 2+1 → 3+3 → 4+6
```

3. 调用栈：递归为什么占内存

每进入一层递归，系统都会创建一个栈帧，保存参数、局部变量和返回位置；函数返回后才释放。

```
调用 f(4)

栈顶  f(1)
      f(2)
      f(3)
栈底  f(4)
```

递归深度为 `n`，就会同时存在约 `n` 个栈帧。层数过深会栈溢出。

4. 尾递归不是 Python 的解法

尾递归指“递归调用是函数最后一步”。有些语言可优化它，减少栈空间。

但 Python 默认不做尾递归优化。即使写成尾递归，递归太深仍会报错。因此 Python 遇到深度大或不确定的递归时，通常改用循环或显式栈。

5. 递归树的警告

斐波那契递归会一分为二：

```
fib(n)
├── fib(n - 1)
└── fib(n - 2)
```

多个分支会产生递归树，同一个子问题可能被重复计算。代码短不等于效率高。

6. 选型规则

```
简单重复、层数很深、Python 运行
→ 用迭代

问题可拆成同类型子问题，结构像树或分治
→ 递归更自然

递归层数可能过深，但逻辑仍是树形
→ 用显式栈模拟递归
```

递归和迭代常可互转，但不要为了“消灭递归”强行改写。改成显式栈后可能更难读。选能保证正确、深度安全、逻辑清楚的方案。
