**笔记：空间复杂度**

空间复杂度看的是：输入 `n` 变大时，程序运行期间需要的**峰值内存**怎么增长。

这页采用的统计口径：

```
统计：暂存变量、额外对象、调用栈、输出数据
不统计：输入数据本身
```

最容易错的是：**循环执行很多次，不代表空间一定是 `O(n)`。**

```
循环 n 次：
每轮只用一个变量，下一轮覆盖或释放上一轮
→ 同时只占一份空间 → O(1)

递归 n 层：
前一层没返回，下一层又创建栈帧
→ 同时堆积 n 层 → O(n)
```

看代码时，只问一句：

> 最大同时存在多少份额外数据？

常见判断：

```
几个变量、固定长度数组       → O(1)
新建长度为 n 的数组/哈希表   → O(n)
新建 n × n 矩阵             → O(n²)
递归每层只保留一个栈帧       → O(递归深度)
每层把规模减半               → O(log n)
建立满二叉树                 → O(2ⁿ)
```

空间复杂度通常只看最差情况，因为内存是硬限制。程序某一刻需要 `O(n)` 内存，即使后面释放了，空间复杂度仍记为 `O(n)`。

时间和空间常要取舍：

```
哈希表缓存结果：多占 O(n) 内存，但查找更快
不建缓存：省内存，但可能反复计算、更慢
```

这叫“以空间换时间”；反过来是“以时间换空间”。
