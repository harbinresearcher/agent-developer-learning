**第 2 章复习清单：复杂度分析**

先只记这 5 句。

```
1. 时间复杂度：数据变大后，代码运行次数怎么增长。
2. 空间复杂度：数据变大后，峰值额外内存怎么增长。
3. O(...)：通常表示最差情况下的增长上界。
4. 复杂度看增长趋势，不等于实际秒数或实际内存大小。
5. 算法常在时间和空间之间取舍。
```

看代码的固定顺序：

```
先找 n 是什么
→ 看循环或递归会执行多少次
→ 看是否创建与 n 相关的额外数据
→ 忽略常数和系数，保留最高阶
```

常见时间复杂度：

```
O(1)      固定次数操作
O(log n)  每轮减半
O(n)      单次遍历
O(n²)     两层 n 级嵌套
O(n log n) 分治排序
O(2ⁿ)     二叉递归、暴力枚举
O(n!)     全排列
```

空间复杂度重点：

```
固定变量、循环里的临时变量     → O(1)
长度为 n 的数组、哈希表         → O(n)
n × n 矩阵                      → O(n²)
递归深度为 n 的调用栈           → O(n)
```

循环调用函数 `n` 次，通常仍是 `O(1)` 空间，因为前一轮已经返回并释放空间；递归 `n` 层会同时保留 `n` 个栈帧，所以是 `O(n)` 空间。

尾递归理论上可优化到 `O(1)` 空间，但 Python、Java、C++、Go、C# 等通常不自动做这类优化。Python 里仍按 `O(n)` 栈空间看。

工程中的取舍：

```
哈希表、数据库索引：多用内存，换更快查询
顺序查找：少用内存，但查询更慢
```

复杂度最适合比较大数据量。数据很小时，常数开销可能让高复杂度方案反而更快。
