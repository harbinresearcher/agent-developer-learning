**笔记：时间复杂度**

时间复杂度不算“跑了几秒”，而是看输入规模 `n` 变大时，操作数量怎么增长。

```
T(n) = 2n² + 7n + 3
忽略常数、系数，只保留最高阶
→ O(n²)
```

**推算规则**

```
固定次数操作           → O(1)
单层循环跑 n 次        → O(n)
两层嵌套，各跑 n 次    → O(n²)
每轮规模减半           → O(log n)
n 次操作 × log n 层    → O(n log n)
递归每层分裂成 2 个    → O(2ⁿ)
枚举全部排列           → O(n!)
```

复杂度从优到劣：

```
O(1) < O(log n) < O(n) < O(n log n)
     < O(n²) < O(2ⁿ) < O(n!)
```

看代码时按这个顺序判断：

```
1. n 是什么？
2. 哪些操作次数依赖 n？
3. 顺序代码相加，嵌套循环相乘。
4. 删除常数和系数，只留最高阶。
```

几个容易错的点：

- 循环固定跑一百万次，仍是 `O(1)`；它可能慢，但不会随输入 `n` 增长。
- `O(log n)` 的信号是每轮把范围缩小一半，例如二分查找。
- `O(n log n)` 常见于归并排序、堆排序、快速排序。
- `O(2ⁿ)`、`O(n!)` 常见于暴力枚举、回溯；数据稍大就可能不可用。
- 时间复杂度通常默认看最差情况。例如线性查找最差是 `O(n)`，即使目标刚好在第一个位置时只需 `O(1)`。

实际写题时，除非题目明确问平均或最佳情况，否则报告最差时间复杂度。
