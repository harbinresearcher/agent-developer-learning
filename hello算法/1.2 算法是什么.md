**笔记：算法与数据结构**

```
┌────────────┬───────────────────────────────┬──────────────────────┐
│ 概念       │ 本质                          │ 判断重点             │
├────────────┼───────────────────────────────┼──────────────────────┤
│ 算法       │ 有限步骤内解决问题的规则       │ 输入、输出、步骤     │
│ 数据结构   │ 组织、存储、操作数据的方式     │ 访问、增删、内存     │
│ 算法题     │ 数据结构 + 算法的组合选择      │ 用什么装，如何处理   │
└────────────┴───────────────────────────────┴──────────────────────┘
```

```
[解决一个问题] ──┬── 输入数据
                 ├── 数据结构 ── 怎么存、怎么访问、怎么修改
                 ├── 算法     ── 按什么步骤处理
                 └── 输出结果
```

1. 算法的严格定义

算法是在**有限时间内**解决某个特定问题的一组指令。

它必须满足三点：

- 输入和输出明确：例如“给数组，返回最大值”，不能只说“处理一下数组”。
- 有限可行：步骤、时间、内存不能无限增长。
- 确定性：同样输入、同样运行条件，结果必须一致。

例如“猜一个数”不是完整算法；“每次比较中间值，缩小一半范围，直到找到目标或范围为空”才是算法。

2. 数据结构是什么

数据结构不只是“存数据的容器”。它规定了：

- 数据本身是什么；
- 数据之间如何关联；
- 能对数据做哪些操作，如访问、插入、删除、更新。

设计数据结构时，通常追求三件事：

```
┌──────────┬──────────────────────────┐
│ 目标     │ 含义                     │
├──────────┼──────────────────────────┤
│ 少占内存 │ 控制空间开销             │
│ 操作快   │ 访问、增删、更新更高效   │
│ 好表达   │ 数据关系清楚，便于写算法 │
└──────────┴──────────────────────────┘
```

三者不能总同时最优，必须取舍：

- 链表比数组更容易插入、删除，但随机访问慢。
- 图能表达更复杂的关系，但通常比链表占更多内存。

3. 数据结构和算法怎么配合

数据结构提供“材料和摆放方式”；算法规定“处理步骤”。

- 没有数据结构，算法难以高效拿到或修改数据。
- 没有算法，数据结构只是在存数据，不能解决问题。
- 同一算法换一种数据结构，效率可能完全不同。

例如“找一个元素”：

- 用无序数组：通常只能从头扫描。
- 用有序数组：可以二分查找。
- 用哈希表：可按键快速查找。

所以刷题时别只问“用什么算法”，还要先问：**数据怎样存，后续操作最频繁的是什么？**

4. 做题固定检查顺序

```
输入是什么？
↓
需要频繁做什么操作？查找、插入、删除、排序，还是关系遍历？
↓
选什么数据结构？
↓
在该结构上选什么算法？
↓
时间和内存是否可接受？
```

“算法题”这个叫法容易让人误以为只考步骤。实际同时考两件事：**选对数据结构，写对处理逻辑。**

数据结构和算法独立于编程语言。Python、Java、C++ 写法不同，底层思路一样。
